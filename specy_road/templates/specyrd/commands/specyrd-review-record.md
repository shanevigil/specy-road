Thin stub — validates review notes and files them as `work/reviews/<NODE_ID>/REVIEW-<model>.md`. Generated by specyrd {{SPECYRD_VERSION}}.

Read only `work/reviews/<NODE_ID>/PACKET.md` (from `/specyrd-review-packet`). Write your notes as Markdown starting with this front matter, one `acceptance` entry per `A#` in the packet's brief:

```yaml
---
node_id: <NODE_ID>
model: <your roster id, e.g. claude-opus-5.5, or human>
date: <YYYY-MM-DD>
verdict: approve            # or block
commit: <"Commit under review" from the packet>
acceptance: {A1: pass, A2: pass}      # pass | fail | n/a
findings: {correctness: [], regression: [], boundary: [], test_integrity: []}
commands_rerun: []
required_changes: []
fresh_session: true
authored_fix: false
is_coordinator: false
---
```

Then, from the **repository root**:

```bash
specy-road review record <NODE_ID> --model <id> --verdict approve --file <notes.md>
```

- `approve` may not list failing acceptance or `required_changes`; use `block`.
- The record counts only for the commit it names. Any later commit needs a new review.
- A model outside the roster in `roadmap/orchestration.yaml` does not count; pass `--family` to file it anyway.

Do **not** run `mark-implementation-reviewed` yourself; the coordinator does. See `docs/orchestration.md`.
