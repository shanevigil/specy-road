# Implementation summary: M16.1.2 — review-gate decision table

Tests and fixtures only. No package code changed. Everything is under `tests/parity/review_gate/` (the touch zone, confirmed: nothing outside it was needed, and no `__init__.py` is needed because `pythonpath = ["."]`).

## What was built

- `cases/gate_rows.yaml` holds the decision table: 44 rows plus the committed **branch list**. The list covers every field `GateResult.passed` and `GateResult.problems()` read at pickup:
  - `config_error`
  - `commit`
  - `blocks`
  - `stale`
  - `invalid`
  - `ineligible`
  - `approval_count`/`required`/`distinct_families`
  - `verifier_problems`
  - `strong_unmet`
  - `policy_pin` (the "Done but wrong" item)

  Each branch has a refusal row. Each branch that can still pass also has an approval row. `block` passes only through a human-applied deferral (`deferral-strong-met`). `config_error` and `no_commit` cannot pass.
- The table has rows for the defaults and for every interaction A1 names:
  - stale vs current commit
  - executor, coordinator (including the human exemption) and fresh-session exclusions
  - missing, invalid and valid signatures, and hand-filed records with `count_human_filed_reviews` off and on
  - `reviewer_reruns_required`
  - reviewer count (with and without distinct families)
  - reviewer disagreement
  - an approval carried over a planning-only commit (`bookkeeping_carry`)
  - delta review: counts, red-green on, `delta_review` off, `reviewer_resumed_delta` on and off
  - integrity gate (a finding, clean) and `ratchet_paths`
  - deferral with strong review (unmet and met)
- A4: each row runs through `resolve_target(repo, "M1.1", "HEAD")`, then `evaluate_gate(..., branch=<registry branch>)`. That is the call finish-this-task (`gate_holds_at_head_or_exit`), mark-implementation-reviewed, `handoff status` and `review list` make. Each row asserts `passed`, `approval_count` and `len(problems())`. A row asserts a problem sentence (`says`) only where a pickup test asserts it, and the YAML names that test. The `no-commit` row passes an unresolvable sha to `evaluate_gate`, because no public command reaches a `None` commit any other way.
- Records are written with `review_files.render_front_matter` (the package writer), not hand-written strings. Signatures use `review_signing.sign` with keys generated by `ssh-keygen`. Blocks that feed a deferral are filed with `specy-road review record`.
- `cases/filing_rows.yaml` (A2) feeds a reviewer's final message, as a Claude Code stream-json turn, through `review_answer.final_answer` and then `review_record_write.file_review`. Outcomes at pickup:
  - clean JSON → `recorded`, gate passes
  - narration before the JSON → `recorded`
  - narration before and after it → `rerun` (the message must end with the object)
  - notes that break a notes rule (an approve line with no "not a defect because") → `rerun`
- `records/` (A3) holds 15 files copied byte for byte from the main checkout's `sr/work/reviews`: one per front-matter key set found there (13 REVIEW formats and 2 READY formats). One of the READY files is the legacy M4.6 file with no front matter, which today's reader reports invalid. `records/MANIFEST.yaml` records each file's source path and what `load_ready`/`load_review` return (ok, keys or errors, verdict, notes digest match). Substitution: the M8.7 record of one format names a home directory, which `scripts/check_machine_paths.py` rejects in tracked files, so the M11.24 record with the same key set is used instead.
- `cases/policy_keys.yaml` (A5) classifies all 24 `policy` keys of `orchestration.schema.json`:
  - 12 gate inputs, each with its reader
  - 12 non-gate settings, each with its reader. `milestone_full_review` is non-gate: it decides whether finish runs a milestone's full review, and `evaluate_gate` does not read it for a leaf.

## Accepted limits

- Frozen records come only from this checkout's gitignored `sr/work/reviews` (as the sheet states).
- Red-green appears only as a refusal (`red-green: missing`). A passing red-green row would need `review red-green` to run pytest at the base and the head, and A1 does not ask for that.

## Added

- `tests/parity/review_gate/test_review_gate_decision_table.py`: the loader and runner for the tables below.
  - `orchestration()`: builds a row's `orchestration.yaml` from a named roster plus the row's policy.
  - `Leaf`: one row's repo, with these step methods:
    - `commit`, `dev`, `claim` (pickup's pinned registration commit)
    - `review` (render_front_matter, optional history copy and signature)
    - `record` (the `review record` CLI)
    - `ready`
    - `defer` (RCA, closed decision and marker)
    - `gate` (resolve_target then evaluate_gate)
  - `assert_outcome()`: asserts passed, approvals, problems and optional required/distinct_families/carry, plus `says` sentences.
  - `test_gate_row`: the decision table (A1, A4).
  - `test_the_branch_list_is_every_field_passed_and_problems_read`: fails when `passed`/`problems()` read a field the branch list does not name.
  - `test_every_branch_has_a_refusal_row_and_an_approval_row_where_it_can_pass`: holds A1's row rule.
  - `test_a_row_with_no_approval_is_refused_at_the_default_config`: the sheet's check against a trivially passing fixture config.

  - `test_filing_from_a_final_message`: A2.

- `tests/parity/review_gate/cases/filing_rows.yaml`: the 4 filing rows.
