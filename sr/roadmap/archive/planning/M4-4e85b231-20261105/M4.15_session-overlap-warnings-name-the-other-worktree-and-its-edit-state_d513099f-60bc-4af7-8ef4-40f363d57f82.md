## Intent

Session overlap warnings name the other worktree and its edit state. Done when:
- When session start or touch reports an overlap with a live session, the warning names that session's worktree path and branch
- The warning says whether the other worktree has uncommitted edits to the overlapping path, committed edits not yet merged into the integration branch, or neither
- An overlap with a session owned by the same user in another worktree is still reported, labelled as yours

## Approach

After each existing overlap warning from `session start` and `session touch`, print two indented lines for the other session: its owner (or `yours` for the same user) with its recorded worktree path and branch, then its edit state on the overlapping paths. The edit state comes from git in that worktree: uncommitted paths (staged, unstaged and untracked, collected separately so a staged edit whose working file matches HEAD still counts) and committed paths not yet merged into the integration branch (merge-base diff against the same integration ref finish uses). List at most four paths, then `+N more`. Any git failure makes that piece `unknown`, never clean. Keep the logic in `specy_road/session_overlap.py`; verify through the public session CLI tests.
