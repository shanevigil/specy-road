## Intent

Claude Code's headless docs say `--bare` "will become the default for `-p` in a future release" (read 2026-10-30). Without `--bare`, `claude -p` loads hooks, skills, subagents, plugins, MCP servers and CLAUDE.md as an interactive session would; with it, none of that. specy-road's design intent (principle 5, harness-native) is that a worker keeps its harness's native tools, so the discovery mode must be a recorded choice per profile that the adapter honours and checks, not a vendor default that can move under us. Design: `docs/design-notes/agent-performance-research-triage.md` (recommendation 1).

## Approach

Add `launch_mode` to the profile's `access` block in `specy_road/model_profiles.py` (validated like `effort_map`). In `ClaudeCode.launch` and `ClaudeCode.resume` (`specy_road/worker_adapters.py`, 342 lines, cap 400: keep it tight), insert `--bare` only when the profile says `bare`; a custom `channels.cli` is never rewritten. In `ClaudeCode.parse`, read the `system/init` line's `version`, `tools`, `mcp_servers` and `plugins` into the `started` event's `detail`, infer the mode from the tool list (the bare set is Bash plus file read and edit), and when the profile's mode disagrees yield a second `error` event naming both; the adapter needs the profile's mode at parse time: `worker_ops.py` reads `access.launch_mode` from the pinned profile where it reads `access.cli` and passes it to `launch`/`resume`; the `Launch` dataclass carries it in the wrapper payload; `worker_runner.run()` hands the launch to the adapter and `_consume` accepts a list of parsed events so one `system/init` line can record `started` plus `error`. Coordinate with M10.1, which edits `run()` and `_consume` too: land after it. Document in `docs/orchestration-models.md` (profile fields) and the model-profiles README; set `launch_mode: full` in the two shipped Claude profiles with a comment that bare needs an API key. Check `suggested_prompts/` for a profile-field list and extend it if one exists. Verify with `pytest tests/test_worker_adapters.py tests/test_models_and_prompt.py`.

Converge verdict (brainstorm `agentic-performance`): Principle 5 (harness-native) depends on it; prerequisite to M8.2's hardened launch. Docs: orchestration-models.md profile fields; model-profiles README; suggested_prompts if the profile schema gains a field.
