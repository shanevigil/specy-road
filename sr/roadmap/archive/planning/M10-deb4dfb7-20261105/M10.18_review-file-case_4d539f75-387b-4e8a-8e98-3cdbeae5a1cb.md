## Intent

Found while coordinating M10.12 (2026-11-02). A reviewer wrote its record as `review-cursor-grok-4.6-high.md` instead of filing it. Running `review record` afterwards reported writing `REVIEW-cursor-grok-4.6-high.md`, but on macOS's case-insensitive filesystem that write kept the existing lowercase name, so `handoff status` and the gate (which look for the `REVIEW-` prefix case-sensitively) did not count the approval until the coordinator renamed the file in two steps.

## Approach

In `review_files.py`, write records by first removing any existing file whose name matches the target case-insensitively, then writing the canonical name; when listing records, match the `REVIEW-` prefix case-insensitively and normalise the reported name. Test with a lowercase file in a temporary directory (the logic must not depend on the host filesystem's case rules). Verify with the review-file tests and file-limits.
