## Intent

Let each nested repository choose how a leaf lands and where its worktree starts. Today `_land_one()` merges onto `remote/integration_branch` and pushes, and `_source_and_tip()` bases worktrees on the remote tip, so a repo whose sibling holds local-only commits, or which requires approval before any push, cannot use `nested_repos` at all.

## Approach

- **Schema.** In `specy_road/templates/project/schemas/git-workflow.schema.json`, the object form of a `nested_repos` item gains `land` (`push` | `local` | `manual`, default `push`) and `base` (`remote` | `local`, default `remote`). `NestedRepo` in `specy_road/nested_repos.py` gains both fields, read in `nested_repos()`.
- **Room.** `nested_repos.py` is at 394 lines: move `_land_one()`, `land_nested_branches()`, `_unpushed()`, `unpushed_branches()`, `describe_unpushed()` and `report_unpushed()` to new `specy_road/nested_repos_land.py`, re-exported from `nested_repos.py` so `finish_land_integration.py` and other callers keep working.
- **land: local.** Merge in the same temporary detached worktree, based on the *local* integration branch; then `git update-ref refs/heads/<ib> <merge> <old>` (fails if the branch moved) instead of pushing. If the integration branch is checked out in a dirty worktree, refuse with the next step.
- **land: manual.** `land_nested_branches()` returns not-ok with a message listing, per manual repo, the exact `git -C <repo> merge --no-ff <feature>` command, and "re-run finish-this-task after merging"; finish stops before landing the main repository. A re-run finds the branch already merged (the existing ancestor check) and proceeds.
- **base: local.** `_source_and_tip()` uses the local integration branch when `base: local`, else today's `base_ref()`.
- **Docs.** `docs/git-workflow.md` nested_repos section documents both keys with one example for "never push".
- **Verify.** Tests under `tests/` with a bare remote: push mode unchanged; local mode updates the local branch and the remote is unchanged; manual mode exits not-ok with the command and the remote unchanged, then succeeds after a manual merge; base local includes a local-only commit.
