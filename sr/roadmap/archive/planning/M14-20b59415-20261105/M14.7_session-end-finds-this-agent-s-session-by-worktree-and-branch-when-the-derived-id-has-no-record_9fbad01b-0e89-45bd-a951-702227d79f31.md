## Intent

Fix `session end` choosing no session. The default id is `<user>-s<POSIX session id>` (`default_agent_id()`), and a harness may run each shell call in a different POSIX session, so `end` derives an id with no record. With exactly one live session of the user's, `_end_own()` ends that one (correct; M13.7 only rewords its message). With several, as when parallel leaves each have a session in their own worktree, it refuses and the adopter had to pass `--agent`. This is a behaviour gap, not wording: the records already hold `worktree` and `branch`, which are enough to pick the right one.

## Approach

- In `_end_own()` (`specy_road/bundled_scripts/session_cli.py`, after M13.7's rewording lands), when `own_live_sessions()` returns more than one, filter by recorded `worktree` equal to this checkout's top (`git rev-parse --show-toplevel`, resolved) and `branch` equal to the current branch. Exactly one match → end it and say "ended <A>: the only live session for this worktree and branch (this shell's id <B> has no record)". Zero or several → today's refusal and list.
- Put the match helper in `specy_road/session_presence.py` (`own_session_here(repo_root)`) and use it in `touch` too, so a later shell call refreshes the right record.
- `session start` prints the id it recorded and the `export SPECY_ROAD_AGENT_ID=…` line (it already prints the export; make sure the id is stated first).
- **Verify.** Tests: two live sessions in two worktrees; `end` from each (with a different derived id) ends its own; ambiguous case still refuses.
