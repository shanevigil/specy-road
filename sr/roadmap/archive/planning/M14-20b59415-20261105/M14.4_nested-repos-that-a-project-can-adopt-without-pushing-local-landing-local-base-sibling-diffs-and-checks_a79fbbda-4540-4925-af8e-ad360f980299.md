## Intent

Remove the reasons a project with separately versioned repositories cannot adopt `nested_repos`: landing always pushes every nested repo and new worktrees always start from the remote tip, which projects with local-only commits or a confirm-before-push rule cannot accept. Until a project adopts it, give the review packet and the worker checks sight of the sibling repositories anyway.

## Approach

- M14.4.1 adds per-repo `land` and `base` modes. M14.4.2 (packet diffs) and M14.4.3 (reconcile and post-run check) reuse M14.1's `sibling_repos.py` for repositories that are not configured.
- The three leaves touch different files and can run in parallel once M14.1 lands (M14.4.1 does not need it).
- Done when a project with local-only sibling commits can configure `nested_repos` with `land: local, base: local` and run a leaf end to end without a push, and a project that has not can still review sibling diffs and see sibling changes in worker checks.

## Tasks / checklist

- [ ] M14.4.1 — `land: push|local|manual`, `base: remote|local`.
- [ ] M14.4.2 — `review-packet --extra-diff`; one line per sibling instead of per file.
- [ ] M14.4.3 — reconcile and post-run check report sibling changes.
- Out of scope: per-repo review policy; touch-zone enforcement in unconfigured siblings.
