## Intent

Make fix rounds converge by asking the executor to fix the class, not the instance. Each fresh review round re-reads everything and probes something new, so round counts are unpredictable. In a consumer run, asking the executor to "review every other value that crosses a JSON or database boundary" was followed by a round with only a test-hygiene finding. This toolkit's own run showed the same pattern: the reviewer found a new input class every round on several leaves (Markdown constructs on M13.6 and M13.3, path forms on M13.1, deferral binding on M12.1, ignore semantics on M13.7). Asking the executor to audit the whole class and list probes "checked and safe" in the summary converged M13.1 and M12.1 faster. A design change that removed the class converged M13.6, where the docs gate scans every line instead of parsing Markdown. Narrowing the acceptance's input class converged M13.3. The planning README already says acceptance should bound input classes; the fix prompt does not.

## Approach

- **Rework section.** In `rework_lines()` (`specy_road/bundled_scripts/role_prompt_rework.py`), after the blocking findings, add a short fixed block: for each finding, name its class (the kind of input, path or state that failed); check every other place in the change that class can reach; prefer a design change that removes the class over patching the one instance; list what you checked under `## Probes` in the implementation summary, one line each: what was checked, and the result. Keep it to about six lines; the prompt is long already.
- **Fix round by message.** `worker message <W> --fix-round` (`specy_road/bundled_scripts/worker_cli.py`, 393 lines: one argument line; logic in `specy_road/worker_ops_message.py`) sends the same block plus the current blocking findings (reuse `blocking_reviews()` and `_review_lines()`) as the message, with any text given appended. Plain `worker message` is unchanged.
- **Verify.** Tests: the rework section contains the class-audit block and `## Probes` instruction when blocking reviews exist, and nothing when none; `--fix-round` message text includes the block and the findings.

## Tasks / checklist

- [ ] A1 — Rework section asks for the class audit, design-over-patch, and a `## Probes` list in the summary.
- [ ] A2 — `worker message --fix-round` sends the same plus current findings; plain message unchanged; tests pin both.
- Out of scope: checking that the summary has the heading; reviewer-side changes (M14.5 covers reviewer probes).
