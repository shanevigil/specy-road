## Intent

M5.2's later review rounds recorded one Markdown mention form that the stale-command check still misses: inside a fenced block, a command token written as a one-line code span right after the product name (``specy-road `frob` ``) was not read as a mention, so an unregistered command written that way never warned. This slice reads that form, keeping M5.2's rule that a fenced block always warns.

## Approach

Extend `_mentions_in_fenced_line` in `specy_road/bundled_scripts/validate_stale_commands.py` to read a code span right after the product name as the command token, reusing `_span_command_token` (the parse open lines already use). Registered names and tokens that are not command-shaped stay quiet. Plain and span-token mentions on the same fenced line are reported in source order, as `unregistered_commands` documents. One test per form plus a mixed-order case through the public interface; no doc change, since the docs already say a fenced block always warns.
