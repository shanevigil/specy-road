## Intent

Under `on_complete: pr`, parallel leaves always conflict on bookkeeping once the first PR merges: `roadmap/registry.yaml` and `roadmap-context.md` conflict even with no shared code, and resolving them means hand-editing generated files and another CI cycle per PR. Finish already resolves these three paths when it opens the PR (`finish_pr_merge.merge_integration_resolving_bookkeeping`), but nothing does it after another leaf merges. Separately, pickup's register commit does not regenerate the digest, so `digest --check` fails on every new leaf branch on its own claim line.

## Approach

- New `specy_road/reconcile_branch.py` and a `reconcile-branch` entry in `cli.py`'s script map (one line; `cli.py` is at 390). It reuses `merge_integration_resolving_bookkeeping` (fetch first), then commits and pushes when the branch has an upstream. Code conflicts abort with names.
- Design choice: a command, not a `.gitattributes` merge driver, because forge merges never run custom drivers and a driver cannot regenerate files from the merged tree.
- Pickup: move the register step from `do_next_task.py` (386 lines) into `do_next_task_register.py`; after writing the registry row, run export and digest and include `roadmap-context.md` (and `roadmap.md` if changed) in the same commit. Update `abort_task_pickup`'s own-registration check to accept those generated paths only.
- Docs in a new `docs/git-workflow-parallel-prs.md` (git-workflow.md is at 383) and a line in the finish stub.
- Tests: the two-leaf scenario; a code-conflict refusal; digest --check right after pickup; abort after the new register commit.

## Tasks / checklist
