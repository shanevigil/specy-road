## Intent

M15.34's two finish runs (09:12 and 09:13 on 2026-11-05) appeared to stop silently after a passing land check. The branch was not merged and was left with a "complete, deregister" commit, so the coordinator treated the leaf as an orphan claim. A failed landing must be visible where people look, at the end of the output, and it must not leave the branch in a state that other tools misread (rc4 fix, maintainer 2026-11-05).

## Approach

Root cause, from work/grind-logs/M15.34-finish.log and M15.34-finish-retry.log in the main checkout:
- finish did not exit silently. Both runs printed `error: could not land merge to WIP/improvements-0-3-1: git push origin WIP/improvements-0-3-1 failed: remote: fatal error in commit_refs ... ! [remote rejected] ... (failure)`, which is a GitHub server-side push rejection, followed by the re-run hint from `merge_landing_failed`.
- That error goes to stderr, which is unbuffered. Everything else goes to stdout, including the land check output that `finish_land_check._run_streaming` copies with `sys.stdout.write`, and stdout is block-buffered when piped. sr/tools/land.sh runs `finish-this-task 2>&1 | tee`, so the error comes first in the log and the log ends with the pytest summary. Anyone reading the tail sees "passed" and nothing else.
- The bookkeeping commit is left on purpose. `_bookkeeping_commit_phase` commits before `apply_on_complete_mode` lands, and `merge_landing_failed` says "the bookkeeping is already committed, so it retries only the landing". That commit removes the claim on the branch, which is what made the coordinator see an orphan.

Fix:
- Make stdout line-buffered for the finish process (for example `sys.stdout.reconfigure(line_buffering=True)` in `finish_task.main`), or flush before each stderr write, so the order is right under a pipe.
- Record the pre-bookkeeping sha and the bytes of the work files the cleanup removes. On a merge-mode landing failure or exception, restore them with `git reset --keep` and rewrite the files. A small new module (finish_bookkeeping_undo.py) keeps finish_task.py and finish_modes.py within their line and function caps.
- Keep `retry_merge_landing` for branches that an older version already finished.
