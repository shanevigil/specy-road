## Intent

A safety bug: `specy-road prompt --channel cli --role reviewer` did not just write a prompt; it ran the profile's `access.cli` example (`agent -p --force "<prompt>"`) with no `--model` and from the main checkout on the integration branch. That run filed an approve under the rostered model's name, and `review list` counted it toward the gate although that model never ran. M8.3 fixes part of it: entries on claude-code, codex or cursor without `channels.cli` now use the adapter's read-only command with the rostered model and no `--force`, and specy-road files the record. What remains: the channel still launches without being asked to, it falls back to `access.cli` for other harnesses, it runs in whatever checkout invoked it, and nothing checks that the harness ran the rostered model.

## Approach

- `--run` flag in `role_prompt.py`'s parser (371 lines after M8.3); without it `--channel cli` writes the prompt and prints the command (as `_shown` does). The run logic stays in `role_prompt_cli.py`.
- `role_prompt_cli.run_reviewer_channel`: drop the `prof.cli()` fallback for reviewers; refuse an unknown API id and permission-bypass flags before launch.
- Worktree: find the worktree with the claimed branch checked out (`git worktree list --porcelain`); `--worktree PATH` overrides; refuse when none. Pass it as the launch cwd (and cursor's workspace flag if the adapter needs one).
- New `specy_road/review_model_check.py`: `normalise(name)`, `reported_model(lines, adapter)` reusing the init/result parsing in `worker_adapter_parsers.py`, `check(reported, entry, profile) -> match | mismatch | unreported`. `review_record_write.file_review` writes `harness_model` and `model_mismatch`; `review_eligible.py` excludes mismatches.
- CHANGELOG line for the behaviour change (text only; no version heading).
