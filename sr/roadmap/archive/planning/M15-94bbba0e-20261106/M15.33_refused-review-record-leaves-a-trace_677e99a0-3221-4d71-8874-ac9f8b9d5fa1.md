## Intent

A reviewer working in the paste or subagent channel ran `review record`, which refused, and then told the coordinator it had filed. `review list` and `handoff status` showed nothing for that model. The coordinator could not tell "refused" from "never started". M15.17 marks superseded failed RUN records, and M15.29 (held) adds started markers. Neither records a refusal.

## Approach

- New `specy_road/review_rejected.py`: `write_rejected(reviews, model, commit, reason)` and `clear_rejected(reviews, model)`. Also `rejected_state(reviews, model, commit)`, which returns `(age, first_line)` or `None`.
- Use `REJECTED-<model>.md`, not `REVIEW-<model>.rejected.md`, because `review_files` reads every `REVIEW-*.md` as a record.
- `review_cli.cmd_review_record`: wrap its refusal path (`_fail`) so that once the target and model resolve, a refusal also writes the marker. A successful write clears it. Keep `review_cli.py` within 400 lines and put the logic in the new module.
- `review_run_status.py` (from M15.17): add the "record refused" line and the `refused` JSON key for review list and handoff status.

## Tasks / checklist

- [ ] A1: marker written on refusal and removed on filing; loaders ignore it.
- [ ] A2: review list and handoff status, in text and JSON.
- [ ] A3: delegated filing path covered by the same code; tests.
- [ ] A4: Out of scope: refusals before node or model resolve, a reviewer's own chat claims, retries.
