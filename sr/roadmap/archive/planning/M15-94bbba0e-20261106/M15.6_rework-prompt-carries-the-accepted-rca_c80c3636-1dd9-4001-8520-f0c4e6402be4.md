## Intent

After a root-cause analysis was accepted, `worker delegate --rework` sent a prompt with only the last blocking review, which proposed the opposite design, plus the previous worker's last message; the RCA was absent. The coordinator had to run the executor by hand with the RCA, losing worker usage and timeline. The RCA should govern the rework.

## Approach

- New `specy_road/rework_rca.py`: `governing_rca(root, node_id) -> RcaDoc | None` reading the accepted RCA through the M12.1 next-step state (`review_next_step.py`, `review_rca.py`), and `rca_lines(doc, reviews)` rendering design and required changes first, then an overruling sentence.
- `role_prompt_rework.rework_lines` calls it before the review loop and marks each review as filed before or after the RCA; `rework_check` names the RCA or refuses when one exists but cannot be rendered.
- Coordinate with M14.11 (claimed), which changes the same rework section for the class audit.

## Tasks / checklist

- [ ] A1 — Accepted RCA first under ## Rework, labelled governing; reviews marked before/after.
- [ ] A2 — `--rework` note names it; refusal when it cannot be carried.
- [ ] A3 — Reported-case test; no-RCA prompt unchanged. Out of scope: which RCA is accepted; the class audit.
