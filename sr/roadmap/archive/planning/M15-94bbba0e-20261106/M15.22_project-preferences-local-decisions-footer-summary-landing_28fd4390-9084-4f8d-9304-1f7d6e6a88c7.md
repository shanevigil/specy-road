## Intent

Repos with stricter rules than the defaults hit four fixed behaviours: `decisions add` writes tracked `roadmap/decisions.yaml`, so in repos that forbid commits to the integration branch a preference needs a PR before it applies; finish's PR body has no configurable attribution footer; the executor prompt says to commit `work/implementation-summary-*.md`, so workers `git add -f` against a repo that ignores them; and merge mode always pushes, with local landing available only for nested repos (M14.4.1).

## Approach

- New `specy_road/decisions_local.py` (decisions.py is at 391; M12.1 also changes it, so depend on M12.1): load and merge `roadmap/decisions.local.yaml`; ensure it is in the managed ignore block.
- New `specy_road/workflow_prefs.py` reading `pr_body_footer` and `implementation_summary` from git-workflow.yaml (git_workflow_config.py is at 396: one accessor call there at most); schema update.
- `finish_pr_body.py` appends the footer; `do_next_prompt.py` picks the summary wording; validate notice on a conflicting ignore rule.
- Root `land: push | local` reusing M14.4.1's semantics in `finish_modes.py`.
- Docs: new `docs/git-workflow-preferences.md`.
