## Intent

Catch drift between what the toolkit enforces and what its docs and agent files claim, on a schedule, instead of when a user trips over it. The leaf adds a read-only scan that reports each kind of drift one line per finding, and an opt-in mode that files each finding class as one small leaf for an executor. The scan never edits code; humans and the normal pickup/review loop do the fixing.

## Approach

- **Command.** Implement as `specy-road chore garden` in `specy_road/bundled_scripts/chore_cli.py` (a new subparser beside `start` / `close`), so no new top-level entry in `specy_road/cli.py` is needed. Output: one line per finding, `<class>: <path>:<line>: <detail>`, exit 0 whether or not findings exist (it is a report); `--json` for machines.
- **Scans (each a function returning findings, read-only):**
  - `stale-command` — reuse `unregistered_commands()` from `specy_road/bundled_scripts/validate_stale_commands.py` over `docs/**/*.md` and the managed agent files (`AGENTS.md`, `CLAUDE.md`, the team file `warn_unregistered_commands()` already reads), not just the files validate checks today. Factor the file list out of `warn_unregistered_commands()` so validate and garden share the scanner and only the path set differs.
  - `advisory-rule` — lines in managed agent files whose provenance comment (`PROVENANCE` in `specy_road/agent_guide_block.py`: `<!-- prevents: … | enforced: … | ref: … -->`) says `enforced: advisory`; one finding per rule, so a PM sees which rules nothing checks.
  - `ratchet-grew` — for each `policy.ratchet_paths` entry (`integration_ratchet_paths()` in `specy_road/integrity.py`), lines added since the newest tag (`git describe --tags --abbrev=0`), reusing `_ratchet_findings()` with the tag as base. No tag → this scan reports nothing and says why once.
- **`--open-chores`.** For each finding *class* with at least one finding, add at most one leaf through the existing add-node write (`append_node_to_chunk` / `next_child_id` as `brainstorm_promote.py` uses them) under a parent named by `--under <PARENT>` (required with `--open-chores`). Title from the class (e.g. "Garden: stale command mentions"), acceptance one line per finding path (capped, with a count), touch zones = the finding paths. Idempotent: the codename is derived from the class (`garden-<class>`); if a non-Complete node with that codename exists, add nothing and print its id. Never edits code, docs or agent files.
- **Cadence.** Optional `policy.garden_cadence_days` in the orchestration schema (`specy_road/templates/project/schemas/orchestration.schema.json`, under the `specy_road/templates/project/` zone). `chore garden` records its last run in `work/chores/garden.json` (gitignored, beside other chore records); `validate_roadmap.py` warns "gardening due: last run …, every N days; run `specy-road chore garden`" with the same arithmetic as `_register_entry_problems()` for research cadences. Unset cadence → no warning.
- **Docs.** `docs/orchestration-chores.md` gains a "Gardening" section: the three scans, `--open-chores --under`, the cadence key, and an unattended recipe (cron/CI running `chore garden --json`, a human or coordinator then running `--open-chores`).
- **Verify.** Tests under `tests/` (extend `tests/test_chore_mode.py` and `tests/test_validate_stale_commands.py`): each scan on a temp repo; `--open-chores` run twice adds one leaf per class then nothing; cadence warning due/not due. `specy-road file-limits`.

## Tasks / checklist

- [ ] A1 — `specy-road chore garden` prints one line per finding for stale command/flag mentions in `docs/*.md` and agent files, `enforced: advisory` rules in managed agent files, and ratchet baselines grown since the last tag; it writes nothing tracked. Test per scan on a fixture repo.
- [ ] A2 — `--open-chores --under <PARENT>` adds at most one leaf per finding class (title, acceptance, touch zones from the finding paths) via the add-node write; a second run with the same findings adds nothing (test asserts the roadmap is byte-identical after run 2).
- [ ] A3 — With `policy.garden_cadence_days` set, `specy-road validate` warns when gardening is due and names the command; unset → no warning. `docs/orchestration-chores.md` documents scans, cadence and the unattended recipe.
- Out of scope: fixing any finding automatically; new scan classes beyond the three named; making the cadence warning fatal; running gardening from CI in this repo; changing what `validate` itself checks in `AGENTS.md`/`CLAUDE.md`.
