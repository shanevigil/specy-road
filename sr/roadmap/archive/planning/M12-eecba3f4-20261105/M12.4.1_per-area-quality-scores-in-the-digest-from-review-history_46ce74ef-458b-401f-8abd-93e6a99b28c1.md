## Intent

Show, in the digest every agent reads first, which areas of the project keep costing extra review: per touch-zone area, how many leaves landed and how many review rounds, blocks, integrity findings and RCA escalations they took. Weak areas are listed first with their numbers, so a planner writes tighter acceptance there and a coordinator can (opt-in) route a stronger reviewer to leaves touching them.

## Approach

- **Determinism first.** `digest --check` runs on every checkout and in CI, but the review records (`work/reviews/<ID>/`) are gitignored and exist only where the loop ran. So the section must be computed from data every checkout has, or `digest --check` drifts between machines. Rule for this leaf: per-leaf numbers come from tracked git history; the local review records are only the *source* that writes them. Concretely: when the gate commit is made, add one trailer beside the existing `Reviewed-by` lines (`commit_trailers()` in `specy_road/review_gate.py`), e.g. `Review-tally: rounds=<n> blocks=<b> integrity=<i> rca=<r>`, computed with `review_rounds()` / `loop_state()` from `specy_road/review_rca.py` and the integrity problems the gate already evaluates. The digest reads those trailers from git history (the same history the digest already uses via `history_index`). Leaves landed before the trailer existed count as landed with unknown tallies and are excluded from the means (the section says how many).
- **Areas.** Area = the first `quality_area_depth` path components (default 1) of each touch zone, relative to the project root; a leaf counts once per distinct area. Window = the last `quality_window` (default 50) completed leaves, ordered by gate commit order (not wall clock).
- **Section.** New `_section_quality(root)` in `specy_road/digest.py`, appended in `render_digest()` before the footer. Columns: area, leaves, mean rounds, block rate, integrity findings, RCA escalations. Areas whose block rate (or mean rounds) exceeds `quality_threshold` sort first and are marked; ties broken by area name. No history → no section at all.
- **Policy.** Defaults for `quality_window`, `quality_area_depth`, `quality_threshold`, `quality_routing: false` in `specy_road/orchestration_config.py`; matching properties in the orchestration schema.
- **Routing.** With `policy.quality_routing` on, `orchestrate plan` marks a leaf whose touch zones fall in a flagged area as wanting a `strong_review` reviewer (reusing `specy_road/review_strong.py`'s notion of a strong reviewer set); off → plan output unchanged.
- **CLI.** `specy_road/bundled_scripts/digest_cli.py` gains no new flag; the section follows policy only.
- **Docs.** `docs/orchestration-review.md` gains "Quality by area": what is counted, where it comes from, the policy keys.
- **Verify.** Tests under `tests/` (extend `tests/test_digest.py`): a temp repo with gate commits carrying tallies → expected section; same repo digested twice and with an unrelated clock → identical bytes; empty history → no section; routing on/off. `specy-road digest --check` on this repo and the dogfood fixture.

## Tasks / checklist

- [ ] A1 — `roadmap-context.md` gains "Quality by area": per area (configurable depth), leaves landed, mean review rounds, block rate, integrity findings, RCA escalations over the last N completed leaves (default 50), from data already on disk (tracked history). Test on a fixture history.
- [ ] A2 — Areas over the threshold are listed first with their numbers; output is byte-identical across runs and checkouts (no timestamps, no gitignored inputs); empty history prints nothing. Tests pin each.
- [ ] A3 — `policy.quality_routing` (default off) lets `orchestrate plan` route strong review to leaves in flagged areas; a test pins on and off.
- Out of scope: per-model or per-person scores; back-filling tallies for leaves landed before this change; GUI display; making quality affect the review gate itself.
