## Intent

The roster is read from `origin/<integration>` because `access.cli` is executed, which is right for security, but no roster can be tried before it lands, so every roster mistake costs a full PR cycle; `models list` ignores the working tree without saying so. Two adopters asked for a local trial path, one for local roster entries beyond availability overlays.

## Approach

- `orchestrate plan --roster-from-worktree`: load the roster from the working tree through a flag on `orchestration_pinned`'s loader that only `orchestrate_cli.py` passes; banner and `roster_ref: worktree` in JSON. Delegation entry points keep the pinned loader (test).
- `models list`: name the ref; diff working tree vs ref by entry id.
- New `specy_road/roster_local.py`: `roster_add` in `roadmap/orchestration.local.yaml` (already gitignored and read for availability); merged after the pinned roster for this clone, ids may not clash, cli fields need `allow_local_cli: true`.
- Docs: new `docs/orchestration-roster.md` (orchestration.md is at 400).
