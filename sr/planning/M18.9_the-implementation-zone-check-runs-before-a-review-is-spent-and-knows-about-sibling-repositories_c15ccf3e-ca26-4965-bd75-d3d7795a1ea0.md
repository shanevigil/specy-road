## Intent

Run the "nothing was implemented" check before reviewers are paid, and stop it from misreading sibling-repository work. In a consumer run whose code lives in an ignored sibling repository, finish-this-task refused with "this branch changes no file under its declared touch zones" only after review and `mark-implementation-reviewed`. Fixing the zones moved the commit, so the approval went stale and a leaf with zero findings needed a second full review. This is the same root cause as F-063 (M14.1), with the opposite effect.

## Approach

- **Earlier.** `implementation_gate_error()` in `specy_road/finish_implementation_check.py` is already a pure check. Call it from `handoff ready` (`specy_road/review_gate_ready.py`, the READY writer) and from `review delegate` (`specy_road/review_delegate.py`, before launching), using the registry row's zones as `implementation_or_exit()` does. On refusal print the same message and exit 1. `handoff ready --allow-empty-implementation` mirrors finish's flag. Respect `require_implementation_before_finish()` so projects that disabled the check are unaffected.
- **Sibling-aware.** In `implementation_paths()`, after matching root and configured nested paths, if nothing matched and every zone lies inside a sibling repository from M14.1's `sibling_repos()`, return `None` ("cannot tell") with a reason the caller prints: "zones <z> are in sibling repository <path>, not configured in nested_repos; specy-road cannot see changes there". No refusal in that case.
- **validate.** In `warn_untracked_zones()` (`specy_road/bundled_scripts/touch_zone_tracked.py`, 195 lines), add a per-leaf check: every zone of an open leaf is inside a directory the root repository ignores (`git check-ignore`) → one warning naming the leaf, the directory and `nested_repos`. add-node and edit-node already run these zone checks, so they warn too. (M13.12, unclaimed, also edits this function's output.)
- **Verify.** Tests: a branch with no zone changes → `handoff ready` refuses before any review exists; same with `review delegate`; all zones in an ignored sibling repo with sibling changes → no refusal, "cannot tell" note; validate warning for an all-ignored-zones leaf.

## Tasks / checklist

- [ ] A1 — `handoff ready` and `review delegate` refuse as finish would; `--allow-empty-implementation` on ready.
- [ ] A2 — Zones inside sibling repos give "cannot tell" with the reason, not a refusal (reported case reproduced).
- [ ] A3 — validate warns when every zone of an open leaf is in an ignored directory.
- Out of scope: diffing sibling repositories for this check; changing finish-this-task's own check.
