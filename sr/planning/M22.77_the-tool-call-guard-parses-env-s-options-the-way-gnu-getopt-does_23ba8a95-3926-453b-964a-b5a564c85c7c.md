## Intent

The third gap in the tool-call guard on 2026-11-18. After M22.74 and M22.76, `env --split "git stash"` and every other unambiguous prefix of `--split-string` still classify as allowed; GNU env accepts them. Each fix today matched the list of forms found so far. This leaf ends the list-chasing: it parses env's options the way getopt does, and an enumerated test runs every destructive case through every wrapper form, so a new spelling of an existing case cannot slip past. Operator: "M22.77 ok" (RC blocker).

## Approach

- Model GNU coreutils env's options (name, whether it takes a value, short letter) in one small table, and parse argv against it with getopt_long's prefix and cluster rules. The command starts at the first non-option argument, or comes from the split-string value.
- The enumerated test crosses the existing destructive tables with a finite set of wrapper forms. That is a property check without Hypothesis; M16.7.7 adds Hypothesis later.
- No rule-table rewrite; that is M23.8.
- Depends on: M22.76. M16.8.4 depends on this leaf.

## Tier

trust: it changes the guard that refuses destructive commands.
