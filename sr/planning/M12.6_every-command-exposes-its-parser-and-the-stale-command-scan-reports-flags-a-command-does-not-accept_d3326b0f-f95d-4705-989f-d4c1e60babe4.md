## Intent

Low priority: last in this phase. Catch docs and agent files that name a flag a command does not accept, which M12.3 scoped out. Today the stale-command scan (validate's `warn_unregistered_commands`, and M12.3's garden scan) checks only command names: `specy_road/cli.py` is a dispatch table from command name to bundled script, with no record of each command's flags, and most bundled scripts build their argparse parser inside `main()` with no way to reach it from outside. Nested subcommands (`review record`, `worker delegate`, `handoff status` …) add depth.

## Approach

- **Parsers reachable.** About 20 of the bundled scripts already define `build_parser()`. For the rest, extract the parser construction from `main()` into `build_parser()` (or `_parser()` renamed) with no behaviour change. New `specy_road/cli_parsers.py` maps each command name to its builder by reading `cli.py`'s existing dispatch tables (the script map and `_FORWARDED`) and importing the module lazily. Commands implemented directly in `cli.py` are handled in `cli_parsers.py` itself, so `cli.py` (390 lines) grows by at most two lines. Subcommands are reached through the parser's `_SubParsersAction` choices.
- **Parity test.** It walks every registered command and every subcommand, asserts a parser is returned, collects each one's option strings, and prints the passthrough exemptions.
- **Flag scan.** New `specy_road/bundled_scripts/validate_stale_flags.py` (`validate_stale_commands.py` is at 338 lines, so only a call is added there). It reuses `validate_stale_commands`' mention parsing (`_command_mentions`, `_occurrences`, the code-span and fence handling) to get each `specy-road <cmd> [<sub>] …` mention, then checks each `--flag` token against that parser's option strings. Unknown flags are reported as `file:line: specy-road <cmd> [<sub>]: --flag is not an option; did you mean --x?` (`difflib.get_close_matches`). It does not check short options, values, or tokens after a bare `--`. `warn_unregistered_commands()` calls it for the same file set, and M12.3's garden scan (in `chore_cli.py`) gets it through the same function.
- **Passthrough exemptions** are declared, not guessed. A parser using `argparse.REMAINDER`, or carrying a marker attribute set by a declared passthrough group, is exempt; grind-session's implement-hook passthrough (`_add_passthrough_args` in `grind_session_args.py`) sets that marker.
- **Verify.** The parity test; a fixture doc with one stale flag and one valid flag (including a nested subcommand) pins the output; the existing `tests/test_validate_stale_commands.py` still passes; `specy-road validate` on this repo reports no false positives (fix real ones in the same change only if they are in docs the leaf already touches, otherwise list them in the summary).

## Tasks / checklist

- [ ] A1 — Every registered command and subcommand yields a parser through `cli_parsers.py`. Parity test included. `cli.py` grows by at most two lines.
- [ ] A2 — validate, and garden through the same function, report unknown flags with file:line and the closest valid flag. Fixture test.
- [ ] A3 — Passthrough commands are exempt by declaration and the exemptions are listed. No command's behaviour changes.
- Out of scope: behaviour-change semantics (M13.8), flag values, prose without a command.
