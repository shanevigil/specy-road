## Intent

Ship the upgrade prompt so each adopter does not write their own. The adopter rated this its most valuable suggestion: its hand-written 16-step procedure carried two wrong assumptions (it named a repo-local install that was a stale 0.1.0 while the real one was elsewhere, and it named the wrong pin file). `specy-road upgrade --prompt <VERSION>` writes `work/prompt-upgrade-<VERSION>.md` for an agent, filled in with this repo's real values, and changes nothing else.

## Approach

- New `specy_road/upgrade_prompt.py` with `render_upgrade_prompt(project, version) -> str` and a template `specy_road/templates/specyrd/upgrade-prompt.md` holding the fixed prose (reconcile rules, verify list, field-notes template). `upgrade.py` only adds the `--prompt VERSION` argument and the call; when given, upgrade writes the file and exits 0 without refreshing. Write it the way `write_agent_prompt()` in `specy_road/bundled_scripts/do_next_prompt.py` writes `work/prompt-<ID>.md` (path, atomic write, print the path).
- **Sections, each from live data:**
  1. Install: running version and `sys.prefix`, plus `launchers_on_path()` (M13.1) with versions.
  2. Pin: `version_pin.pinned_version()` (M13.8): file and value; whether VERSION is a pre-release (`version_skew._version_sort_key` / an `rc|a|b` suffix). If it is, give the hash-checked `--no-deps` TestPyPI recipe and say to leave the pin unchanged.
  3. Stop conditions: live sessions (`session_presence.list_sessions(live_only=True)`) and other worktrees (`git worktree list`), with branch.
  4. Baseline: run `validate`, `export --check`, `digest --check`, `file-limits` in subprocesses and record exit codes (the commands, not their full output).
  5. Preview recipe: cite `docs/upgrading.md` (M13.10) and inline its commands with VERSION filled in.
  6. Root AGENTS.md line count against the project's own `constraints/file-limits.yaml` cap if any, as a report; root agent files are developer-owned.
  7. Behaviour changes since the stamped version (M13.8 catalogue, selected as M13.11 does).
  8. Reconcile rules: never edit inside markers; never write `.specyrd/AGENTS.team.md` unless asked; duplicated means M13.3's heading matches or M13.11's `--report-duplicates` paragraphs; keep text when unsure.
  9. Verify list and an optional field-notes template.
- **Docs.** `docs/upgrading.md` gains a "Let an agent do it" section.
- **Verify.** Fixture repo with a `requirements.txt` pin, a second fake launcher on PATH and a linked worktree: each section contains the real value (pin file name, both launcher paths, worktree path), no `<placeholder>` text; the checkout's `git status` is unchanged apart from the prompt file.

## Tasks / checklist

- [ ] A1 — `upgrade --prompt <VERSION>` writes only `work/prompt-upgrade-<VERSION>.md`, with install, other launchers, pin location and pre-release handling.
- [ ] A2 — Stop conditions, baseline results, preview recipe, AGENTS.md size (report only), behaviour changes, verify list and field-notes template.
- [ ] A3 — Reconcile rules stated.
- [ ] A4 — Fixture test asserts real values, no placeholders; documented in `docs/upgrading.md`.
- Out of scope: running the upgrade; editing anything but the prompt file.
