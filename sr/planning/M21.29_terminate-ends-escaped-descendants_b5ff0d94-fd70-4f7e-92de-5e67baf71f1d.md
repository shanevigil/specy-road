## Intent

Defect D6 (Medium) from the rc4 real-harness checks (pre-release evidence 2026-11-05, runbook §5.9, calculator w-0003). A Cursor worker was in the middle of a shell-tool `sleep 120` when `worker terminate` ran. Terminate reported "terminated" and the process group was empty, but the `sleep` kept running: it was in its own session (`/bin/bash -O extglob -c … __cursor_command` as session leader), its parent was pid 1 and its cwd was in the worker's worktree. It had to be killed by pid.

`kill_group` signals only the wrapper's process group. Cursor's shell tool starts its commands in a new session, so they leave that group. The docs mention orphans only for Claude after SIGKILL.

Fix: terminate also ends the descendants of the worker's processes that left the group. It lists them before the first signal (while their parent links still hold) and checks each by start time, so a reused pid is never signalled.

Out of scope: a process that was already re-parented to init before terminate ran (no parent link is left to find); Windows; `worker interrupt` (unsupported, unchanged); a process's cwd as a kill criterion (another user's shell may sit in the worktree).

Overlaps checked (2026-11-05): no M21.16 to M21.23 zone names worker_process.py. M21.23 edits docs/orchestration-workers.md, which this leaf does not touch. M22.6 and M22.13 (rc5) edit worker_ops_lifecycle.py, not this file.

## Approach

- In `kill_group` (worker_process.py:199), after the group is verified and before the first `killpg`, read `ps -A -o pid=,ppid=,pgid=,lstart=` once. Collect every transitive descendant of the group's members that is not in the group, with its start time.
- After the group is gone, SIGTERM those still alive with the same start time, wait the same grace, then SIGKILL them. Raise `WorkerError` naming any pid still alive, as the group case does today.
- Use the same `ps` helper style as `_group_members` (:141). On a missing `ps`, behave as today.
