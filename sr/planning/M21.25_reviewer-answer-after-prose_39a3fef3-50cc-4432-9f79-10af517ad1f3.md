## Intent

Defect D2 (High) from the rc4 real-harness checks (pre-release evidence 2026-11-05, grind §7 on the calculator app, M3.3): `review delegate --model composer-2.5` failed 2/2 times, `--resume` included, with "rerun requested: the final message is not one complete JSON object". Cursor's stream-json `result` event joins all of the turn's assistant text, so the reviewer's valid approve object arrived behind its narration: `'Reading the reviewer prompt…\n\n\nRunning precondition checks…\n\n\n{"node_id":"M3.3",…,"verdict":"approve",…}'`. The review was lost and grind stopped with exit 4. Any reviewer that narrates is rejected, so Cursor cannot be a delegated reviewer.

The coordinator already works around this with sr/tools/last-json.py, which takes the last top-level object in the text. This leaf moves that rule into the product's one answer reader, with one stricter condition: the object must end the message. The extracted object still has to pass the review output schema, so the record rule (one schema-valid object, filed by specy-road) does not weaken.

Out of scope: the reviewer prompt's "exactly one JSON object" instruction (unchanged); the generic/agy envelope path; `review record`'s own input; sr/tools/ (coordinator tooling; it can drop last-json.py after this lands, but not in this leaf).

Overlaps checked (2026-11-05): no M21.16 to M21.23 zone names review_answer.py or tests/test_review_answer.py. M21.24 edits another row of docs/orchestration-reviewer-output.md. M22.9 (rc5) also lists that doc.

## Approach

- In `review_answer._answer`, for a string body with `envelope=False` (Cursor's `result` text, a Claude `result` without `structured_output`, Codex's `agent_message` or `-o` file): scan for `{` and `json.JSONDecoder.raw_decode` at each one, skipping past each decoded object, as last-json.py does. Keep the last dict whose end is followed only by whitespace. Use `loads_untrusted` limits, or an equivalent depth guard.
- Each refusal keeps the `RERUN` prefix and says why: "the final message holds no JSON object", "the final message does not end with a JSON object" (non-whitespace text after the last object), or the existing schema-mismatch reason for a last object that is invalid. An earlier valid object is never used as a fallback.
- The whole-message path stays as it is when the message is one object. `final_answer` stays total.
