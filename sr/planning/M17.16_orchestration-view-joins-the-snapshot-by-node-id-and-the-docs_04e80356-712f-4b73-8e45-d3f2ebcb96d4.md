## Intent

The orchestration view (drawer, outline badges, edit dialog section) never matches real snapshot data: GET /api/orchestration keys leaves by node id, while the GUI joins on the outline's node_key, so every leaf shows as missing from the outline and no badge renders. Its tests passed only because the mock and test fixtures used node_key keys. Found by the coordinator while writing M17.9's checklist (2026-11-14), before the sandbox run; the maintainer chose to fix it before the run ("fix first"), so the run checks fixed code and needs no second sandbox approval. The second defect: the GUI's worker status type and docs/pm-gui.md name states the snapshot never sends (exited_ok, exited_failed, claimed, abandoned), so the failed-worker badge never fires.

Out of scope: changing the snapshot or the parity goldens, any new badge or drawer feature, other GUI views.

## Approach

- Change the GUI side only: the join key becomes the outline node's id. The server and the M16.3.1 parity goldens already agree on node id, and other readers of the snapshot use it.
- Replace node_key keys and invented worker states in the mock fixture and tests with what the snapshot sends; add one test that fails on the old join (an outline leaf rendered as missing).
- Run npm ci, lint, test and build in gui/pm-gantt; commit the rebuilt bundle under specy_road/pm_gantt_static/.
- Check with a live server: start `specy-road gui --read-only` on a repo with a claimed leaf and confirm GET /api/orchestration's key appears in the outline badge (curl the API and grep the built bundle's join, or a Playwright run if available).
