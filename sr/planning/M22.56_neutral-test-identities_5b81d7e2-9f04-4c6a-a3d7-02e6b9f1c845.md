## Intent

Two test files name the maintainer: `tests/test_claim_traps.py` uses a real name as a registry owner and git user name, and `tests/test_review_record_caller.py` uses the local username as a human filer. Those are personal data in a public tree. First pass of the sweep, inside RC5. Source: the maintainer's scrub plan (private), sections 3 and 5, approved 2026-11-09.

## Approach

Replace the values with neutral identities, for example Test User for the owner and alice for the filer. Change only the values; every assertion keeps its meaning. No other test changes.

## Tasks / checklist

- [ ] `tests/test_claim_traps.py`: neutral owner and git user name
- [ ] `tests/test_review_record_caller.py`: neutral human-filer value in the parametrized cases and the signed case
- [ ] Whole-word grep with the run-time values over `tests/` and `specy_road/` (M22.54 lands after this leaf and enforces the same check)

## Tier

plain: a value swap in two test files with no behaviour change.

## Done but wrong

- An assertion changed meaning: each changed line is either a literal value or an assertion comparing against the same new literal; the number of tests and parametrized cases is unchanged.
- A value was missed: a whole-word scan for the maintainer's name tokens and username, read at run time, hits no tracked file under `tests/` or `specy_road/`. The repo-owner handle inside github.com URLs contains a name token and is not a hit; a substring grep is the wrong check.

## If this fails

Assumption: no other test or fixture depends on these exact strings (for example a golden transcript). If one does, stop and name it; frozen captures under `tests/parity/` are not edited by this leaf.

## Accepted limits

- The repo-owner handle in github.com URLs stays; it is allowed while the repo lives under that account.
- `owner:` values and presence session names under `sr/` stay. The registry is never hand-edited, and `sr/` leaves the tracked tree in M22.60.
