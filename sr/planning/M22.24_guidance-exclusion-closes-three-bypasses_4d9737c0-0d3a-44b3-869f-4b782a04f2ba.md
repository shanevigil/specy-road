## Intent

Security leaf in M22's fix intake. While `policy.signed_reviews` is on, a model whose profile records `guidance_bypass_observed` is kept out of the executor and reviewer roles unless its committed roster entry opts in (`orchestrate_assign.guidance_bypass_refusal`). The delta review found four ways an entry still launches such a model with no committed opt-in:

- **A human entry is exempt whatever it runs** (Sol F1, `orchestrate_assign.py:137`). `family: human` returns no hit before anything is read. So a local `roster_add` entry `{id: local-composer, family: human, roles: [executor], harness: cursor, harness_model: composer-2.5}` launches composer-2.5. That entry needs no `allow_local_cli`, because it sets no command.
- **Model discovery skips the profile's `access.cli`** (Sol F2, `orchestrate_assign.py:113`). A generic executor whose profile says `api_id: safe` and `access.cli: agent -p --model composer-2.5 {prompt}` passes the check. Yet `worker delegate` runs that command (`worker_ops_launch._cli_for`), and so does `prompt --role executor --channel cli` (`role_prompt_cli.resolve_cli`).
- **The committed-profile listing reads git's quoted names** (Sol F3, `orchestration_pinned.py:363`). Under the default `core.quotePath`, `model-profiles/custom/café.md` is listed as `"model-profiles/custom/caf\303\251.md"`. The `.md` suffix filter then drops it, so a project-only flag on an explicitly routed profile there never reaches the flag map.
- **A model flag it cannot read counts as no model, and names must match exactly** (Grok FAIL 2). `command_model` returns `None` for `--model "$(printf composer-2.5)"`, and a `None` adds no name. The flag lookup is exact, so `COMPOSER-2.5` misses `composer-2.5`.

This leaf closes all four and keeps the rule bounded: the exclusion covers what the roster and profiles declare, not a model hidden in a custom command. It lands in pass 0, before M16.5.3 moves the roster and orchestrate code into the orchestration package and before M16.5.4 makes one `check_assignment` decide every launch and the gate. Otherwise those refactors would carry the gaps forward as parity.

**What must stay fail-closed** (the leaf fails review if any of these loosens):

- An integration-branch read that fails refuses the entry and never reads as "not flagged". After this leaf that holds for a human entry with launch configuration too.
- A model flag specy-road cannot read refuses the entry while signed reviews are on. Only the committed roster's opt-in admits it.
- A listing git cannot return (a timeout, a non-zero exit, or a name that is not valid UTF-8) stays a `_failed` source, so every model entry is refused.
- A working-tree or feature-branch copy of a profile never clears a committed flag, and a `roster_add` entry still may not set `allow_guidance_bypass_model`. Both are unchanged.
- Comparing normalised names can only add matches. An exact match still matches.

## Approach

All the code changes are in `specy_road/orchestrate_assign.py` (`_launch_models`, `_guidance_hit`, and the refusal and warning texts) and `specy_road/orchestration_pinned.py` (`_committed_source`). No caller changes: `orchestrate plan`, `worker delegate`, `review delegate`, `prompt`, `handoff status`, the review gate and `validate`/`doctor` already pass the entry and its routed profile through `guidance_bypass_refusal`, `guidance_bypass_warning`, `guidance_problem` and `guidance_bypass_lines`.

- **The human exemption covers a person, not a launch** (acceptance line 1). `_guidance_hit` returns `None` for `family: human` only when all three hold:
  - the entry sets none of `harness`, `harness_model`, `harness_bin`, `profile`, `channels.cli` or `channels.cli_resume`;
  - the caller resolved no profile for it (`profile is None`). This covers a profile found by the entry's id, which `worker delegate`'s default `generic` harness would run;
  - `channels.paste`, `channels.subagent` and `preflight` are not model launches and do not remove the exemption.

  Any other human entry is judged like a model entry: its names are matched, and a read error refuses it. The exemption check runs for committed and local entries alike, at every caller. The other option in the acceptance, a refusal at the configuration boundary (`roster_local.merge_local_roster` or the roster schema), is not taken. Those files are outside the touch zones, and it would not cover a committed entry at the gate.
- **The profile's `access.cli` is a launch name** (acceptance line 2). `_launch_models` adds `command_model(copy.cli())` for each profile copy it is given: the routed profile and `src.committed(profile)`. So the integration-branch copy that `_cli_for` actually runs is read even when the working tree's copy differs. Every copy counts even when `channels.cli` wins on a given path, which can only add names.
- **The listing reads NUL-delimited output** (acceptance line 3). `_committed_source` runs `git_stdout(["ls-tree", "-r", "-z", "--name-only", sha, "--", PROFILES_REL])`, raw rather than stripped, and splits on `\0`, dropping the empty tail. The `.md` / `README.md` filter and `_committed_text` stay as they are. `_committed_text` already passes the unquoted path to `ls-tree` and `show`.
- **A model flag that cannot be read is refused** (acceptance line 5). A new helper in `orchestrate_assign.py` returns the first field among `channels.cli`, `channels.cli_resume` and each copy's `access.cli` whose command is unreadable:
  - it splits the command as `role_prompt_cli.bypass_problem` does: every backslash-newline removed, then `shlex` in POSIX mode with `punctuation_chars` and no comment character. A command that cannot be split counts as unreadable;
  - a model-flag word is `--model`, `--model=…`, `-m`, or `-m` with a value attached (`-mcomposer-2.5`);
  - a command is unreadable when it has a model-flag word and `command_model` returns `None` for it (a list, a pipeline, a substitution, a variable, or an attached value), or when it has more than one model-flag word.

  While signed reviews are on, an unreadable entry gets the refusal below. An integration-branch read error still takes precedence and keeps its own text.

  ```text
  <id> (model unreadable in <field>) is excluded from executor and reviewer roles while policy.signed_reviews is on: its <field> passes a model flag specy-road cannot read (one simple command with one literal --model / -m value is readable), so the model it launches cannot be checked for recorded guidance bypass. Pass the model as one literal --model <id>, or set allow_guidance_bypass_model: true on its committed roster entry to use it at your own risk.
  ```

  The committed opt-in admits such an entry, because the opt-in already admits a flagged model and an unknown one is at most flagged. The launch then prints `warning: <id> (model unreadable in <field>) opted in at its own risk: its <field> passes a model flag specy-road cannot read`. `validate` and `doctor` print the same two warning forms (`is excluded` / `opted in at its own risk`) through `guidance_bypass_lines`.
- **Names are compared after normalising.** Each launch name is matched against each flag key with `model_names.same_model(name, key)`, which applies `normalise` and drops Cursor's `cursor-` prefix, instead of `n in src.flags`. The record comes from the matched key, and `(model …)` shows the name as the entry spells it. `composer-2` stays unflagged, because it normalises to `composer-2`, not `composer-2-5`.
- **Docs** (`docs/orchestration-roster.md`, "Models observed to bypass the guidance") get the bounded rule as one paragraph:
  - the exclusion covers declared configuration: the profile's `api_id` and aliases, `harness_model`, the roster id, and the literal model flag of `channels.cli`, `channels.cli_resume` and the profile's `access.cli`, compared after normalising;
  - a model flag it cannot read is refused;
  - `family: human` is exempt only without launch configuration;
  - it does not see a model chosen inside a script or wrapper the command runs, by an environment variable, by a harness's own config file, or by a harness's default when no model is passed.
- **CHANGELOG:** extend the existing `[Unreleased]` guidance-bypass Security bullet, without adding a version heading.
- **Verify:** `pytest -n auto` (which includes `tests/test_guidance_bypass_roles.py`), `specy-road file-limits`, and `specy-road validate --repo-root tests/fixtures/specy_road_dogfood`. Every row goes through the public CLI (`prompt`, `worker delegate`, `review delegate`, `handoff status --json`, `validate`), reusing the file's `roster`, `guidance_repo`, `on_dev` and `launched` helpers. Extend `roster()` with an option to omit `channels`. Tests never import or patch a `_`-prefixed name.

## Tasks / checklist

- [ ] **Line 1, the human exemption.** One parametrized row, with the entry either committed or local `roster_add`:
  - `{family: human, roles: [executor], harness: cursor, harness_model: composer-2.5}`;
  - `{family: human, roles: [executor], profile: <the bundled composer-2.5 path>}`;
  - `{family: human, roles: [executor], channels: {cli: 'agent -p --model composer-2.5 {prompt}'}}` (local with `allow_local_cli: true`).

  Each is refused by `worker delegate` and `prompt --role executor`: exit 1, the excluded text names `(model composer-2.5)`, and the preflight and harness markers are absent. A person with no launch configuration keeps the exemption: extend `test_an_unreadable_integration_branch_profile_refuses` so that `handoff status --json` in the same repo shows the `human` reviewer row eligible while the model entry is refused.
- [ ] **Line 2, `access.cli`.** A generic executor with no `channels.cli`, routed to a committed `model-profiles/custom/safe.md` (`api_id: safe`, `access.cli: agent -p --model composer-2.5 {prompt}`). It is refused, with nothing launched, by both `worker delegate` and `prompt --role executor --run --channel cli` (parametrized). A committed copy keeps that `access.cli` while the working tree's copy sets `access.cli: none`, and the entry is still refused.
- [ ] **Line 3, quoted paths.** An explicit `profile: model-profiles/custom/café.md` (`api_id: my-model`, with a project-only `guidance_bypass_observed`), committed on `dev`. `prompt --role executor --model my-model` exits 1 with `my-model (model my-model) is excluded`. The test sets `core.quotePath=true` through `GIT_CONFIG_COUNT`, so a developer's own `core.quotePath=false` cannot hide the regression.
- [ ] **Line 5, unreadable flags.** These are refused with "passes a model flag specy-road cannot read", with nothing launched:
  - a local `roster_add` entry with `allow_local_cli: true` and `channels.cli: agent -p --model "$(printf composer-2.5)" {prompt}` (the review's case), through `worker delegate`;
  - parametrized commands: `cd . && agent --model composer-2.5 {prompt}`, `agent --model "$M" {prompt}`, `agent -mcomposer-2.5 {prompt}`, `agent --model safe -m composer-2.5 {prompt}`, an unbalanced quote, and the substitution in `cli_resume` only.

  The same entry with a committed opt-in launches and prints the opted-in warning once. With `signed_reviews` off, nothing changes: add an unreadable-command row to `test_unchanged_unless_a_flagged_model_meets_signed_reviews`.
- [ ] **Line 5, normalised names.** Extend the parametrized `test_every_model_an_entry_launches_is_matched` with `harness_model: COMPOSER-2.5`, `harness_model: cursor-composer-2.5` and `agent -p --model Composer_2.5 {prompt}`. Each is refused. `test_composer_2_is_not_flagged` still passes.
- [ ] **No shipped profile is refused.** A `validate` row: a repo with signed reviews on and one generic executor per bundled profile (`profile:` set, no `channels.cli`) prints `is excluded` only for the flagged composer-2.5 profile. Every shipped `access.cli` either passes one literal model flag or none.
- [ ] **Line 4, docs and CHANGELOG.** The bounded-rule paragraph in `docs/orchestration-roster.md` and the extended `[Unreleased]` Security bullet in `CHANGELOG.md`.
- [ ] **Out of scope** (each stated in the docs paragraph):
  - a model chosen inside a script, wrapper, alias or environment variable the command reads;
  - a harness's own config file, or its default model when no flag is passed;
  - abbreviated long options (`--mod`);
  - the coordinator role, which is unchanged;
  - how signatures are verified;
  - the roster schema and `roster_local.py`, which are outside the zones.
- [ ] **Concurrency.** The checks only read and keep no state beyond `guidance_source`'s per-commit cache, which is unchanged. Parallel launches each read the same committed source.
- [ ] **Input classes:**
  - commands: no flag, one literal flag, a flag in a list or pipeline, a substitution, a variable, an attached `-m` value, two flags, an unbalanced quote, a quoted flag word (`'--model' x`, which is read as `--model`);
  - names: exact, case, separators, the `cursor-` prefix, an alias;
  - human entries: with and without each launch key;
  - profile paths: ASCII, and non-ASCII (git quotes it). A name that is not valid UTF-8 already fails the listing and refuses, and needs no new code.
- [ ] **Gates:** `pytest -n auto`, `specy-road file-limits`, and `specy-road validate --repo-root tests/fixtures/specy_road_dogfood`. List every helper, branch, guard and test added, each with its reason.
