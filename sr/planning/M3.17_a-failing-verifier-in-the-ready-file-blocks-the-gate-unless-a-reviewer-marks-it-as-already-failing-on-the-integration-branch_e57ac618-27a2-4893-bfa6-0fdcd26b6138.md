## Intent

Three regressions landed on the integration branch overnight although their READY files reported the failing tests; the gate printed them only as notes. Make a failing verifier block unless a reviewer marks it pre-existing.

## Approach

Treat a non-zero READY verifier as a gate failure in `evaluate_gate` (the same
result `handoff status`, `mark-implementation-reviewed`, and `finish-this-task`
already consult). Add optional `verify_pre_existing` on the review-record schema
so an *approving* record can name commands that already fail identically on the
integration branch; coverage is the union of those names from counted approvals
only (blocks, stale and ineligible records do not contribute). An empty `verify`
list stays a reported note. Drop unreachable `not ready.ok` / non-approve
filters: `latest_ready` returns only valid files and `_count` already partitions
verdicts. Verify with `pytest tests/test_review_evidence.py` (failing verifier
blocks, marked pre-existing does not, marker on a block is ignored, no READY
does not invent a verifier problem, empty verify still notes and still passes).
