## Intent

Make a weak approve visible. In the reported run one reviewer approved in 70 seconds with no findings and about five lines of `commands_rerun`, although the prompt asks for at least one probe input; another reviewer blocked the same commit with 13 findings, three of them confirmed defects. With `reviewers_required: 1` the weak approve would have landed defective statistics. This toolkit's own run saw the same pattern.

## Approach

- **Prompt.** In `PROBE_RULES_LINES` (`specy_road/review_record_rules.py`), item 2 says to write each probe as a `commands_rerun` entry starting `probe:` with the input tried and what it returned.
- **Record.** In `check_record()`, count `commands_rerun` entries starting `probe:` (case-insensitive, after whitespace); write `probes: <n>` into the record (schema: optional integer filled by specy-road, plus `unprobed: true` on an approve with zero). Print a warning on such an approve naming the reviewer and the rule; do not refuse.
- **Policy.** `policy.require_probe` (boolean, default false) in the orchestration schema. In `specy_road/review_eligible.py`, an approve with `probes == 0` (or missing on a record filed after this change) is ineligible with reason "approve with no recorded probe", which handoff status already lists for ineligible records. Records filed before the field existed are not affected (no `probes` key → eligible).
- **Docs.** `docs/orchestration-review.md`: the probe convention, `require_probe`, and a `strong_review` example for numeric or statistical zones (the project names the zones; no default).
- **Verify.** Tests: approve with zero probes → warning and `unprobed`; with one → none; `require_probe` on → ineligible, off → counts; old record unaffected.

## Tasks / checklist
