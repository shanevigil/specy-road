## Intent

Nothing about a leaf's run is timed today: the event log has `at` on every event but no event for the moment the harness process started or first spoke, and nothing records when the coordinator saw a completion. The research timeline for one leaf (`docs/design-notes/agent-performance-research-triage.md`, section 3) is all estimate because of that. Two new events and a `worker timeline` command make the loop measure itself from files alone, which every later speed decision in M10 rests on.

## Approach

In `specy_road/worker_runner.py` `run()`, append `launched` right after `Popen` succeeds (detail: `argv0`, `harness`, `resumed`) and `first_output` before the first `_consume`; add both names to `specy_road/schemas/worker-event.schema.json`. In `specy_road/worker_ops.py` `sync(..., ack=True)`, record `acked_at` and the acked seq per worker in the existing sync state file (keep its current keys readable). Add `timeline` to `specy_road/bundled_scripts/worker_cli.py` (346 lines, cap 400: argparse wiring only there) with the phase arithmetic and text/JSON rendering in `worker_cli_render.py`; accept a worker id or a node id (latest worker for that node). Phases: delegated→launched, launched→first_output, first_output→turn end, turn end→acked; print `unknown` for a missing boundary. Update the event list and command table in `docs/orchestration-workers.md` (374 lines, cap 400: add rows, not prose). Verify with `pytest tests/test_worker_state.py tests/test_worker_cli.py tests/test_worker_faults.py`.

Converge verdict (brainstorm `agentic-performance`): Principle 9 (docs win, smallest change): states C1 best; M4.16 needs the same timestamps. Docs: orchestration-workers.md event table and fields.
