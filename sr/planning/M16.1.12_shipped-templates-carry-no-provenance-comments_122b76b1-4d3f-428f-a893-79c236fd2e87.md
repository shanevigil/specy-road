## Intent

Split from M16.1.5 at its third fix round. The shipped templates carry maintainer provenance comments (27 in `agents-rules.md`, 8 in `agents-md-block.md`, 2 in `claude-md-block.md`), and three modules read them from there. Adopters should not receive them. Moving them changes code and tests, which is more than M16.1.5's entry-point docs change.

## Approach

Move the provenance lines into `specy_road/agent_rule_provenance.md`, keeping each on the line after its rule, so the shipped templates are that text with those lines removed. The renderers keep reading the templates (they only strip these lines today). Only the garden scan reads the new file, and only inside a checkout.

## Tasks / checklist

- [ ] Move the comments and update the three readers
- [ ] Tests for rendered consumer files and the moved readers
- [ ] CHANGELOG entry

## Tier

behavioural: a template can look clean while a reader silently loses its provenance.

## Done but wrong

- Rendered files have no comment while the templates still carry them. Check: row (1) reads the template files, not the renderers.
- Fixture garden tests pass while `advisory_rule_findings` never opens the new file. Check: row (3).
- The new file and the templates drift (a rule loses its comment, or shipped rule text changes). Check: row (1)'s equality.

## If this fails

Assumption: a maintainer still needs each comment on the line after its rule, and that pairing survives in the new file. If a comment cannot be tied to its rule that way, or keeping garden findings would need the file shipped, stop and say so. The coordinator decides.

## Accepted limits

- Rendered consumer output does not change; it already omits these comments.
- Advisory comments a project writes into its own managed agent files still report.
- A comment whose enforced field is not advisory stays unreported, including "the rest is advisory".
- No rule ids: pairing is line adjacency inside the new file only.
