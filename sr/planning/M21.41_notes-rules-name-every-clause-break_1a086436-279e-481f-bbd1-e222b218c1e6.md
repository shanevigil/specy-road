## Intent

rc4 final review (§3.2, 2026-11-06): three small fixes found beside the FAILs.

1. **Notes rules.** `NOTES_RULES_LINES` (review_record_rules.py:54) is now also the repair-turn prompt (M21.35). It says a clause splits on `'. '`, `'; '` or a conjunction. The checker's `_CLAUSE_END` (:126) also splits on `'! '` and `'? '`, so a reviewer following the prompt is still refused. Example: `Ship it! The suite passed, not a defect because ...`.
2. **Rework docstring.** The rework_rca.py module docstring (:6) names `review_deferral.deferral_in_effect`, but the code calls `rca_deferral` (:92).
3. **Verify tests.** tests/test_brainstorm_verify.py:161 and :170, added by M21.36, monkeypatch the private `_is_off_host`, which the private-import rule forbids for new tests. Patch the public DNS boundary `socket.getaddrinfo` instead.

The approve-notes rule itself is unchanged (maintainer decision 2026-11-06); this leaf changes only the wording that describes it.

## Approach

- In the clause line of NOTES_RULES_LINES, name `'. '`, `'! '`, `'? '`, `'; '` and the conjunctions (and, but, while).
- Add a test that every separator `_CLAUSE_END` splits on appears in that line. It reads the regex's character class, so a future separator without a matching rule line fails the test.
- In the docstring, point at `review_deferral.rca_deferral`, keeping "the rule the gate and review_next_step apply".
- The two tests patch `socket.getaddrinfo` to return a public address for `example.com` (and a private one for any other host, matching the old lambda) and keep calling `check_source` with the fetcher argument.
- `scripts/check_test_private_imports.py`: the baseline does not grow.
