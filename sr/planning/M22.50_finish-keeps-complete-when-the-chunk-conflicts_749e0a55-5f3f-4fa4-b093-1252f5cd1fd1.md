## Intent

A leaf can land with its Complete status silently lost. Seen 2026-11-08 on M22.43: landing merge 5006d413 (parents 0c27b537 on WIP, ac62b8e8 the leaf's "complete, deregister" commit) resolved `sr/roadmap/phases/M22__b303b5.json` to the integration side. Its message says "finish's Complete status was applied again", but M22.43 stayed Not Started. Coordinator commit 0c27b537 had just changed another node's touch zones in that same chunk. The dispatcher then tried to pick up M22.43 again, and the coordinator restored the status by hand (24c04a5a).

## Approach

Reproduce the case first with a test, then find why `_complete_again` did not take effect: the bookkeeping commit not being found, `_finished_node_key` returning None, or the re-applied edit being lost before staging. Fix that cause. Make the merge message reflect what happened, and stop before pushing when the status cannot be re-applied.

## Tasks / checklist

- [ ] Reproduce with an integration-side edit to the same chunk
- [ ] Fix the cause; stop rather than push when Complete cannot be re-applied
- [ ] Test, CHANGELOG

## Tier

trust boundary: finish and land. A failure after its fix rounds is a blocking alert to the operator, not a coordinator decision (governance plan, 2026-11-09).

## Done but wrong

- The test passes because nothing conflicts: row 1 changes the finishing node's own sibling_order on the integration side, so its status line conflicts, under a nested project root (the likely cause: the graph-path lookup from `sr/` returns `roadmap/...` and the `sr/` prefix filter drops it).
- The leaf is Complete but other integration edits are lost: row 1 asserts the integration sibling_order and the other node's touch_zones survive.
- Recovery is skipped but finish still reports success: row 2 asserts a non-zero exit, an error naming the chunk and codename, and an unchanged integration ref.

## If this fails

Assumption: a nested temporary repository with a real chunk conflict still lands the leaf Not Started on today's code. If that reproduction already lands Complete, stop and record the landed status and the merge message; the coordinator decides before any file outside the zones is added.

## Accepted limits

- A clean merge of the chunk is unchanged. A conflict the branch authored is still refused.
- A leaf the integration side removed from the graph stays absent, and the message does not claim the status was applied.
- Conflicts outside roadmap chunks, and milestone-rollup landing, stay as they are.
