## Intent

An adopter followed the documented TestPyPI pattern with the `[gui]` extra and every variant failed: with TestPyPI as any index, a squatted dependency name there outranked PyPI's and pip ran the stranger's setup.py; uv's first-index would not take specy-road from the second index. Only a direct wheel URL worked. The landed RC recipe (M13.6) is safe for the bare package but never shows an extra, never shows the direct-URL form for uv tool or pipx, and the extras list omits `[gui]`.

## Approach

- Move the RC section to a new `docs/install-release-candidates.md` (`docs/install-and-usage.md` is at 395 lines); keep a two-line pointer and fix links in `docs/upgrading.md` and `docs/release-runbook.md`.
- Add per-tool commands with `[gui]`: pip (`pip install "rc/<wheel>[gui]"` after the `--no-deps` check), pipx and uv tool from the checked wheel, and the direct-URL form `"specy-road[gui] @ https://test-files.pythonhosted.org/.../<wheel>"`. Verify each command in a scratch environment before writing it; note the sha256 check for the URL form (download and `sha256sum` first, or a `#sha256=` fragment where the tool honours it — state only what you verified).
- One paragraph: TestPyPI is never an index for extras or dependencies, whatever the flag or strategy, and why.
- Extras list: name `[gui]`, `[gui-next]`, `[review]`; a test reads `pyproject.toml` `[project.optional-dependencies]` (minus `dev`) and asserts each is named.
- Runbook A.3 step 5: reword so the announcement carries the filled-in commands with `[gui]` plus the direct URL and sha256. The file is at 898 of its 900-line override: reword, no net lines.
