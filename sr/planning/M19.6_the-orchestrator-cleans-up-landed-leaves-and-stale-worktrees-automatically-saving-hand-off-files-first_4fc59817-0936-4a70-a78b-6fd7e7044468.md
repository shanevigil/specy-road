## Intent

Have the orchestrator do the worktree and worker cleanup a coordinator does by hand today, without losing anything. In today's run, after each leaf landed, the coordinator ran `git status --porcelain --ignored` in the leaf's worktree before force-removing it. Codex reviewers had written review history copies into that worktree's own ignored `work/reviews/<ID>/history/`, and for M13.5, M13.1 and M13.6 those had to be copied to the main checkout by hand or `worktree remove --force` would have deleted them. Stale worktrees from earlier sessions piled up (seven, under `.claude/worktrees/agent-*` and an old session's temp scratchpad), each audited by hand for unlanded commits, dirty files and ignored files that cannot be regenerated. Worker records for finished leaves also stayed behind.

## Approach

- **New module `specy_road/worktree_cleanup.py`.**
  - `REGENERABLE`: patterns for ignored files that are safe to delete: `__pycache__/`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `node_modules/`, `work/prompt-*.md`, `work/brief-*.md`, `work/.on-complete-*.yaml`, `.specyrd/cache/`.
  - `salvage_handoffs(worktree, node_id)`: copy everything under the worktree's own `work/reviews/<ID>/` (project prefix applied) into `reviews_root(main)/<ID>/`. A same-named file with the same bytes is skipped; a different one is kept beside it as `<name>.from-worktree<n>`. Return what was moved, so the ignored-file check treats those paths as saved.
  - `cleanup_after_land(root, node_id)`: salvage; then `plan_prune()` from `specy_road/worktree_prune.py`, whose refusals already cover branch not merged, uncommitted or untracked changes, stashes, a running worker and, after M14.3, another repository's worktree; then refuse on ignored files outside `REGENERABLE` and the salvaged set; then terminate an idle worker on the leaf (`worker_ops_lifecycle.terminate`); then `remove()`. Each refusal is one line with its reason.
  - `sweep(root, dry_run)`: walk `git worktree list --porcelain` (every linked worktree, wherever it lives; skip the main one and locked ones). A candidate's branch or detached HEAD is contained in the integration branch. It must be not live by M14.2's rules (the `doctor_worktrees` helpers: no registry claim, no non-terminal worker, branch with commits of its own), and have no live session (`session_presence.list_sessions` with that worktree). It must also pass the same unsaved-work checks. For each worktree print `removed`, `would remove` or `kept: <reason>`. It also ends orphaned workers through `worker_orphans.terminate_orphaned()`.
- **CLI.** `specy-road worktree cleanup <ID>` and `specy-road worktree sweep [--dry-run] [--delete-local-branch]` in `specy_road/bundled_scripts/worktree_cli.py` (81 lines). `--delete-local-branch` reuses `grind_session_cleanup.delete_local_branch()`, local only, and only for a branch the integration branch contains. Remote branches are never deleted.
- **Automation.**
  - grind-session calls `cleanup_after_land()` after each leaf it lands (hook beside `run_session_cleanup` in `specy_road/bundled_scripts/grind_session_cleanup.py`).
  - `policy.worktree_sweep: off|between_leaves` (default `off`) in `DEFAULT_POLICY` and the orchestration schema makes it also run `sweep()` between leaves.
  - `specyrd-orchestrate.md` step 7 says to run `worktree cleanup <ID>` after finish and `worktree sweep --dry-run` at session start.
  - `docs/orchestration-chores.md` gains a "Cleanup" section.
- **Verify.** Tests under `tests/`:
  - a review history file only in the leaf worktree's ignored `work/reviews/<ID>/history/` survives cleanup in the main checkout's hand-off dir, and the worktree is gone;
  - one test per refusal (unmerged commit, uncommitted change, untracked file, non-regenerable ignored file), each with nothing removed;
  - a sweep over claimed, live-session, dirty and removable worktrees prints the four expected lines, and `--dry-run` removes nothing;
  - a different same-named hand-off file is kept beside the existing one.

## Tasks / checklist

- [ ] A1 — `worktree cleanup <ID>` salvages leaf-local hand-off files, terminates the idle worker and removes the worktree. Test: a history file survives.
- [ ] A2 — Cleanup refuses on unmerged commits, uncommitted or untracked changes, or non-regenerable ignored files. It reuses `plan_prune` and worker terminate. One test per refusal.
- [ ] A3 — `worktree sweep [--dry-run]` finds removable linked worktrees anywhere, never claimed or live ones, and prints one line each. Test with four worktrees.
- [ ] A4 — grind-session cleans up after each landing. `policy.worktree_sweep` enables the between-leaves sweep. The orchestrate command and the chores doc describe both.
- [ ] A6 — Cleanup and sweep end session presence records of the removed worktree/branch.
- [ ] A7 — Sweep removes merged pickup-created worktrees; the branch is no longer skipped as '(worktree)'.
- [ ] A8 — Docs warn about `gh pr merge --delete-branch` and hand-off files; run `worktree cleanup` first.
- Out of scope: remote branch deletion (never); local branch deletion only with the opt-in flag; cleaning the main checkout's `work/` files, which finish-this-task's cleanup already owns.
