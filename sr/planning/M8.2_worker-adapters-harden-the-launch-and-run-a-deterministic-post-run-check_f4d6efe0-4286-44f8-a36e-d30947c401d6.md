## Intent

Worker adapters harden the launch and run a deterministic post-run check. Done when:
- Claude Code launches pass an explicit permission mode and allowed tools, no permission prompts, and the retry watchdog with a capped usage-limit wait; a worker stopped by a usage limit enters a paused-by-limit state that worker resume picks up after the reset
- Codex launches use exec --json with the workspace-write sandbox, both memory switches off and a per-profile CODEX_HOME; Cursor launches create the chat first and pass --force --trust and never -w
- After every turn the adapter checks the event stream for permission denials, failed turns and api retries, and the git state (HEAD, branch, stash list, porcelain) for anything beyond the expected files; a finding flags the worker and is shown by worker sync, regardless of exit code

## Approach

Work on top of M11.59's split (the per-harness adapter modules and worker_ops_* modules), one harness at a time.

- Claude Code: build the launch from the fixture's permission mode and allowed tools; recognise a usage limit in the stream (result subtype and api_retry lines) and move the worker to a paused-by-limit state with the reset time instead of idle/failed; resume keeps the launch flags.
- Codex: exec --json, workspace-write sandbox, memories off, per-profile CODEX_HOME; read the "try again at" time on a limit.
- Cursor: create the chat first, pass --force --trust, never -w.
- Post-run check (A3): one function per turn that reads the event stream (permission denials, failed turns, api retries) and git state (HEAD, branch, stash list, porcelain) and records findings as events that flag the worker.

Verify each harness with fake-binary tests that pin argv and replay recorded streams (the harness-captures fixture). Overlaps M11.62 (usage limits): coordinate by keeping the paused state in one place; whichever lands second reuses it.
