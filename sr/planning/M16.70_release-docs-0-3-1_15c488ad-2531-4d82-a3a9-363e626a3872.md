## Intent

The last content pass before the 0.3.1 tag: after the end-to-end pass (M16.65) and its fix leaves land, and after the alias window closes (M16.62), the docs adopters read first describe what actually ships. M16.31 restructures the docs by topic mid-milestone; this leaf is the final consistency sweep and the release summary, not a second restructure.

Out of scope: writing the `## [0.3.1]` heading, bumping `project.version` and tagging. Those are human-owned and happen at promotion. No product code changes; a doc that reveals a behaviour bug becomes a fix leaf.

## Approach

1. Generate the 0.3.1 command and config-key inventory from the parity harness (M16.0) after M16.62, and add a test that scans README.md, AGENTS.md, CLAUDE.md, docs/, constitution/ and constraints/README.md for removed command or alias names.
2. Walk README.md (install, `init project`, layout, quick start), AGENTS.md, CLAUDE.md and docs/ against the inventory and the branch head; fix drift.
3. Check each suggested_prompts/*.md against templates, schemas, validators and docs/roadmap-authoring.md (CLAUDE.md maintainer-hygiene rule).
4. Consolidate CHANGELOG [Unreleased] into an adopter-facing summary (Added, Changed, Deprecated/Removed with replacements, Fixed, Upgrading).
5. Run the gates in the acceptance and list the release-runbook promotion steps, marking the human-owned ones.
