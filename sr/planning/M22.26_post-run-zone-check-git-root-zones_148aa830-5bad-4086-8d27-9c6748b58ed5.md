## Intent

Fix the post-run zone check so a nested project's git-root zones match. `worker_turn_check._outside_zones` tries only the project-relative form of a path, so a zone written as `sr/...` never matches and a correct commit is flagged `committed_outside_zones`. This false stop has to go before any `sr/`-zoned leaf runs.

## Approach

Use `finish_implementation_check.in_zones` with the project prefix in `_outside_zones`, which tries both forms. No other behaviour changes. Verify through `close_turn` in a nested layout: a commit inside an `sr/...` zone and one inside a project-relative zone give no finding; a commit outside both still does.
