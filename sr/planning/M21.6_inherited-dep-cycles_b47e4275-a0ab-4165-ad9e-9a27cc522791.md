## Intent

rc4 roadmap-tooling fix (maintainer 2026-11-05), filed in M16's fix intake. A dependency on a milestone is inherited by every descendant (`effective_dependency_keys` in roadmap_layout.py, which do-next-available schedules from), but validate's `cycle_check` (validate_roadmap_checks.py) walks explicit edges only. A group edge plus a leaf edge can therefore form a cycle that validates and then never schedules. Nothing reports how much serialization a group edge adds. Checked 2026-11-05: sr/ and the dogfood fixture have no such cycle today.

Evidence: regrouping M16 into sub-milestones using only specy-road commands (scratch run, 2026-11-05) took about 85 commands, a temporary holder node and about 100 s, and left about 950 stale id mentions in prose. Earlier related fix: M16.8.5 (move-node renumbers only the moved subtree; whole-outline renumber became explicit).

## Approach

- Cycle check over effective dependencies, where a dependency on a group counts as one on each descendant (as its rollup does). The error names the cycle path, the inherited group edge and the leaf edge that closes it.
- add-dependency, set-dependencies, apply and the PM GUI dependency patch share `edit_node_set_pairs` validation, so they all refuse it with the same message and write nothing.
- add-dependency on a node with descendants prints how many descendant leaves newly wait, with the first few ids.
