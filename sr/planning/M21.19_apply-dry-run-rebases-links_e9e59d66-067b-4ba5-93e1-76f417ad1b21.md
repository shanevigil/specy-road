## Intent

Release blocker F4 plus roadmap W1. `apply --dry-run` rehearses a batch on `_scratch_root` (roadmap_crud_dependency_ops.py:301-326). That copies the graph trees with `copytree(..., symlinks=True)` and never rebases the links. `remove-node`'s `rehearsal_root` (roadmap_crud_delete.py:146-158) does rebase them, through `_rebase_graph_symlinks`.

- Data loss (sol). An `archive` entry, new in apply for rc4, resolves a planning sheet's path and `shutil.move`s it (archive_ops.py:69-73). When the scratch copy's sheet is an absolute symlink to the live repo, the dry run moves the live sheet into the temporary archive. The temporary directory then deletes it.
- Disagreement (grok). With an in-repo absolute chunk-directory link (`roadmap/phases` → `<repo>/roadmap/storage`), `apply --dry-run` exits 1 with "invalid include path (outside roadmap/)", while the real apply succeeds. `tests/test_remove_node.py` requires remove-node's dry run and real run to agree on that layout; apply has no such test.

Out of scope: the batch entry kinds and their semantics; remove-node's behaviour (its tests must pass unchanged); a rollback snapshot for dry run (a rehearsal must not need one); links that escape the repository in a real apply, beyond the archive refusal below.

Overlaps checked (2026-11-05): no other M21 leaf touches these files. M22.1 to M22.3 (rc5) touch group/move code, not the scratch root or archive_ops.

## Approach

- Move the rebase into the shared scratch root. `_scratch_root(root)` calls `_rebase_graph_symlinks(scratch, root.resolve())` before yielding, so every rehearsal (apply, remove-node, any later caller) sees the layout a real run writes. `rehearsal_root` then just yields `_scratch_root`. Move `_rebase_graph_symlinks` beside `_scratch_root` (or import it from roadmap_crud_delete; pick whichever avoids an import cycle). Its rule stays as is: links into a copied live tree are re-pointed at the scratch copy, and other links are kept.
- archive_ops `_move_planning_sheets`: refuse (ValueError naming the sheet) when a sheet's resolved source is outside `root` (`managed_block.resolves_outside(root, root / origin)`). The check runs before anything moves. In a rehearsal, root is the scratch root, so a link left pointing at the live tree or outside the repo is refused instead of moved. In a real apply, a sheet linked outside the repository is refused too. That matches the "never write through a link out" rule of M21.17.
- Tests in tests/test_roadmap_apply.py, via the CLI:
  1. apply `--dry-run` with an archive entry whose planning sheet is an absolute symlink into the live repo: exit 0 or a refusal. Either way the live sheet exists with identical bytes, and `git status --porcelain` of the live repo is unchanged.
  2. The same with a sheet linked outside the repository: refused, outside file bytes unchanged.
  3. The in-repo absolute chunk-directory layout (`in-repo-abs-dir-link` as in tests/test_remove_node.py): `apply --dry-run` of an edit-node title change exits 0 with live chunk bytes unchanged, and the real apply exits 0 and writes through the link, so both agree.
  4. A refused rehearsal (a later entry fails validation) after an archive entry leaves every live file's bytes unchanged.
