## Intent

In the clean-VM rc4 rehearsal (sr/work/sandbox-feedback/2026-11-05-rc4-trial-1da375e1.md, finding 2) `specy-road doctor` exited 1 in a new repo only because it had no `origin`: `fetch_integration` runs `git fetch --prune origin`, fails, and `_context` returns None. A repo with no remote has nothing remote to compare against, so that is not a failure. After this leaf doctor reports what it can and says in one line why the remote-backed checks were skipped; a real fetch failure still fails.

Out of scope: `branches prune` (shares `fetch_integration`, keeps its current refusal), comparing branches against a local base as a substitute for the remote, any new flag, and the usage text in cli_usage.py (M21.11 owns that file in this batch).

## Approach

1. In `doctor._context` (or `cmd_doctor`), before calling `fetch_integration`, resolve the remote the same way (`resolve_integration_defaults`: --remote, SPECY_ROAD_REMOTE, git-workflow.yaml, else origin) and check `git remote get-url <remote>`. If it is not configured, print one line, for example `doctor: no git remote named 'origin' is configured; skipped fetch and the branch and registry checks that compare against it.`, and return a marker meaning "no remote".
2. `cmd_doctor`: on "no remote", skip the branch/worktree/registry sections that need `remote/base`, still run the stash findings (they need no remote) and `_print_orphaned_claims`, and return `int(bad_config)`. If the stash section needs a `_Ctx`, list stashes directly with `_stash_findings(root)`; `--fix` applies only to what was listed.
3. Configured remote with a failing fetch: unchanged path, exit 1 and the existing error.
4. Keep doctor.py under the file and function line caps (now 324 lines; `cmd_doctor` must stay under 80 lines, so put the no-remote branch in a helper).

Verify: the new parametrized test and `pytest tests/test_doctor*.py`, then by hand: `git init`, `init project`, commit, `specy-road doctor` exits 0 with the line.
