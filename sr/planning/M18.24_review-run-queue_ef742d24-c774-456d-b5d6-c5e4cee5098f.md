## Intent

One command reviews one leaf the way the coordinator's `rv.sh` and review queue did: check that the branch still merges and stays in its zones, then run the reviewers the policy selects one after another, so a second reviewer is spent only after the first approves; cap how many reviewer runs go at once across leaves; and retry once when `review record` refuses a reviewer's answer. Today `review delegate` runs one reviewer and retries only capacity errors.

**Out of scope:** reviewer account pools (M18.23 covers executors); changing the review-record rules (M15.17, M21.12); plan review (M18.18); the reviewers' prompt text.

## Approach

- `review run` is a thin sequence over existing pieces: the packet (M15.17 builds a missing one), the trial-merge check (M3.13), the zone check before review (M18.9) and `review delegate` per reviewer. Registered from review_delegate's parser like M18.10's `review rca`, so `review_cli` gains no subcommand code.
- Sequential order saves the costlier reviewer when the first blocks (`rv.sh` ran Sol only after Grok approved).
- Concurrency: slot files under `work/reviews/.slots/` with the holder's pid and a random token, taken at review delegate's launch, reclaimed when the pid is dead or no longer carries the token; sequenced waiting tickets give arrival order. The shell queue deadlocked when it counted processes with `pgrep` (RE 2026-11-04, M12 orchestration) and lost its marker to a fast-failing duplicate run (RE 2026-11-05 03:51); a pid-owned slot and an early exit for a duplicate avoid both.
- Refusal retry resumes the same session with the refusal text, which is cheaper than a full rerun and replaces the coordinator's prompt addendum (OD 03:37) and `rv.sh`'s blind retry (OD 07:15).
- Depends on M16.5.12 (review fold), M16.4.3 (review command names), M18.9 (zone check before review) and M18.19 (reviewer selection).
