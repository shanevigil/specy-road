## Done but wrong

- The run renders the mock or a dev build, not the wheel's server. Check: RESULTS.md's wheel commit is the branch head, the URLs carry no `?mock=`, and a screenshot shows a seeded value the mock lacks, such as the seeded worker id.
- The expected values were fitted to what the page showed. Check: CHECKLIST.md is committed before the run date in RESULTS.md and is unchanged by the results commit.
- The running worker is not alive when the page loads, so "running" is never shown. Check: the setup script confirms `pid_alive` is true in `GET /api/orchestration` before the browser step.

## If this fails

The assumption most likely to break is that the sandbox tools and the image M17.10 approves can build the wheel and intercept or stub the 404 route as scripted. If not, RESULTS.md records where the run stopped. The maintainer decides on a new dated approval or other limits.
