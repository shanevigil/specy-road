## Intent

specy-road writes text with \n line endings but reads it back with Python's broad defaults: read_text() translates \r\n and \r, and str.splitlines() splits on \r, U+0085, U+2028, U+2029 and others. Where specy-road writes data and reads it back, or rewrites a file a user owns, anything other than plain \n lines can change. M16.7.7's properties found two such places: front matter (U+0085, U+2028 and U+2029 in a key or value read back as a space; the registry has the U+0085 case) and managed blocks (CRLF rewritten as LF, a whitespace-only tail dropped, blank lines before the tail collapsed, \r in a block line never idempotent). The maintainer chose one combined fix before RC5 (2026-11-20: "C1 behaviorial", "go"); M22.82 extends it to every other such path before 0.3.1. This leaf absorbs the former M23.12 and M23.15.

## Approach

- Add one helper beside atomic_write_text in specy_road/fs_atomic.py: read a file keeping its line endings exactly, and split text on \n only. Reuse it in the four subjects; do not add a second helper.
- Front matter: escape the three characters in the YAML the writer emits; readers split on \n only. Files written by earlier versions use \n only and must parse as before.
- Registry: escape U+0085 in dump_registry_text.
- Managed block: read and write keeping line endings; keep the text after the block byte-identical.
- Remove M16.7.7's matching exclusions in tests/property/ only to show they pass; M16.7.7's worker commits the property changes, so coordinate through the summary if the files differ.
- Depends on: nothing open. M16.7.7 and M16.8.4 depend on this leaf; M22.82 follows it.

## Tier

behavioural.
Path floor reviewed: specy_road/review_files.py, front-matter writer and reader line handling only; no review verdict, commit matching or landing logic changes (operator 2026-11-20: "C1 behaviorial").

## Done but wrong

- The readers stop splitting on the extra characters but a body loses its M22.75 behaviour: the M22.75 body tests must pass unchanged.
- Other non-ASCII text changes its rendering: an existing front-matter fixture must render byte-identical.
- CRLF is kept in the block's own lines but not in the user's lines: the test must use a CRLF file with user text before and after the block.

## If this fails

If escaping in the writer cannot make both readers round-trip without changing how hand-off files from earlier versions parse, stop and report; do not change the on-disk format of existing files.
