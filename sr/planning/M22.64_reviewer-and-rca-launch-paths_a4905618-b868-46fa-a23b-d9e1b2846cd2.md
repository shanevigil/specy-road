## Intent

Two launch and prompt defects on the review side, found in field use of 0.3.1rc4.

1. `prompt --role rca --channel cli --run` with a bundled Codex profile is refused once the prompt is over 128 KiB. An rca prompt carries every review round and the diffs between them, so it gets that large. The refusal is correct as a check (`oversized_arg`, `specy_road/worker_adapter_base.py:80-87`). The defect is that the bundled Codex command puts `"<prompt>"`, the whole text, on the command line, when `codex exec` reads its prompt from standard input (`worker_adapter_codex.py:60`).
2. A Codex reviewer runs in `sandbox_mode=read-only` (`CODEX_REVIEW_POLICY`, `worker_adapter_base.py:103`). Every reviewer prompt tells it to run the tests that import each changed module (`PROBE_RULES_LINES` rule 1, `specy_road/review_record_rules.py:28`). A Codex reviewer that cannot write pytest's temporary files then blocks a commit only because the tests did not run.

The third field defect, a chore reviewer inventing `A2`, `A3` and so on, is deferred to M23 (maintainer decision): its fix is in `chore_cli.py`, which M16.2.3 claims, and moving it out frees this leaf from that dependency.

## Approach

- **D1, rca on stdin.** The bundled profiles' `access.cli` is rendered from `harness-facts.yaml`'s `executor_template` for the harness whose `renders_cli_for` names the profile's family (`specy_road/harness_facts.py:103-109`). Change the `codex` record's `executor_template.value` from `... "<prompt>"` to `... - < {prompt}`, then run `specy-road refresh-profiles --render` to re-render the four OpenAI GPT profiles and the README harness block. `{prompt}` is the quoted file path (`substitute_prompt`, `worker_adapter_parsers.py:67`), and every path that runs `access.cli` goes through `sh -c` (`worker_adapter_base.py:198,287`; `role_prompt_cli.py:302`; `run_plain_cli`, `role_prompt_cli.py:390`), so the redirection works for `prompt --channel cli --run` and for generic-harness workers alike. No Python change is needed in `role_prompt.py` or `role_prompt_cli.py`.
- **D2, a test the sandbox cannot run.** `PROBE_RULES_LINES` rule 1 gains this sentence: "If the sandbox prevents a test from running, name the command and its error as not run in the notes; on an approve, include the existing 'not a defect because <reason>' explanation. Do not put the command in `commands_rerun`; the absence of that run alone is no block." The approve case needs the explanation because `NOTES_RULES_LINES` and `approve_defect_problem` refuse an approve whose notes carry an unexplained observation; without it a compliant reviewer loops on repairs. A test that runs and fails is still a failure, not a not-run.
- **What the sentence does not change.** It is prompt text only. Nothing in `review record` or the gate reads it. Under `policy.reviewer_reruns_required` an approve with no `commands_rerun` is still refused at filing (`rerun_problem`, `review_rejected.py:186-187`; `review_gate.py:205-215`); a block still blocks; a non-empty `commands_rerun` still meets the policy. A read-only Codex reviewer that can run nothing at all still cannot approve under that policy. Keeping the not-run test out of `commands_rerun` is what stops the policy being met by a command that never ran.

## Tier

trust boundary: it changes a reviewer's prompt and the command the bundled profiles launch.

## Done but wrong

- A not-run test counts as a rerun: the reviewer-rule row checks the sentence sends it to the notes, and the not-run-no-rerun row checks filing still refuses it.
- The sentence is read as loosening the rerun policy: the not-run-no-rerun row.
- The profile files are hand-edited instead of rendered: the rendered row fails on drift.
- Only `gpt-6.1-terra` is fixed: all four profiles share the rendered template.
- The size check is loosened instead of the command fixed: `oversized_arg` and its tests are unchanged.

## If this fails

Assumption: `codex exec ... -` reads the whole prompt from stdin under the same flags as the profile command (the codex adapter already launches that way). If the captured codex build refuses `-` with these flags, stop and report the error; the coordinator decides before any file outside the zones changes.

## Accepted limits

- A reviewer that ignores the sentence can still block, or can still list the test under `commands_rerun`. No gate check is added.
- A Codex reviewer still cannot run tests that write files, and under `reviewer_reruns_required` one that can run nothing cannot approve. A writable temp root for Codex reviewers is M23 intake.
- Profiles whose harness reads the prompt only as an argument keep `"<prompt>"`, and an rca prompt over 128 KiB on them is still refused with today's message. That includes the Claude, Gemini, Grok and Copilot profiles. Whether `claude -p` with no prompt argument reads stdin under the profile flags was not checked here; it is a candidate for the same change (M23 intake).
- Adopters' own copies of the OpenAI profiles change on their next `specy-road upgrade` (`refresh-profiles`), as any re-rendered profile does.
- The chore reviewer's `A1`-only sentence is M23 intake.
