## Intent

rc4 final review (§3.2, 2026-11-06), the prior-F2 class on publish, finish and pickup. This leaf moves those writers onto the M21.37 rule (`specy_road/safe_write.py`).

- **Publish.** GUI Publish regenerates through an in-repo symlink (`roadmap.md` -> `payload.md`). It truncates the target, then stages or pushes it. Finish refuses that layout as `irregular_destination`.
- **Land helper.** `finish_land_deterministic` uses the outward-only check and then `write_text`.
- **Finish reviews base.** Finish's preflight never inspects the reviews base itself. With `work/reviews` linked outside, the untracked-summary copy lands there.
- **Pickup hint.** The pickup hint follows a symlinked `.specyrd/cache`, or a dangling marker link, with no prompt.

Decisions:

- **Publish and land use the rule.** After M21.37, `refused_generated_files` refuses any link, so Publish and the land helper refuse an in-repo link with the same wording as finish's `irregular_destination`. The land helper also writes through `safe_write`, so a later caller that skips finish's preflight still cannot write through a link.
- **The reviews base is walked from the checkout.** `write_destinations` names the summary copy from the owning main checkout's project root (`work/reviews/<node>/<summary>`), not from `reviews_root`. `irregular_destination` then walks `work` and `work/reviews` too, and it becomes a thin wrapper over `safe_write`'s walk.
- **One cache-dir fix.** `ensure_cache_dir` is the one place the cache directory is made. It refuses a symlinked `.specyrd` or `.specyrd/cache` (root = `cache_dir.parents[1]`). Its other callers (search_index, context_notice_cache, brainstorm_session) inherit this through their existing `OSError` handling. The brainstorm lock opens with `safe_write.open_lock`.
- **The pickup hint is best effort.** The marker is inspected with `lstat`, not `is_file()`: a symlink at the marker name (live or dangling, to anywhere) is a refusal, never "already shown". A refused marker prints one warning line; pickup still exits 0 and claims as before, and the link's target is unchanged.
- **Brainstorm lock refusals stay brainstorm errors.** `session_lock` converts `SafeWriteError` into `BrainstormError` with the same message, so its callers (brainstorm_cli.py, brainstorm_cli_v2.py, gui_app_routes_brainstorm.py), which already print or return a `BrainstormError`, report it with no traceback and no change of their own.

Out of scope: index, mode and unlink-before-write in finish rollback (M22.20).
