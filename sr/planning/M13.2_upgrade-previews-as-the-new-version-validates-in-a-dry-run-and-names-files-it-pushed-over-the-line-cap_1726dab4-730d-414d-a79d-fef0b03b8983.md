## Intent

Make `specy-road upgrade` say up front what is doing the upgrading, and let `--dry-run` catch everything a real run would: today a dry run under the old version previews the old version's writes without saying so, returns before `validate` (so a breaking validate error appears only after every refresh is written), and the real run can push a project file over its file-limits cap without saying so.

## Approach

- **Header.** At the start of `run_upgrade()` in `specy_road/bundled_scripts/upgrade.py`, print the running version, `sys.prefix`, and the launcher list from M13.1's `launchers_on_path()`. Under `--dry-run` the first line is `previewing what specy-road <version> would write`.
- **Dry-run validate.** Today `run_upgrade()` returns right after `_refresh()` when `dry_run` is set. Instead, copy the project tree (tracked files plus the managed-block files, excluding `work/` and `.git`) into a `tempfile.TemporaryDirectory`, run `_refresh(..., dry_run=False)` against the copy, then `validate_at()` on it, and exit with validate's code. Model the copy on `_block_previews()` in `refresh_stubs.py`, which already builds managed blocks under a temp dir. If validate needs git (history/registry), `git init` the copy with one commit; keep the checkout untouched (test asserts its `git status --porcelain` is unchanged).
- **File limits on own writes.** Before writing, record line counts (`line_count()` in `specy_road/file_limits_engine.py`) of every file the refresh will touch; after writing, load the project's `constraints/file-limits.yaml` the way `validate_file_limits.py` does, and for each written file now over its cap that was not over before, print path, old → new lines, cap. A file already over the cap is reported as "already over" at most once, not blamed.
- **Digest wording.** Replace "a new version's digest often differs" with a pointer to validate's notices (held milestones from M13.4 appear there) and the `specy-road digest` command.
- **Init template.** In `specy_road/templates/project/constraints/file-limits.yaml`, leave root `AGENTS.md` and `CLAUDE.md` out of the default globs and add a commented example of opting them in (specy-road budgets only its managed blocks and `.specyrd/` files; root agent files are developer-owned). This repo's own `constraints/file-limits.yaml` is untouched.
- **Other worktrees.** After writing, run `git worktree list --porcelain` (as `doctor._worktrees()` does) and, for each worktree other than this one, print path and branch, one line saying it was not upgraded and still has the old managed files while it runs the shared install, and the command to run there (`specy-road upgrade` from that worktree). With one worktree, print nothing.
- **Help text.** Module docstring and `--help` mention `pip install -U`, `pipx upgrade specy-road` and `uv tool upgrade specy-road`.
- **Verify.** Tests under `tests/` (extend the existing upgrade tests): dry-run header text; dry run exits 1 on an injected validate error and writes nothing; a refresh that grows a capped file is named, a pre-existing overage is not blamed.

## Tasks / checklist

- [ ] A1 — Header names version, `sys.prefix`, launchers; dry run's first line is "previewing what specy-road <version> would write".
- [ ] A2 — `--dry-run` validates a temp copy with refreshes applied and exits with validate's code; checkout untouched (test).
- [ ] A3 — After writing, files pushed over their cap by the upgrade are named with counts and cap; pre-existing overages are not blamed (tests).
- [ ] A4 — A freshly initialised project's file-limits does not cap root `AGENTS.md` / `CLAUDE.md`; commented opt-in example present (test).
- [ ] A5 — Help/docstring cover pip, pipx, uv tool.
- [ ] A6 — Other worktrees listed as not upgraded, with the command to run there; nothing with one worktree (test with a linked worktree).
- Out of scope: which refreshes run or their order; digest wording beyond pointing at validate; this repo's own file-limits.
