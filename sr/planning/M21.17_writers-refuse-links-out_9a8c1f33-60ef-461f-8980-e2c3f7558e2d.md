## Intent

One rule for every specy-road writer: never write through a symlink that leads out of the directory the writer owns. Today four writers break it.

- Release blocker F2. `init project` regenerates `roadmap.md` and `roadmap-context.md` (init_project.py:202, `_write_generated`). It checks only `Path.exists()`, which is false for a dangling link, and then `write_text` (generated_files.py:110, export_roadmap_md.py:154) follows the link and creates its target outside the repository. With `--force`, an existing outside target is overwritten.
- Review W3. `write_rejected` (review_rejected.py:39) and `ensure_packet` (review_delegate_packet.py:41) use `Path.write_text` in the hand-off directory, so a symlink at `REJECTED-<model>.md` or `PACKET.md` sends the write to its target.

The other writers (`managed_block._write`, `refresh_stubs._write_if_changed`, `upgrade_templates`, `agents_md_block`, `specyrd_skills`) already refuse through `managed_block.resolves_outside(root, path)`. Its docstring says "a link out of the checkout points at someone else's file". This leaf applies the same helper to the four writers above, with the root each one owns.

Out of scope: the reviewer tripwire's own symlink handling (`replace_file`, `append_log`); `write_review`; `write_marker` (M21.18 owns review_deferral.py); upgrade's own regeneration (M21.16 checks `resolves_outside` itself); in-repo links, which stay followed as the managed-block writers follow them (for example `CLAUDE.md` → `AGENTS.md`).

Overlaps checked (2026-11-05): M22.8 (rc5, init next steps) also edits specy_road/init_project.py and lands after rc4. M21.16 calls `resolves_outside` directly and does not edit generated_files.py. M21.20 (GUI Publish) calls `regenerate_generated_files` and gets this guard for free. Neither edits the helper.

## Approach

- One guard next to `resolves_outside` in managed_block.py: `refused_link(root, path, *, any_link=False) -> str | None`. It returns the one-line reason (the existing `REFUSED` text plus the path) when `resolves_outside(root, path)`, or, with `any_link=True`, when `path` is a symlink at all. Otherwise it returns `None`. A dangling link out of `root` is refused, as `resolves_outside` already defines. `any_link` exists for the hand-off directory, where the tripwire already treats every symlink as a failure, so a link to a sibling record (`REJECTED-x.md` → `REVIEW-y.md`) must not be followed either.
- `generated_files.regenerate_generated_files(root)`: check both names with the guard before writing either. A refused name is not written: print the reason on stderr and return the refused names. Callers that ignore the return value (archive, GUI archive routes, finish) keep working, and a link out is no longer followed.
- `init_project._write_generated`: count a path as present when `os.path.lexists`, so a dangling link is skipped without `--force` like any existing file. With `--force`, a refused name is reported on the init's skipped list with the reason, and nothing is written through it.
- `write_rejected`: guard with root = the reviews directory and `any_link=True`. When refused, print the reason on stderr and write nothing. The refusal it records still returns its own error and exit code.
- `ensure_packet`: guard with root = the reviews directory and `any_link=True`. When refused, raise the same setup error `review delegate` already reports. Nothing is launched and no `RUN-<model>.json` is written.
- One table-driven test file covers each writer (init without and with `--force`, `regenerate_generated_files`, `write_rejected`, `ensure_packet`) against four layouts: a regular file, a dangling link out of the root, a link to an existing file outside the root, and a link inside the root. Expectations: a regular file is written. Links out are refused: the link is unchanged, and the outside target is neither created nor changed (bytes compared). A link inside is followed by init and `regenerate_generated_files`, which write its in-root target, and refused by the two hand-off writers, which leave the target's bytes unchanged.
