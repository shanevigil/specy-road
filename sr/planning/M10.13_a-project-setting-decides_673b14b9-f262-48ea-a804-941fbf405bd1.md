## Intent

PM-requested, default off: worker logs get very long. Teams that want a leaf's run history to travel with the code can opt in per project to mirroring the event log (or the raw output too) into a tracked path that finish commits with the leaf; everyone else keeps a clean repository and `work/.workers/` stays gitignored.

## Approach

Add `track_worker_logs` to the git-workflow schema and `specy_road/git_workflow_config.py` (377 lines, cap 400: one accessor). In `worker_runner.py`, after each `append_event` (events) or each raw line (full), append the same line to `work/worker-logs/<NODE_ID>/<worker>.events.jsonl` or `.log`. `finish_work_artifacts.py` stages that directory when the mode is on and never deletes it. `agent_ignores.py` keeps the ignore list as is. Docs: `docs/git-workflow.md`, `docs/orchestration-workers.md`, the work README. Verify with `pytest tests/test_worker_state.py tests/test_finish_work_cleanup.py tests/test_agent_ignores.py`.

Converge verdict (brainstorm `agentic-performance`): PM-requested; resolves the open decision on B29 and B47 by making it a per-project setting with a conservative default. Docs: install-and-usage.md or git-workflow.md config keys, orchestration-workers.md 'Records live in work/.workers/ (gitignored)' sentence, archiving.md if logs are archived with the leaf.
PM decision 2026-10-30: default off; opting in is per project.
