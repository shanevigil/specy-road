## Intent

M16.5.5 reads both roster forms; this leaf moves every roster to the new one, so the version-1 reader can go when the alias window closes (M16.8.3). Kestra's 2.0 is the failure mode to avoid: configs that stopped parsing after an upgrade with no migration.

## Approach

- `upgrade` does the rewrite, as it does for the `checks:` block (M16.4.5) and the grind keys (M16.5.11), and reports it in the one upgrade report (M16.4.2).
- The expected output is pinned by files, not prose: the before files are the toolkit's own roster as of pickup and a 0.3.1-shaped sample, and the after files are M16.5.5's hand-written version-2 equivalents, adjusted here only for comment placement.
- Comments carry vendor quirks in the toolkit's roster, so none may be lost; the fixtures pin where each one lands.
- The toolkit's live `sr/roadmap/orchestration.yaml` is read by the running coordinator, so this leaf does not rewrite it; the maintainer runs `upgrade` on it after merge.
- Depends on: M16.5.5. The last acceptance line is an informational line-change estimate, not a gate; report `scripts/lean_metrics.py --check` deltas in READY once M16.1.7 has landed.
- Behaviour-preserving: the parity harness (M16.1.1) and the review-gate decision table (M16.1.2) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines.

## Tier

behavioural: it rewrites every roster and must keep comments with only PyYAML available; matching committed after-files proves little if those files came from the new code.

## Done but wrong

- The after-files were generated, not hand-written: they differ from M16.5.5's committed version-2 equivalents only in comment placement.
- The local file's patches change: in a local file with `roster:` patches and `roster_add` entries, the patches are byte-identical after upgrade.
- An unsupported shape is half-rewritten: a file using a shape outside the committed table (for example an anchor or a flow-style entry) is reported and left byte-identical.

## If this fails

Most likely to break: a line-level rewrite covers the shapes in the toolkit's own roster. PyYAML drops comments, and no comment-keeping YAML library is a dependency. If it does not, narrow the supported shapes and report the rest; the maintainer decides whether to add a dependency, which needs supply-chain approval.
