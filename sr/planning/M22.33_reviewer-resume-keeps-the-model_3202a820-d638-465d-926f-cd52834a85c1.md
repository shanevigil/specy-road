## Intent

A review's format-repair retry resumes the harness session. On Codex, `reviewer_launch`'s resume branch leaves out the `-m` flag that the fresh turn and the worker resume both pass, so the retry runs on the configured default model while the verdict is filed under the requested id. With no reported model the record only warns and still counts, so a verdict can sit under the wrong model and family. Found in a real review run and confirmed in the code.

## Approach

Pass the requested model on the reviewer resume, matching the fresh turn. Read the Claude Code and Cursor reviewer paths and confirm they do the same; Cursor already does. This leaf does not change how the gate treats an unreported model: that is a separate decision.
