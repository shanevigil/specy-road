## Intent

Stop `refresh-profiles` (and `upgrade`, which calls it) from writing every bundled model profile into a project that rosters none of those vendors, and turn the follow-on "matches no model profile" warnings into a fix. In the report, 21 profile files appeared in a repo with no `model-profiles/`, and validate then printed three warnings where the roster id differed from the bundled `api_id` only by punctuation or a vendor/effort affix.

## Approach

- **Roster filter.** In `refresh_profiles()` (`specy_road/bundled_scripts/refresh_profiles.py`) add `profiles: str = "roster"` (`roster` | `all`). For `roster`, read roster entries from `roadmap/orchestration.yaml` (via the config loader `model_profiles.py` already uses) and keep only bundled files whose `api_id` / file token a roster entry names (directly or via `profile:`), plus `model-profiles/README.md`. Reuse `index_bundled_profile_names()` from `specy_road/init_project.py` (already used for `--only`). Add `--profiles roster|all` to the parser; `upgrade.py` keeps calling `refresh_profiles(project, dry_run=…)` and so gets the roster default without edits. No roster → README only, plus one line naming `--profiles all`.
- **Near-miss alias.** Where `specy_road/model_profiles.py` builds the "roster entry … matches no model profile" warning, compute the closest bundled `api_id` after normalising (lower-case; `.`, `_` → `-`; strip a leading harness/vendor token such as `cursor-` and a trailing effort token such as `-high`/`-medium`/`-low`). On a unique match print the roster line that fixes it (`profile: <api_id>`); otherwise keep the current text.
- **Verify.** Tests under `tests/`: roster with one Claude entry → only that profile + README; no roster → README only; `--profiles all` → today's set; warnings for `claude-opus-5.5` → `claude-opus-5-5` and `cursor-gpt-5.6-sol-high` → `gpt-5.6-sol` name the fix; an unrelated id keeps today's text.

## Tasks / checklist

- [ ] A1 — Default writes roster-named profiles + README only; `--profiles all` restores today's behaviour; no roster → README and a hint. Tests for all three.
- [ ] A2 — "matches no model profile" names the near-miss `api_id` and the roster line to add for the two cited shapes; no near match keeps today's text. Tests.
- [ ] A3 — Out of scope: editing the roster automatically, deleting profiles already written, changing profile content.
