## Done but wrong

- The contract test only sees a near-empty response, and a missing response field passes because the check runs one way. Check: on the row with a claim, a running worker and a READY, the response contains every required key path, and dropping one field from the builder's output fails the test.

## If this fails

The assumption most likely to break is that one root resolution gives the main worktree's state for a linked worktree and the nested project for a nested root, both at once. If the folded gui_app resolves them differently, the coordinator decides which helper the route uses.

## Accepted limits

- Under `--read-only`, `POST /api/orchestration` gets 403 from the existing guard, which refuses every non-GET `/api/` request; the row does not show that the route itself refuses writes.
