## Intent

rc4 roadmap-tooling fix (maintainer 2026-11-05), filed in M16's fix intake. A move rewrites ids in chunks, sheet file names, registry claims and touch-zone segments (`_rewrite_touch_zones`), but never in prose: planning sheets and acceptance text keep citing old ids, which now name other nodes. The regroup scratch run left about 950 stale mentions.

Evidence: regrouping M16 into sub-milestones using only specy-road commands (scratch run, 2026-11-05) took about 85 commands, a temporary holder node and about 100 s, and left about 950 stale id mentions in prose. Earlier related fix: M16.67 (move-node renumbers only the moved subtree; whole-outline renumber became explicit).

## Approach

- One rewriter (planning_rename.py) taking an old -> new id map applied simultaneously (swaps and chains safe), matching whole ids only: not preceded by an id character, not followed by a digit or by `.` plus digit, so M16.1 never matches M16.10 or M16.1.2.
- Scope: planning sheets of live nodes and node `title`/`acceptance` text. Skips fenced code blocks and text between `<!-- historical -->` and `<!-- /historical -->`.
- Standalone `rename-refs <id-map.json> [--dry-run]`; opt-in `--rewrite-refs` on move-node, group-nodes, indent and outdent feeding the move's own map into the same transaction. GUI: optional `rewrite_refs` (default false) on move/indent/outdent/group requests.
