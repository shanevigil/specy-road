## Intent

In the clean-VM rc4 rehearsal (sr/work/sandbox-feedback/2026-11-05-rc4-trial-1da375e1.md, finding 4) a pip-installed user read help text written for a source checkout: `specy-road --help` says `see: python specy_road/bundled_scripts/roadmap_crud.py add-node -h` and `see specy_road/bundled_scripts/scaffold_planning.py -h`; every bundled subcommand's `usage:` line names its module file (`usage: roadmap_crud.py add-node ...`, `usage: validate_roadmap.py ...`) because `_run` starts them with `python -m` and argparse takes `prog` from `sys.argv[0]`; help cites `docs/orchestration-workers.md`, `docs/orchestration-chores.md`, `docs/roadmap-authoring.md` and `docs/git-workflow.md`, which a pip install lacks; and the `gui` line says `init --install-gui`, which the init parser rejects (it requires `init gui --install-gui`). After this leaf, help names only commands that exist on an installed system.

Canonical GUI install: `specy-road init gui --install-gui` (the only form the parser accepts, and the one docs/pm-workflow.md and docs/contributor-guide.md use). `pip install 'specy-road[gui-next]'` stays as the plain-pip alternative; no command or flag is removed.

Out of scope: rewording help beyond these references, the `specyrd` CLI, module docstrings that are not shown as help, renaming commands, and the docs themselves.

## Approach

1. cli_usage.py: `add-node ... — see: specy-road add-node -h`; scaffold-planning `see specy-road scaffold-planning -h`; gui line `(after: specy-road init gui --install-gui, or pip install 'specy-road[gui-next]')`. Pass `USAGE_TEXT` through `doc_links.link_toolkit_docs` when printed in `cli.main` (one call), so the two `docs/...md` citations become versioned URLs.
2. cli._run: start the child so argparse sees `specy-road <cmd>` as its program name, for every bundled entrypoint at once, for example `[sys.executable, "-c", "import runpy, sys; sys.argv[0] = ...; runpy.run_module(module, run_name='__main__')", *args]`, with `specy-road` for CRUD/archive/forwarded commands (their subparser adds the command name) and `specy-road <cmd>` for `_SCRIPTS`. Keep the existing exit-code handling. Check that scripts setting `prog=` explicitly are unaffected.
3. roadmap_crud_argparse.py (`apply` description) and do_next_task_args.py (`--on-complete` help): wrap the text in `link_toolkit_docs`, or drop the reference if the import is awkward.
4. tests/test_cli_help_text.py: for `--help` and each name in the public `registered_agent_command_names()["specy-road"]` except `version` with `-h` (`orchestration guard -h` for orchestration; each row exits 0 and its usage line starts with `usage: specy-road`) (run via the console entry or `sys.executable -m specy_road.cli` in a tmp cwd, in parallel-safe form), assert no `bundled_scripts/`, no `usage:` line or `python ...` line naming a `*.py` file (a prose mention such as `conftest.py` in impact's help is allowed), and no bare `docs/<name>.md` outside `SHIPPED_DOCS`. `init` with `-h` and `gui -h` included. Top-level help also must contain the canonical gui and `<cmd> -h` lines and must not contain `specy-road init --install-gui`.

Verify: the new test, `pytest tests/test_cli_*.py`, `specy-road file-limits`, then `specy-road add-node -h | head -1` shows `usage: specy-road add-node`.
