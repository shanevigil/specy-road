## Intent

Two worker-launch warnings from the rc4 checks, deferred to rc5 by the maintainer.

- Workers W1 (grok and sol). `merge_local_roster` (roster_local.py:78-84) refuses a local `roster_add` entry in the gitignored `roadmap/orchestration.local.yaml` that sets `channels.cli` or a profile `access.cli`, unless `allow_local_cli: true`. Three other fields also choose what runs on this clone and pass without the flag:
  - `preflight`, run with `shell=True` before launch and resume (worker_ops_launch.py:163-168);
  - `channels.cli_resume`, run by message and resume (worker_ops_message.py:82, worker_ops_launch.py:181);
  - `harness_bin`, used as argv[0] of the default command (harness_binary.py:29-38).
- Workers W2 (grok). Codex `reviewer_launch` (worker_adapter_codex.py:76-88) passes neither `CODEX_MEMORY_OFF` nor an isolated `CODEX_HOME`, which a worker launch passes (:59-61), so the reviewer runs with the user's own Codex home, memories and global config. A resumed reviewer turn also drops `-m`, which worker `resume` keeps (:72-73).

Out of scope: committed roster entries (the integration branch is trusted); the meaning of `allow_local_cli`; Claude and Cursor reviewer launches; the read-only policy itself (`CODEX_REVIEW_POLICY`).

Overlaps checked (2026-11-05): M21.21 (rc4) changes how `review delegate` validates a reviewer command in review_delegate_harness.py; it does not touch the Codex adapter. M21.22 (rc4) edits only worker_adapters.py's docstring. M22.6 touches worker_ops_message.py's queued delivery, not roster merging.

## Approach

- `merge_local_roster`: treat a non-empty `preflight`, `channels.cli_resume` and `harness_bin` on a local entry like `channels.cli`. Without `allow_local_cli: true` the entry is refused with the same message shape, naming the field. Parametrize tests/test_roster_worktree_dry_run.py's refusal test (:170) with the three fields, and keep its positive opt-in case.
- Codex `reviewer_launch`: add `*CODEX_MEMORY_OFF` to both argv shapes. Pass `env={"CODEX_HOME": str(profile_home(model))}` on a fresh turn, and the session's home (`session_home(id)`, falling back to `profile_home(model)`) on resume, as worker launch and resume do. Pass `-m` on resume. Assert both argv shapes and the env in tests/test_harness_launch.py.
- docs/orchestration-roster.md's local-roster paragraph (:51, :65) lists the fields that need `allow_local_cli`. docs/orchestration-reviewer-output.md's Codex reviewer line names the isolated home and memory-off.
