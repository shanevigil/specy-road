## Tier

behavioural: removing handlers moves where errors stop, and a handler that matches the pattern can be doing more than printing and exiting.

## Done but wrong

- A warning becomes a failure. `nested_repos.announce_nested_worktrees` catches `NestedRepoError`, prints a warning and continues, after the claim is pushed. Check: pickup with a nested repo that cannot be checked out still prints the warning and exits 0.
- A site-specific message is lost. `review_policy_pin.cmd_accept_policy` adds "; nothing was written" and also catches `PolicyUnreadable`, which is not one of the 15 classes. Check: accept-policy's stderr and exit code are byte-identical for both errors.

## If this fails

The assumption most likely to break is that each class prints one prefix and exit code everywhere. The two sites above do not. Acceptance requires every matched site to be removed, so the maintainer decides whether they stay.

## Coordinator resolution (2026-11-07)

Line 3 (byte-identical output) wins. Sites whose removal would change output, such as `nested_repos.py` 230-236 and `review_policy_pin.py` 414, stay as named exceptions, and the stderr prefix is recorded per site.
