## Intent

`file-limits` went from passing to 183 failures with no code change because TS/JS function measurement arrived after rc1, and `upgrade` said nothing. `override_limits` is hard to find, and a project adopting a new measurement needs a baseline that keeps new files at the default caps.

## Approach

- New `specy_road/file_limits_baseline.py`: compute failing files from the engine's results, bucket by worst file length (round up to 50) and worst function length (round up to 20), and append `override_limits` entries to the YAML preserving comments (append text rather than re-dumping). `--write-baseline` and `--dry-run` in `validate_file_limits.py`.
- Pointer line at the end of a failing run.
- `upgrade.py` final step runs file-limits and reports the count (depends on M13.2, which changes `upgrade.py` and the engine). `file_limits_engine.py` is at 379: put new logic in the baseline module.
- Docs: `docs/file-limits.md`.

## Tasks / checklist

- [ ] A1 — `--write-baseline` buckets, keeps comments, idempotent.
- [ ] A2 — Pointer line on failure only.
- [ ] A3 — upgrade reports the count; never fails on it. Out of scope: M13.2's own-writes case; release notes.
