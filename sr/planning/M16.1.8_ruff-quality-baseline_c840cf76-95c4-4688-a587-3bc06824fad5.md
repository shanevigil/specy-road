## Intent

The toolkit's cap went from 400 to 1,000 lines on 2026-11-05. Lines over 100 characters went from 78 to 3,068 because width was the way around the old cap; the width rule closes that before the folds start. The consumer template still says 400.

Split (2026-11-06): this leaf had ten acceptance lines. It keeps the 100-character width baseline, the consumer file-limit default and the upgrade notice; the ruff quality rule families (revision 3) moved to M16.1.11, which depends on this leaf. Every original acceptance line is in one of the two.

## Approach

- Do not touch project.version.
- Revision 1: the baseline counts long lines per file instead of listing files, so a listed file cannot gain more (Sol 19); the decision is an acceptance line (Grok 16). Revision 2: the maintainer decided 1,000 lines with a 750 warning, the toolkit's own values; upgrade only reports the new default and never rewrites a project's file.
- The fold leaves lower the width entries of files they merge; a recorded move transfers a file's count to its new path.
- Depends on: M16.1.7. The last acceptance line is an informational line-change estimate, not a gate; report `scripts/lean_metrics.py --check` deltas in READY once M16.1.7 has landed.
- Behaviour-preserving: the parity harness (M16.1.1) and the review-gate decision table (M16.1.2) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines.
