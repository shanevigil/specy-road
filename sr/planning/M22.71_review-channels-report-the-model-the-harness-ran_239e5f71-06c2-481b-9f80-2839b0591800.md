## Intent

Review records are meant to name the model the harness actually ran (M15.3: `review_model_check`, `file_review` writes `harness_model`), so reviewer independence can be checked against what ran, not only what was requested. In practice only 31 of 859 recorded reviews carry it. The Codex reviewer wrapper passes back only the final JSON message, so the record falls back to "the harness reported no model". A model upgrade or a saved-setting migration could change what ran without the record showing it (agent-CLI briefing, 2026-11-16).

Out of scope: changing what counts as distinct families, and making an unreported model block a review.

## Approach

- Pre-pickup (planner): find where each bundled channel's output reaches `stream_lines` and `check_run` (Codex: the wrapper's final-message-only output and its side transcript; Cursor and Claude: their stream events), then set the exact touch zones.
- Have each channel surface the harness's reported model without changing the review answer format.
- One test per channel from a captured output, each failing on the current code.
