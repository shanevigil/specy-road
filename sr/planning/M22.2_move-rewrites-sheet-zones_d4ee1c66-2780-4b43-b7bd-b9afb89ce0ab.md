## Intent

A move renames planning sheets but `_rewrite_touch_zones` rewrites only path segments equal to an old id, so a zone naming the sheet itself <!-- historical -->(`sr/planning/M16.33_rc5-close-..._<key>.md`)<!-- /historical --> keeps the old file name <!-- historical -->(REHEARSAL.md B2: M16.20, M16.33, M16.70)<!-- /historical -->. validate is silent while the rename is unstaged and afterwards shows it only inside the general "zones that match no tracked file" notice. After this leaf the move rewrites those zones in the same transaction, and validate warns on any zone that names a planning sheet that is not there.

Out of scope: rewriting zones on nodes or claims outside the move's scope (a plain move still rewrites nothing outside the moved subtree; the new warning reports them), prose references (M21.3's --rewrite-refs), decisions.yaml (M22.3), and the general missing-zone notice for other paths.

## Approach

1. `stage_id_rewrite` already computes `sheet_moves = plan_planning_artifact_moves(scope)` (node_key, old planning_dir, new planning_dir). Build an old -> new path map from it in both forms: planning_dir as stored (`planning/<file>`) and with the checkout-relative project-root prefix (`sr/planning/<file>` when the project root is `sr/`; derive the prefix from the project root relative to the git root, as validate_touch_zones resolves "either root").
2. Apply that map to whole zones (exact equality, before or after the segment rewrite) on `scope` and in `_stage_registry_ids` on the claims it already touches. Keep it inside the same AtomicWritePlan so a refused move writes nothing.
3. validate_touch_zones: a zone whose path (either form) is directly under the planning dir and ends in `.md`, and which does not exist on disk, is a warning for every status; when its trailing `_<uuid>.md` is a live node_key, name that node's planning_dir as the likely fix. Working-tree existence, not `git ls-files`, so the unstaged case is caught.
4. Verify on a scratch worktree with the rehearsal's own-sheet zones (M16.1.6, M16.8.1, M16.8.8) moved, then `specy-road validate` with and without `git add`.
