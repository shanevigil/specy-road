## Tier

behavioural: the unknown-flag scan is new validate output, and the import-count gate depends on how the count is taken.

## Done but wrong

- The scan reports flags the CLI accepts. Options declared on a parent or the top-level parser (for example `--repo-root` on roadmap_crud's shared parser) are not on the subcommand's own parser. Check: a fixture line using a flag accepted that way is not reported.
- The halving is measured on a different count than the baseline. Check: the test counts the same set (`specy_road` modules or all of `sys.modules`) and runs the same command as M16.1.7's baseline.

## If this fails

The assumption most likely to break is that validate can reach half the baseline count with lazy imports in the CLI layer alone. If modules validate legitimately loads hold the rest, the coordinator decides how far to go. If the target cannot be reached without a behaviour change, the maintainer decides.

## Accepted limits

- Abbreviated long flags, which argparse accepts by prefix, are reported as unknown.
- Flags mentioned outside backtick or fenced spans are not checked.
