## Intent

Two adopters on Claude Code subscription logins could not run a Claude Code reviewer: without `channels.cli` the reviewer always runs `--bare`, which reads only `ANTHROPIC_API_KEY` or `apiKeyHelper`, so it fails "Not logged in" about four seconds after launch. Executors on the same roster entry work, so the gap shows only at the first review, and the workaround (a subagent plus `review record --launch-mode full`) leaves no RUN record. M8.3 keeps `--bare` and only prints a note from `prompt`.

## Approach

- New `specy_road/reviewer_auth.py`: `claude_reviewer_mode(env, user_settings) -> "bare" | "explicit"` and `auth_problem(mode, env, settings) -> str | None`. Bare only with a key or `apiKeyHelper`; else explicit: `--setting-sources user --strict-mcp-config` (no `--mcp-config`), which reads OAuth and still loads no project hooks, settings or MCP servers. Read the flags from `model-profiles/harness-captures/claude-code/help.txt` in the templates.
- `ClaudeCode.reviewer_launch` takes the mode; the argv keeps M8.3's `--disallowedTools`, `--json-schema` and `--add-dir`. `review delegate` and `role_prompt_cli.run_default_reviewer` call the same function; the RUN record's and REVIEW's `launch_mode` say which mode ran (`explicit` is already in `REVIEW_LAUNCH_MODES`). `review_delegate.py` is at 395 lines after M8.3: keep the logic in `reviewer_auth.py`.
- Forced bare without auth: refuse before opening a RUN record. `orchestrate plan`: one `reviewer auth:` notice per such entry.
- Docs: `docs/orchestration-models.md` next to `billing_route`; `docs/orchestration-reviewer-output.md` for the modes.
- Tests: argv per mode; never bare without a key; refusal before launch; the key never printed.
