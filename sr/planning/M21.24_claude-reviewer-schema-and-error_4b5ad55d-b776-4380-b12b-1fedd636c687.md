## Intent

Defect D1 (High) from the rc4 real-harness checks (pre-release evidence 2026-11-05, ToDo app and runbook §2): `review delegate --model <claude-code entry>` always fails on Claude Code 2.1.318. The CLI printed `harness exited 1: no error text; rerun requested: the final message is not one complete JSON object`, and `RUN-<model>.log` held `Error: --json-schema is not a valid JSON Schema: no schema with key or ref "https://json-schema.org/draft/2020-12/schema"`. Run directly, `claude -p … --json-schema "$(cat review-output.schema.json)"` failed the same way. With the top-level `$schema` removed, Claude Code accepted the same schema. So no Claude Code reviewer can run through `review delegate`, the grind pre-finish recipes or `chore … --review`. The captures in the docs were verified on 2.1.312.

There is a second fault. When a turn has no parsed error event, the failure reason says "no error text", even though the run log has the harness's error line.

Fix: the Claude Code reviewer launch sends the schema inline without `$schema`. A failed turn's reason quotes the last non-blank log line when there is no parsed error.

Out of scope: the Codex `--output-schema` file and agy's `--json-schema <file>` (the file keeps `$schema`); Cursor (M21.25); reviewer-command validation (M21.21). The Claude executor path passes no schema: `ClaudeCode.reviewer_launch` is the only place that sends `--json-schema` for claude-code (worker_adapter_claude.py:85). A test states this.

Overlaps checked (2026-11-05): M21.21 edits review_delegate_harness.py and tests/test_review_delegate.py, not these files. M21.22 changes only the docstring of worker_adapters.py. M21.25 also edits docs/orchestration-reviewer-output.md (another row), and M21.26 and M21.27 also edit review_delegate.py (other functions), so land them one after another. M22.5 (rc5) lists worker_adapter_claude.py.

## Approach

- `ClaudeCode.reviewer_launch`: load the schema file, drop the top-level `$schema` key and `json.dumps` the rest. Nested keys and order are unchanged. `write_schema` keeps writing `$schema` to the file.
- `review_delegate._attempts`: when `failed` and `said` is empty, take the reason from `harness_error_line(exit_code=…, errors=[], tail=turn["tail"])` (reviewer_run_failure.py:87). Check that `delegate_turn`'s `tail` includes the stderr lines the log records. If it does not, read the last non-blank line of the turn's log span. Keep the 200-character cut, and fill `attempts[].error` from the same text.
- Tests in a new file, so as not to touch M21.21's tests/test_review_delegate.py.
