## Intent

rc4 fix (maintainer decision 2026-11-05: steering-file protection is an rc4 fix), filed in M16's fix intake as a dependency of gate M16.66. specy-road runs unattended executors in linked git worktrees, and some files they can write are later read or run by trusted code outside the executor: the coordinator's harness, git, the coordinator's shell, the toolkit's own gate. Today nothing notices a change to them. The post-run check (worker_turn_check.py) compares HEAD, branch, stash and porcelain only, and finish checks that work landed inside the zones, not what it touched outside them.

Evidence:

- sr/docs/research/agent-safety-posture-2026-11-05-claude-research.md, Executive summary item 3 "Protect the steering files" and Disagreements item 2 ("the toolkit is itself in the attack path"). It describes the CVE class where an agent writes a file that trusted code later runs: harness settings and hooks, git hooks and `core.fsmonitor` / `core.hooksPath`, shell startup files, virtualenv interpreters, and symlinks the unsandboxed parent follows.
- The 2026-11-04 context-regression replay (docs/design-notes/context-regressions-2026-11-04-triage.md, CR1 / cursor; docs/orchestration-review.md "What the gate cannot stop"). An executor added itself to `roadmap/orchestration.yaml` on the integration branch and approved its own work. Another called the toolkit's record writer from `python -c`. A third drove the human menu with `expect`.

Found in the code (2026-11-05):

- In a linked worktree, `.git/hooks` and `.git/config` are the common git dir's. An executor that writes them changes the coordinator checkout's git.
- `env_setup.link` (worktree_env.py) symlinks `.venv`, `.conda` and `node_modules` from the main checkout into the worktree. A write through `.venv/bin/python` changes the coordinator's interpreter.
- Claude Code executors in `launch_mode: full` load the worktree's project `.claude/settings.json`, hooks included, on the next turn.
- Codex runs `workspace-write` with `approval_policy=never`. Cursor runs `--force`.
- The only existing protection: Cursor's built-in write block on `.cursor/*.json`, `.vscode/**` and `.git/hooks/**` (maintainer, harness behavior). It is not written down anywhere in the repo yet.

## Approach

- **One list** in a new `specy_road/steering_paths.py`, documented in docs/orchestration-workers.md. For each worker it resolves the paths below in the worktree and in the main checkout:
  - harness config and hooks: `.claude/settings*.json`, `.claude/hooks/**`, `.codex/**`, `.cursor/*.json`, `.cursor/hooks/**`;
  - git steering: the hooks directories (common git dir, the worktree's gitdir, and any `core.hooksPath` target), plus the values of `core.hooksPath`, `core.fsmonitor`, `core.sshCommand`, `include.path` and `includeIf.*.path` in the common and per-worktree config;
  - the toolkit's policy and record inputs: `roadmap/orchestration.yaml`, `roadmap/orchestration.local.yaml` and `roadmap/git-workflow.yaml` (whose commands finish and worktree setup run). Each one counts in the working tree and as the blob at the integration branch tip, so a roster commit made from another checkout shows. Also registry entries other than the leaf's own, and every file under `work/reviews/` except the leaf's own READY;
  - shell and env: shell startup files at the worktree root (`.bashrc`, `.bash_profile`, `.profile`, `.zshrc`, `.zshenv`, `.envrc`), the `bin/` entries of each `env_setup.link` target, and any symlink made during the turn whose target leaves the worktree.
- **Before and after each turn:** `TurnWatch` records a digest of each path (or its link target, or "absent") before the harness starts. `close_turn` compares and adds `steering_file` findings, kept separate from the zone and porcelain findings. It also sets a sticky `steering_changed` flag that a clean turn does not clear; `worker reconcile` lists the changes again and clears it.
- **At finish:** `finish-this-task` refuses before its bookkeeping commit when the branch diff changes an in-tree steering path, unless a touch zone names that exact path. The message names the path and the next step.
- **At launch, where cheap:** Claude Code executors get `--disallowedTools` Edit/Write path rules. Paths the leaf's zones list exactly are exempt. Shell writes stay detection-only. Cursor's existing block and what Codex `workspace-write` already protects are written down, not duplicated. Custom `channels.cli` commands get detection only.
- **Out of scope:** OS-level isolation, signing, and the M20 posture model and doctor probes. Restoring a changed file is also out; this leaf detects and refuses.
