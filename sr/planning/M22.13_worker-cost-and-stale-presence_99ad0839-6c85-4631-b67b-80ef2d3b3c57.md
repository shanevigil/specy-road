## Intent

Two low worker defects from the rc4 real-harness checks (pre-release evidence 2026-11-05, runbook §5, calculator app).

- D8. The Codex worker's usage lines read `usage: in 316548 (295552 cached), out 2500, reasoning 57, $?`. Its roster `channels.cli` was `codex exec --json -m gpt-6.1-sol … - < {prompt}` (the documented git-roots form), and the docs say Codex cost is estimated from the profile for the launch's `-m`. A `channels.cli` runs as one shell command string, so `model_from_argv` (which reads `-m` / `--model` from argv items) finds no model, and no estimate is made.
- D9. Presence session `savigil-s1`, started by the Codex worker on `feature/rm-power-and-roots`, was still listed as live after `worker terminate`, `abort-task-pickup --force` and deletion of the branch. It would expire only after 4 h, and until then `handoff status` showed it and the session guard counted it as a live peer.

Fix: price a shell `channels.cli` from the `-m` inside its command string. A session stops counting as live once its worktree or branch is gone, and `worker terminate` ends the sessions recorded in that worker's worktree.

Out of scope: Codex's own cost reporting; sessions with no recorded worktree and branch (they still expire); the brainstorm agent's leftover session (it expires; no worker or leaf owns it); presence TTL.

Overlaps checked (2026-11-05): M22.6 edits worker_ops_lifecycle.py (the queued message in `_terminate_locked`) and docs/orchestration-workers.md, so land them one after another. M22.9 edits worker_adapter_codex.py, which this leaf does not touch. M21.23 (rc4) edits docs/orchestration-workers.md and lands first. M21.29 edits worker_process.py, not these files.

## Approach

- D8: `parse_events` (worker_adapter_base.py:226) reads the model with `worker_models.launch_model` instead of `model_from_argv`, so a shell `-c` launch (the form the runner builds for `channels.cli`) goes through `command_model`, which already refuses lists, pipelines and non-literal words. `apply_roster_price_estimate` then prices it as for a direct argv. `model_from_argv` is unchanged. The mismatch rule in `worker_models.usage_event` is unchanged.
- D9: `list_sessions(live_only=True)` (session_presence.py:134) leaves out a session whose recorded `worktree` is not a directory, or whose recorded `branch` has no `refs/heads/<branch>` in the repo. `session list --all` (session_cli.py `cmd_list`) still shows it, marked `stale: worktree gone` or `stale: branch gone` (worktree first when both). A non-string `worktree` or `branch`, or a git error on the ref check, keeps the session live. `_terminate_locked` calls `end_session` only for the live session in the worker's worktree whose agent is `<user>-s<pgid>` (the wrapper starts in its own session and the runner drops `SPECY_ROAD_AGENT_ID`), reading `pgid` before it is cleared.
