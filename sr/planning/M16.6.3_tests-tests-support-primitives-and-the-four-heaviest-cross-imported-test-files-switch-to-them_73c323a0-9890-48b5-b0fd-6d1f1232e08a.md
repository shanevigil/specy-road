## Intent

98 test files import helpers from other test files, a `repo` fixture is defined in 40 files, 53 helper groups are byte-identical, and 41 files hand-write manifest.json. Every later test stage depends on one fixture layer.

## Approach

- Revision 1: the test lane starts after the code lane (M16.5.14), so arc sets are compared on unchanged production code and no code leaf edits the same test files (Grok 2, Sol 14); support primitives come first, then migration in bounded batches (Sol 8).
- Depends on: M16.5.14. The last acceptance line is an informational line-change estimate, not a gate; report `scripts/lean_metrics.py --check` deltas in READY once M16.1.7 has landed.
- Behaviour-preserving: the parity harness (M16.1.1) and the review-gate decision table (M16.1.2) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines.

## Tier

behavioural: shared fixtures replace per-file setup, and a session-cached repo that leaks state between tests can make tests pass for the wrong reason.

## Done but wrong

- A test's repo copy shares state with the cached template or with another test. Check: a test that commits and pushes in its copy leaves the template's HEAD and the bare remote's refs unchanged for the next test.
- `run_cli` and `run_cli_subprocess` disagree on the same command. Check: both give the same exit code and stdout for `--version` and for a usage error.

## If this fails

The assumption most likely to break is that the 79 files importing from the four heaviest files can switch to tests/support without changing a collected id or the covered-arc set. If a file cannot switch that way, it keeps its import and is listed. The coordinator decides whether that file moves to M16.6.4.
