## Intent

Two upgrade defects from the rc4 pre-release checks.

1. Release blocker F1. `upgrade --dry-run` builds a scratch mirror with `git init` (upgrade_plan.py:131), then runs `git add -A` and `git commit` in it (upgrade.py:275-278). None of these calls strips the inherited git environment. Inside a git hook, or anywhere `GIT_DIR` / `GIT_WORK_TREE` is set, `git -C <scratch>` still uses the caller's repository. The dry run then stages the scratch tree and commits it into the real repo. `Plan.changed_since` compares worktree stat only, so it cannot see this. ignore_report.py:56-78 already strips exactly these variables (`_REPO_ENV`) for its own scratch git.
2. Sandbox finding, medium. After a real `upgrade` on a project with a finished leaf, `digest --check` fails. rc4's digest adds a "Quality by area" section. `upgrade` exits 0 and only lists `Run specy-road digest (and specy-road export if roadmap.md is tracked)` under `== next`, so CI fails on the first push. The real run should regenerate the drifted generated files itself and say so.

Out of scope: the mirror's ignore/untrack notices describing the mirror's empty index (cli W1, filed as rc5 M22.11); bounding scratch git waits or disabling scratch hooks beyond `--no-verify` (sol's extra suggestion); `missing_work_template_rels` (M21.22); `sync`, `init`, and any refresh's own contract.

Overlaps checked (2026-11-05): M21.17 adds the shared symlink guard to generated_files.regenerate_generated_files. This leaf does not edit that module. It checks `resolves_outside` itself before each write, through the helper upgrade.py already imports. M22.11 (rc5) touches upgrade.py/upgrade_plan.py after this leaf and depends on it. M21.23 edits docs/install-and-usage.md's refresh-profiles paragraph; this leaf edits the upgrade paragraph above it.

## Approach

- Make the stripped environment a public helper in ignore_report.py: `scratch_git_env()`, which returns `os.environ` minus `_REPO_ENV`. ignore_report's own `_git` uses it. Pass `env=scratch_git_env()` to the `git init` in `Mirror.build` and to both `git -C copy.repo` calls in `_dry_run`. After `git init`, if `copy.repo/.git` is not a directory, the dry run fails with an error and validates nothing.
- Regression test: build a second repo R and set `GIT_DIR` / `GIT_WORK_TREE` to R (monkeypatch.setenv). Run `run_upgrade(project, dry_run=True)`. R's `HEAD`, `git rev-list --count HEAD`, the index (`git diff --cached --name-only` empty and `.git/index` bytes) and its working files must be unchanged. Repeat with `GIT_INDEX_FILE`.
- Real run: after `_apply` and `validate`, and only when validate passed, compare the digest with `render_digest(project)`. Compare `roadmap.md` with the export render, but only when it is tracked (`git ls-files --error-unmatch`). Write each one that drifted or is missing (the digest when missing; `roadmap.md` only when tracked), refusing any whose path `resolves_outside(project, path)`. Print `wrote roadmap-context.md (specy-road digest)` / `wrote roadmap.md (specy-road export)` under a `== generated files` section. `digest --check` then passes. The `== next` digest line stays only for a refused write, or when validate failed (nothing is regenerated from an invalid graph).
- `--dry-run`: compute the same comparison on the copy and print `would write …` lines. The checkout is never written.
- Update upgrade.py's module docstring and docs/install-and-usage.md's upgrade paragraph. `UPGRADE_STEP_LABELS` (upgrade_templates.py) is not changed: the six step labels keep their order, and the new section prints between `validate` and `digest --check`.
