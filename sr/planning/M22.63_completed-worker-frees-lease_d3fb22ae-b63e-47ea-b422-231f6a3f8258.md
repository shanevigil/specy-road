## Intent

Two worker runtime defects found in field use of 0.3.1rc4.

1. A worker that ends `completed` keeps its slot lease ref on the remote. Locally a `completed` worker no longer counts against `policy.max_workers` (`SLOT_STATES`, `specy_road/worker_orphans.py:50`). Other clones count it through the lease ref until its leaf is over. With two leaves parked for a person, an unattended queue in another clone stops.
2. A turn started by a queued message gets specy-road's own package path in `PYTHONPATH`. That breaks a project whose own Python tooling then imports the wrong packages.

## Approach

- **Lease.** `_exit_state` (`specy_road/worker_runner.py:415-417`) deletes the lease only when the state is `failed`; the comment says "idle and completed keep it". `completed` joins `failed` there. A later `worker message` or `resume` of a `completed` worker pushes a new lease, so `acquire_lease` is called with `new=True` for `completed` as well as `failed` (`specy_road/worker_ops_message.py:114`). `sync_leases` already treats a `completed` worker as holding no slot (`holding_slots`), so `worker sync` agrees. The block comment at `specy_road/worker_lease.py:166-169` and the docs say the new rule. `idle` keeps its lease, as today.
- **PYTHONPATH.** `spawn` records the caller's `PYTHONPATH` as `harness_pythonpath` (`worker_runner.py:173`). It then starts the wrapper with the package path prepended (`:182`), and the wrapper restores the caller's value for the harness (`orchestration_role_env.harness_env`). A queued message, though, is delivered from inside the wrapper (`_deliver_queued`, `:418`, `deliver_queued_message`, then `spawn`). That `spawn` reads the wrapper's own `PYTHONPATH`, which is the package path, and records it as the next harness's value. The fix: the wrapper puts its process `PYTHONPATH` back to the `harness_pythonpath` it was given (or removes it when there was none) once its imports are done, before it runs the turn. Every `spawn` it makes then records the caller's original value. The wrapper's own imports are unaffected (`sys.path` is fixed at start, and `-P` stays).

## Test table

Fake harness scripts as `tests/test_worker_queue_message.py` and `tests/test_worker_max_workers_global.py` use them, with a local bare remote for lease refs. No sleep beyond the existing wait helpers, and no network.

| Row | Setup | Expect |
|---|---|---|
| completed releases | A worker's turn ends with READY (`completed`) | Its `refs/specy-road/leases/<cid>/<worker>` is gone from the remote |
| other clone | Clone B at `max_workers: 1`, clone A's only worker `completed` | B's `delegate` is not refused for A's worker |
| resume re-leases | `worker message` to the `completed` worker | A lease ref exists again while it runs |
| idle keeps | A turn ends `idle` (no READY) | The lease ref is still there (today's behaviour) |
| queued path | Caller has `PYTHONPATH=/caller`; a message is queued while the first turn runs | The second turn's harness sees `PYTHONPATH=/caller`, and no path of the specy-road package |
| queued no path | Same with no `PYTHONPATH` in the caller | The second turn's harness has no `PYTHONPATH` |

## Tier

behavioural: worker slot accounting and the harness environment change, and no review, record or sandbox rule does.

## Done but wrong

- The lease is released on `completed` but a resume pushes no new one, so other clones under-count a running worker: the resume row.
- `idle` workers also lose their lease (out of scope; that needs the escalation and human-wait states, M23): the idle row.
- The queued path is fixed by clearing `PYTHONPATH` for every harness, dropping a value the caller set on purpose: the first queued row keeps `/caller`.

## If this fails

Assumption: restoring the wrapper's `PYTHONPATH` after its imports does not change which `specy_road` the wrapper runs. If a lazy import in the wrapper then resolves a different package, stop and report the import; the coordinator decides whether `deliver_queued_message` should pass `harness_pythonpath` explicitly instead.

## Accepted limits

- An `idle` worker parked for a person still holds its slot (M23 intake: free it once its leaf is escalated or waiting on a person).
- A lease delete that cannot reach the remote is left for `worker sync`, as for `failed` today.
