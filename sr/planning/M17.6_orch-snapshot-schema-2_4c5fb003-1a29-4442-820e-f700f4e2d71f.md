## Intent

The panels need fields that M16.3.1's v1 snapshot does not carry (ahead/behind, READY, gate state, holds, account, last activity, flags). The M17 rule is that a missing field is a snapshot change with a new schema number, never a side import from the GUI; this leaf makes that change.

Out of scope: new orchestration behaviour, any write path, M18.22's supervision rows, the HTTP route (M17.7).

## Approach

- Additive only: v1 fields unchanged; consumers that read v1 fields keep working.
- Field names are fixed by M17.2's TypeScript optional fields; if a name must change, change both in this leaf.
- Reuse existing readers (READY parsing, handoff status, list-gates, worker records) through their public functions; git ahead/behind through M16.2.3's git helper.
- Blocked on M16's code chain: depends on M16.3.1. If M16.5.x has moved readers by pickup, import from their new homes.
- Depends on: M16.3.1, M17.2.
