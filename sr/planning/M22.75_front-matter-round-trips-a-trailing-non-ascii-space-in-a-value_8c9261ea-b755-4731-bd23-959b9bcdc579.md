## Intent

Two front-matter bugs lose or misread data. `render_front_matter` calls `.rstrip()` on the YAML dump, so a value ending in a non-ASCII space, such as U+00A0, is deleted: `{'0': '\xa0'}` reads back as `{'0': None}`. `split_frontmatter` also ends the block at an indented `---` inside a multi-line value, while `load_ready` correctly requires an unindented one. The M16.7.7 planner found both on 2026-11-18. The operator made this a blocker for the 0.3.1 release candidate.

## Approach

- Strip only the trailing newline that the YAML dump adds, not whitespace inside a value.
- `split_frontmatter` matches `load_ready`: the block ends at an unindented `---` line only.
- Add one test per behaviour, through the public functions.
- Not in scope: a body's trailing newline and Unicode line separators in a body. The M16.7.7 property excludes those from its domain. The registry U+0085 round-trip comes after the RC.
- Depends on: nothing. M16.8.4 depends on this leaf.
