## Intent

<!-- historical -->`group-nodes --into-new M16.1 M16.0 M16.1 ...` is refused with `id 'M16.1' is already taken by another node` (REHEARSAL.md step 1), although M16.1 is one of the nodes being grouped and leaves that id in the same transaction.<!-- /historical --> Every regroup into ids the flat leaves occupy then needs a temporary id and one `move-node --id` per group (8 commands became 16 in the rehearsal), and the temporary id lands in the group sheet (M22.4). After this leaf the regroup is one command per group.

Out of scope: move-node, indent and outdent (move-node --id already ignores the moved subtree), apply (M21.5 calls group-nodes and benefits), a GUI control, and B4's sheet text (M22.4).

## Approach

1. `group_nodes`: pass the listed nodes' own ids as `ignore_ids` to `check_chosen_child_id` instead of the empty set. A descendant's id is never a direct child id of the common parent, so it stays refused by today's direct-child message; ignoring whole subtrees would add nothing.
2. Final topology by node_key, no intermediate collision. Sequential `NodeMove`s with `new_parent_id = NEW_ID` fail twice: the member holding NEW_ID hits "cannot move node under itself" in `_validate_reparent_target`, and the first destination (M1.1 -> M1.2.1 in the test) collides with the child of a member not yet moved. So the new parent enters the batch under a transient id that cannot collide (a free direct child id of the common parent), the members move under it with transient child ids (`<transient>.1..N`), and after the last move one `assign_subtree_ids_inplace(nodes, new_parent_key, NEW_ID)` gives the parent and its whole subtree their final ids, before the old -> new map, the scope and the staging are computed (a `NewParent` finish step that `move_nodes` calls after the moves). The sheet is planned for NEW_ID before the transient id is set. The final graph validates once, as today.
3. The transient id never reaches disk, a sheet path, the printed map or a message. `roadmap_outline_ops.py` and `roadmap_outline_renumber.py` stay unedited; plain move-node keeps its code path.
4. Chain safety comes from the existing staging: `_stage_planning_moves` reads every source before staging deletes, and registry/zone rewrites look each id up once in the old -> new map.
5. Verify with the M1.1 / M1.2 / M1.3 test and the GUI contract test; then by hand in a scratch worktree, <!-- historical -->`group-nodes M16.0 M16.1 ... --into-new M16.1` from REHEARSAL.md step 1<!-- /historical -->.
