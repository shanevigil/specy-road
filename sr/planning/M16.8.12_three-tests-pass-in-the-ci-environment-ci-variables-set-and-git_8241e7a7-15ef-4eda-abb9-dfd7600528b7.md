## Intent

The rebuilt rc5 release PR passed every CI step except the last: three tests fail in CI's environment and pass on the orchestration host. This leaf makes them hold in both, so the release candidate can be validated and published. No shipped code changes.

1. `tests/cli/test_cli_smoke_lane.py::test_a_missing_listed_id_fails_a_run_that_deselects_the_first_item` (both parameters) asserts that the inner pytest run prints "lists ids that are not collected: [...]" exactly once. With `CI` set, pytest also prints the message in an untruncated short summary line, so the count is 2.
2. `tests/flows/review/test_review_packet.py::test_nested_and_over_budget_packets_match_the_goldens` compares packets with `tests/parity/golden/packet/nested-PACKET.md` and `over-budget-PACKET.md`. Its fixture `_nested_leaf` adds a remote and fetches. From git 2.48 a fetch creates `refs/remotes/origin/HEAD`, so the packet names `refs/remotes/origin/dev`, while both goldens, recorded on older git, carry the "origin/HEAD ... is missing" policy-source line. CI runs git 2.56; the orchestration host runs 2.43.

## Approach

Test-only (maintainer, 2026-11-23: "Go").

1. Make the smoke-lane inner pytest run independent of the caller's CI variables (for example by removing `CI` and `GITHUB_ACTIONS` from the environment `_inner_pytest` passes), so the message is printed once. Keep the assertion at exactly once.
2. Make `_nested_leaf` leave the recorded remote state on every git version: no `refs/remotes/origin/HEAD` after its fetch, done in a way that is a no-op on git older than 2.48 (for example a per-command `remote.origin.followRemoteHEAD=never`, which older git ignores). Both goldens cover the fails-closed policy-source line and must stay byte-identical. Do not switch the fixture to `git remote set-head origin dev`: that changes line 6 of both goldens.

Do not change product code, any golden, dependencies, lock files or workflows. If a fix seems to need one, stop and report.

Verify: the two test files with `CI=true GITHUB_ACTIONS=true` and with both unset; `pytest -n 4` in the usual environment. The worker's environment has git older than 2.48. The newer-git case is checked by the coordinator in a container shaped like CI (Ubuntu 24.04, current git, Python 3.12 from `requirements-ci.txt`, the CI variables set) before the release commit is rebuilt; that run is a coordinator check, not a review.
