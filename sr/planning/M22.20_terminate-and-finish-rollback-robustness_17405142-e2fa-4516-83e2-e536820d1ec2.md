## Intent

rc4 final review (§3.2, 2026-11-06), items deferred to rc5: robustness of `worker terminate` and of finish's rollback.

- **Terminate.**
  - Escaped descendants are signalled only after the group's grace period, so a child forked in that window survives (ops-grok W).
  - A zombie descendant counts as a survivor, so terminate never succeeds (ops-sol W1).
  - A failed `ps` inventory does not persist, so the next `terminate` marks the worker terminated and leaves escaped descendants running (ops-grok W).
- **Finish rollback.**
  - The pre-commit restore unlinks the file before the snapshot bytes are on disk (ops-grok W).
  - The restore drops mode bits (ops-sol W4).
  - The whole-index restore silently discards staging that happened meanwhile (ops-sol W3).

## Approach

- `worker_process`:
  - Signal the snapshotted escaped pids on the group's SIGTERM/SIGKILL schedule.
  - Exclude `Z`-state entries from the survivor checks (the inventory includes the state, consistent with `_exists`).
  - Record `descendants_unchecked: true` on the worker record when the inventory fails. `terminate` repeats the descendant pass until an inventory succeeds.
- `finish_bookkeeping_undo`:
  - `_restore` writes a temp file and calls `os.replace`, with no unlink first. On failure it keeps the temp file and prints its path.
  - Snapshots keep regular-file mode bits, and the restore applies them.
  - Before the index restore, compare the index with the snapshot's post-staging state. If it changed, refuse the destructive restore, keep both versions and print their paths.

| an unrelated path staged while the pre-commit hook runs | its staging is kept or saved and named, never silently dropped |
