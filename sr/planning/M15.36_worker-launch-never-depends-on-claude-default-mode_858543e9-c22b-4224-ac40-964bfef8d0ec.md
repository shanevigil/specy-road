## Intent

Claude Code's docs say `--bare` "will become the default for `-p`", and bare mode cannot see a subscription login. Workers launched with `claude -p` would then silently switch accounts or fail. M15.2 handles this for reviewers; this leaf applies the same rule to workers (maintainer decision 2026-11-05, from the harness research in sr/docs/research/).

## Approach

- Reuse M15.2's `reviewer_auth` check (rename or wrap it as a shared auth check if needed) in the worker launch and resume paths, before any worker state is written.
- Make the Claude adapter always pass an explicit mode for workers, derived from the roster entry, instead of relying on the CLI default.
- Tests at the public launch boundary; isolate HOME and CLAUDE_CONFIG_DIR in every test (see M15.2's test-isolation fix).

## Tasks / checklist

- [ ] A1 auth preflight on delegate and resume, refusing before state is written
- [ ] A2 explicit mode in worker argv, pinned per entry kind
- [ ] A3 tests, isolated from the developer's account
