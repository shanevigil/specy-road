## Intent

Close a review-gate hole. When code lives in a repository the root repository does not track, a rework can change only that code while the root commit changes only bookkeeping (the implementation summary). `only_planning_or_review_bookkeeping_since()` then sees only bookkeeping paths and carries the old approval forward ("approvals still count …"), so unreviewed code can pass on a stale approve; in the reported run only a separate block stopped it. After this leaf, approvals never carry when sibling repositories exist, and approvals record and check the sibling HEADs they reviewed.

## Approach

- **Detection.** New `specy_road/sibling_repos.py`: `sibling_repos(project_root) -> list[Sibling(path, head, dirty)]`. Walk the project root to depth 2 (skipping `.git`, `work/`, `node_modules`, and paths configured in `nested_repos` via `nested_repos.nested_prefixes()`); a candidate is a directory whose `.git` exists (file or dir) and `is_repo_top()` (from `nested_repos.py`) is true, and that the root repository does not track (`git ls-files` empty for it, or `git check-ignore` matches). HEAD via `git rev-parse HEAD`, dirty via `git status --porcelain`. Cache per process; keep it cheap (validate and handoff status call it).
- **Carry.** In `count_at_later_commit()` / `only_planning_or_review_bookkeeping_since()` in `specy_road/review_bookkeeping.py` (57 lines), return "not carried" when `sibling_repos()` is non-empty, and set a reason on `result` that handoff status prints in place of `CARRY_NOTE` ("approval at <sha> is stale: sibling repositories <list> are present and nested_repos is unset, so changes there cannot be seen"). `review_gate.py` is at 400 lines and is not edited: all logic stays in `review_bookkeeping.py`.
- **Recorded heads.** Add optional `sibling_heads: {path: sha}` to `specy_road/schemas/handoff.schema.json` and `specy_road/schemas/review-record.schema.json`. `handoff ready` (`review_gate_ready.py`) and `review record` (`review_cli.py`, 387 lines: one call into `sibling_repos.py`) fill it. In `count_at_later_commit()`, a record whose `sibling_heads` differ from the current heads (or a sibling now dirty) is stale even at the same root commit. A record without the field counts only at the same root commit.
- **validate.** `specy_road/bundled_scripts/validate_roadmap.py` is at 399 lines. Replace its run of `warn_*(root)` calls with one loop over a tuple of those functions (net fewer lines) and add `warn_unconfigured_sibling_repos` from `sibling_repos.py`: one warning naming the repositories and pointing at `docs/git-workflow.md`'s nested_repos section. (M13.8, unclaimed, also edits this block; whichever lands second rebases.)
- **Policy line (F-073).** In the final gate a carried approval from four rounds and several code commits earlier counted toward `policy: 2/1`. `GateResult.summary()` lives in `review_gate.py` (400 lines, not edited), so render the line in `review_cli.py` from the gate's `approvals` (each `CountedReview` has the review's commit): `policy: 2/1 approvals (gpt-6.1-sol@1a2b3c4d5e6f, grok-4.7-high@0f9e8d7c6b5a carried from an older commit)`. Use the same text in handoff status and `review record`'s closing `policy:` print.
- **Verify.** Tests under `tests/`: a temp root repo with an ignored sibling repo; approve at root commit A; commit only the summary in root (B) and a code change in the sibling; gate at B does not count the approval and status prints the reason. Same root commit, sibling HEAD moved → stale. No siblings → carry unchanged (existing tests pass). validate warning once.
