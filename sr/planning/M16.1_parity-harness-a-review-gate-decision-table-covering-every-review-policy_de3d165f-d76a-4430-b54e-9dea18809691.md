## Intent

The review gate is the part of specy-road whose behaviour must not move during M16: the review-policy evidence pass (M16.20), the review fold (M16.21) and the `checks:` block (M16.14) all touch it. One decision table makes every kept policy's verdict explicit and cheap to re-run.

## Approach

- Cases are YAML/JSON fixtures under tests/parity/review_gate/cases/; one parametrised test reads them.
- Build records with the existing review record writers, not hand-written strings, so record-format changes stay in one place.
- Reason codes, not sentences: where the gate only returns prose today, assert the stable key it already prints (no package change in this leaf).
- Revision 1: rows per reason code, defaults and named interactions instead of one row per schema key (Sol 3); frozen historical records test the reader, not today's writer (Sol 3); reviewer-output rows protect the M8.3/M15.17 filing path (tonight's grind lesson).
- No public-result seam is added here: rows without a reason code assert what the result already exposes.
- M16.52 and M16.22 add their own rows to this table.
- Depends on: none. Expected net line delta is the last acceptance line; report `scripts/lean_metrics.py --check` deltas in READY once M16.2 has landed.
- Behaviour-preserving: the parity harness (M16.0) and the review-gate decision table (M16.1) stay green; no function rises above its merge-base complexity.
