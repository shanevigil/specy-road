## Intent

Defect D7 (Low-Medium) from the rc4 real-harness checks (pre-release evidence 2026-11-05, ToDo app). `handoff status M2.1` failed the gate closed with "refs/remotes/origin/HEAD … is missing, and with a remote configured the integration branch is named only there; run `git remote set-head origin --auto`", even though `git-workflow.yaml` names `integration_branch: main`. The suggested command then failed ("error: Cannot determine remote HEAD"). The cause is a common setup: the bare remote was made with `git init --bare`, so its HEAD points at an unborn `master`, and the app was created with `git init`, `remote add` and `push -u`. The gate worked only after `git remote set-head origin main`.

`origin/HEAD` is the anchor because a feature commit must not nominate its own integration branch (review_policy_ref.py docstring). So the fallback must not trust the branch under review either.

Fix: when `refs/remotes/<remote>/HEAD` is missing, use the integration branch that HEAD's config names, but only if that remote-tracking branch's own committed config names itself (and the same remote) and it is the **only** branch on that remote that does. Without the anchor, a feature branch would have to name itself to win, and it would then be a second self-naming branch, which fails closed. When the fallback does not apply, the error names the exact `git remote set-head <remote> <branch>` command instead of `--auto`.

Out of scope: running `set-head` for the user; repos without a remote (unchanged); a remote whose default branch the feature author can push to (already outside the protection).

Overlaps checked (2026-11-05): M22.3 and M21.26 also edit docs/orchestration.md (other paragraphs). No other open leaf lists review_policy_ref.py.

## Approach

- `integration_name` (review_policy_ref.py:45-75): if the anchor is missing, take `name` from HEAD's copy. Require that `refs/remotes/<remote>/<name>` exists and that its copy names `integration_branch: <name>` and the same remote. Scan `git for-each-ref refs/remotes/<remote>/` (skipping HEAD) and require that no other ref's committed copy names itself. Return `where = "(roadmap/git-workflow.yaml at <remote>/<name>; <remote>/HEAD not set)"`. A candidate whose committed config is malformed or not a mapping, or a failed `for-each-ref`, fails closed. Any check that fails returns the existing error. The hint names `git remote set-head <remote> <name>` (with a note that `--auto` fails when the remote's HEAD is unborn) only when exactly one ref other than one at HEAD's commit has a readable config that names itself (`or "main"` does not apply); otherwise it names no branch.
- The cost is one `git show` per remote branch, paid only when the anchor is missing. Say so in the docstring.
