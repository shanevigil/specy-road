## Intent

Promoted nodes have a goal, a sane codename and a stable order, and promote reports once what is still missing.

## Approach

`promote_session` still loops one add-node write per idea (`append_node_to_chunk`). Each write passes `validate=False` so the chunk router does not run `validate_at` per node; after the batch, one `run_validate_raise` reprints pin/schema warnings once. `write_with_routing` gained the same skip flag so promote does not copy the routing transaction.

Codename derivation stays in `roadmap_edit_fields.title_to_codename`: `max_words=4` is passed through `derive_codename_with_collision_suffix` (existing collision suffix). `revise --codename` is stored on the session idea and wins over derivation.

Every `accept` (including without `--reason`) writes `decision.seq` and a millisecond `decided_at`; promote sorts by seq, then timestamp, then id. `sibling_order` comes from `next_sibling_order`, so later promote calls append after existing siblings rather than restarting at 1. A non-empty hypothesis becomes the node's `goal`. After a successful promote, one stderr line lists new node ids still missing `acceptance` or `touch_zones`.
