## Intent

The operator's gate for the irreversible steps of the sweep. History rewrites, force-pushes, repository visibility, GitHub Support and TestPyPI deletions are operator-only; no agent runs them. 0.3.1 is not tagged until this gate is cleared. Final pass, before the 0.3.1 tag. Source: the maintainer's scrub plan (private), section 4, approved 2026-11-09.

## Approach

The maintainer clears this gate (sets it Complete) after doing these steps, using M22.58's evidence and script:

- **Publish the rewrite:** force-push every rewritten branch and tag, or move to a new repository built from the rewritten history (which drops pull-request refs and caches but loses stars, issues and the PyPI trusted-publisher binding).
- **Support:** file the GitHub Support request for the pull-request refs and cached commit views.
- **TestPyPI:** decide yank or delete for each candidate published before the rewrite, and carry it out.
- **Re-clone:** re-clone every machine and worktree, after bundling local-only branches, refs and the stash.

Freeze all workers and grind sessions before the push, so no session pushes old history back.

## Tasks / checklist

- [ ] Workers and grind sessions frozen
- [ ] Force-push of the rewritten refs, or the move to a new repository
- [ ] GitHub Support request filed
- [ ] TestPyPI decision made and carried out
- [ ] Every machine and worktree re-cloned
- [ ] Maintainer: gate cleared (date)

## Tier

none: a human gate. No agent work is dispatched or reviewed under it.

## Done but wrong

- Old history comes back: after the push, `git log --all` on a fresh clone contains no SHA from the old side of M22.58's map.
- A clone was missed: no machine or worktree still has a remote-tracking ref at an old SHA.

## If this fails

If the trusted-publisher binding or the release-version CI fails on the new SHAs, stop before tagging; M16.8.9 stays blocked until the maintainer re-registers the binding or fixes CI.

## Accepted limits

- Forks and copies made while the repository was public are out of reach.
- Pull-request refs and cached views stay until GitHub Support acts.
