## Intent

The integrity report (`specy_road/integrity.py`, `compare_integrity`) compares the test files present at base and at ref, so a `git mv` of a test file reads as a removed test file and every test in it as a removed test. M16.6.5 moves about 460 test files into lane directories. The report then lists all of them, which puts the reviewer prompt over the Codex input limit, and review records refuse an approve while unplanned removals remain. This leaf makes the report follow renames, so a pure move is not a removal and M16.6.5 can be reviewed.

Out of scope:
- Tests moved between files without a file rename (M16.6.6 folds; its planner declares those in `planned_test_changes`).
- Ratchet and suppression findings, which already follow renames.
- The review packet's layout.

## Approach

- Reuse `_changed_files(root, base, ref, "--find-renames")`, which `integrity.py` already uses for ratchets, to map each renamed test file from its old path to its new path.
- `_removed_test_files` skips a base path that has a rename target.
- The per-file test comparison reads the base side at the old path and the ref side at the new path. A test dropped, newly skipped or losing asserts during the move is still reported, under the new path.
- Tests: one that fails on the current behaviour (a moved file gives removed-test-file and removed-test), and one showing that a test dropped in the same move is still a removed-test.
- Check against M16.6.5's branch (c16b2d01 against 3affe0ea) and report the remaining finding counts in READY.

behavioural: it changes which removals the integrity report and the review gate see. The new test must fail on the old behaviour, and real removals during a move must still be reported.

## Done but wrong

- Removals are suppressed for any file that git's rename detection pairs, even when tests were dropped in the move. The per-test comparison must still run, against the new path.
- A file deleted outright stops being reported.
