## Intent

Four or five 'verification command' concepts grew separately (baseline, land check, verify, per-zone CI gates requested by an adopter). One block is the only new config M16 adds, and it retires three keys. The review-before-finish switch (`require_implementation_review_before_finish`) stays in git-workflow.yaml as it is (operator, 2026-11-13).

## Approach

- Revision 1: verify_cmd is a prompt-time contract as well as a command, so `when: prompt` keeps it (Sol 4); a migration table freezes absent, blank, override, old, new and mixed forms (Sol 4, Grok 12); zone-scoped merge gates (held M15.23's purpose) are M16.4.6, the named new behaviour, now M23.4 after 0.3.1 (2026-11-09); the entry schema has only name, run and when.
- CLI overrides are `--baseline-cmd` (pickup, grind-session) and `--land-check-cmd` (finish); an empty value disables the check for that run. `review packet --verify-cmd` and `ready --verify` record evidence and are not key overrides.
- The entry schema is written in a `checks:` section of docs/git-workflow.md (tracked, zoned), not under sr/work/.
- Help goldens that change (each through a tests/parity/command_map.yaml row): tests/parity/golden/help/specy-road__brief.txt, tests/parity/golden/help/specy-road__do-next-available-task.txt, tests/parity/golden/help/specy-road__finish-this-task.txt, tests/parity/golden/help/specy-road__grind-session.txt.
- The dogfood fixture keeps the old key form. planned_test_changes covers tests/parity/golden/dogfood/validate.txt, tests/parity/golden/upgrade/rc3-dry-run.txt and `ALLOWED_ADDED` in tests/parity/test_generated_outputs.py.
- Depends on: M16.4.4. The last acceptance line is an informational line-change estimate, not a gate; report `scripts/lean_metrics.py --check` deltas in READY once M16.1.7 has landed.
- Behaviour-preserving: the parity harness (M16.1.1) and the review-gate decision table (M16.1.2) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines.

## Tier

trust boundary: Replaces the readers of the land check, verify and baseline commands and migrates them via `upgrade`, so it changes what ready, land and pickup run. The land check decides landing. The review-before-finish switch is not moved (operator, 2026-11-13). (Raised from behavioural by the tier review in spirit, 2026-11-09; was: it migrates the land check and the review-before-finish switch, which decide landing; a test of the file contents can pass while an effective requirement is lost.)

## Done but wrong

- Review-before-finish is touched by upgrade: on a repo with the switch on, after `upgrade`, the switch is still in git-workflow.yaml and finish still refuses a leaf with no approval.
- A land check is skipped on one landing path: a failing `when: land` entry refuses landing under `land: push` and under `land: local` (`finish_land_local.py` runs its own check).

## If this fails

Most likely to break: a recorded row (a CLI override, an empty value, or the prompt's appended test paths) gives a different result from its `checks:` equivalent. If a row cannot keep its recorded result, stop and name the row; the maintainer decides.
