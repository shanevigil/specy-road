## Intent

Report the states that stalled the 0.3.1 grind without anyone asking: a dead or silent loop, a failed worker nobody re-sent, a running worker gone quiet, a finished leaf with nothing in flight, review runs queued with none running, a ready leaf nobody delegated, and an integration checkout left dirty. The coordinator's `watchdog.py` did this by polling logs; `doctor` should do it from specy-road's own records.

**Out of scope:** restarting the loop, re-sending turns or terminating workers (the report is read-only; restarting belongs to the user's supervisor: cron, systemd, launchd or a terminal multiplexer); configurable thresholds; notifications.

## Approach

- One table of rows in new `specy_road/orchestration/supervision.py`, each row a predicate over the M16.15 snapshot, the grind event log, the review run records (M18.24) and a heartbeat file the loop writes each tick. `doctor` and `grind-session --status` render the same rows.
- Thresholds are the watchdog's, as named constants: heartbeat three ticks, stalled 45 minutes, idle 15, queue 15, undelegated 30, dirty checkout 5.
- The undelegated row names its reason, the overlapping claim and zone or the capped model, because "ready but not delegated" was only diagnosable by reading dispatcher code.
- Evidence: the dispatcher deadlocked on its own git lock for an hour (RE 2026-11-05 11:25); four failed workers sat about 20 minutes because nothing raised a failed worker (RE 15:44); a dirty checkout blocked landings (RE 15:12); five blocked leaves idled (RE 15:23).
- Buy vs build: supervision is a workflow engine's job too; see `sr/docs/research/harness-landscape.md`. No daemon is added.
- Depends on M18.20 (heartbeat and events), M18.24 (review run records), M16.11 (doctor's cleanup rework) and M16.15 (snapshot).
