## Intent

After a successful `specy-road init project`, the output stops at `Initialized specy-road layout under <dir>`. The steps that have to follow (set the integration branch and remote, commit the scaffold, validate) are written only in docs/install-and-usage.md. An adopter who stops at the scaffold has an uncommitted tree that most commands then complain about. This leaf prints a short next-steps block at the end of a real run.

Out of scope: running git or validate for the user, `init gui`, `specyrd init`, `upgrade`, and changing any `wrote` / `skipped` / dry-run line.

Overlaps checked (2026-11-05): M16.1.1 (parity harness) records golden `--help` transcripts and an end-to-end loop that runs `init project`. Its goldens are help text, so they are unaffected; an end-to-end transcript, if it compares init stdout, picks up the block when it lands. M16.5.6 (upgrade migrates rosters) and M16.4.2 (upgrade report) change `upgrade`, not init. M19.19 changes the roadmap template and guide, not init output. M16.6.2 aligns suggested_prompts. No suggested prompt quotes init's output, so none changes here. M22.1 to M22.5 do not touch init.

## Approach

- In `init_project.run_init_project`, after the `Initialized` and `Recorded project_root` lines of a real run, print:

  ```
  Next steps:
    1. Set integration_branch and remote in <prefix>roadmap/git-workflow.yaml
    2. git add -A && git commit -m "specy-road init"
    3. specy-road validate
  ```

  Outside a git repository (`top is None`), a `git init` step comes first and the rest are renumbered. `<prefix>` is the git-root-relative prefix the `wrote` lines use.
- `--dry-run` returns before the block. Refusals return earlier still.
- Tests: update the two report tests that read stdout (none compares the whole output today, so only additions). Add exact-text cases.
