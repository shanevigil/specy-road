## Intent

Final sandbox rehearsal, 2026-11-06 (sr/work/sandbox-feedback/2026-11-06-rc4-final-2c45d7e8.md): the non-blocking findings, fixed together for rc5. Each is small and independent.

1. **F4, planning-sheet save churn.** Saving a planning sheet in the PM GUI rewrites Markdown the person did not touch: a list item's two-space continuation indent is removed and a trailing blank line is added. Same meaning, but diff churn in every saved sheet.
2. **F5, two names for the GUI extra.** `--help`'s `gui` line and the `gui` command's install errors name `specy-road[gui-next]`, while docs and the brief use `[gui]`. pyproject.toml's `gui` and `gui-next` extras list identical dependencies.
3. **F7, upgrade's own stale warning.** `specy-road upgrade` first prints `warning — AGENTS.md block written by specy-road <old>, running <new>; run \`specy-road upgrade\`.`, telling the person to run the command they are running.
4. **F8, export drift hint.** `export --check`'s drift message is `drift: <path>` with no fix; digest's says `Run: specy-road digest`.
5. **F9, modals.** Escape does not close the GUI edit or publish modals, although `ModalFrame` has a `closeOnEscape` listener; each edit modal opening logs `[tiptap warn]: Duplicate extension names found: ['link']` (StarterKit already includes Link and MarkdownWorkspace adds it again).

Not here: the ~225 ms selection lag (F1) and acceptance editing (F2) are M17 questions (M17.1 open questions); display-id compaction (F6) and the group control (F10) are observations with no fix filed.

Moved out (2026-11-06): F5 to M16.6.1, F7 and F8 to M22.28; this leaf keeps F4 and F9, and its line-change estimate was split with them.

## Approach

- **F4.** In `MarkdownWorkspace`, an unedited document saves byte-identical text, and editing one block leaves the other blocks' source text unchanged. The implementer picks the mechanism (serializer options for list indentation and the trailing newline, or keeping the loaded text for unchanged top-level blocks); the round-trip test pins the behavior, not the mechanism.
- **F5.** One name in what tells a person to install: `[gui]` in `cli_usage.py`'s help, `cli.py`'s install errors, `cli_init.py` / `cli_init_argparse.py` (the pip command `init gui --install-gui` runs and its help), review_node.py's and update_specy_road.py's messages, and the install lines in README.md, docs/install-and-usage.md, docs/pm-gui.md, docs/pm-workflow.md and docs/contributor-guide.md. The `gui-next` extra stays in pyproject.toml as an alias so existing installs keep working (no packaging change); docs/supply-chain-security.md keeps listing both extras because both exist.
- **F7.** `cli._maybe_warn_running_version_older` skips `upgrade` as it already skips `doctor`; upgrade's own report already states the versions.
- **F8.** `export --check` drift prints `drift: <path> no longer matches the roadmap. Run: specy-road export`, the digest wording.
- **F9.** Find why the Escape listener does not fire for `EditModal` and `PublishRoadmapModal` (focus inside the editor, a parent passing `closeOnEscape={false}`, or `minimized`) and fix it so the front-most modal closes on Escape and only that one; configure Link once (`StarterKit.configure({ link: false })` or configure it inside StarterKit).
- GUI tests run in vitest's node environment (vitest.config.ts), so they pin the behavior through pure helpers: the Markdown save (src/planningSectionUtils.ts or a helper beside it), the editor's extension list (exported from MarkdownWorkspace or a small module), and the Escape decision (front-most, not minimized, not swallowed by the editor).
- GUI: `npm ci && npm run lint && npm test && npm run build` in gui/pm-gantt, and the rebuilt `specy_road/pm_gantt_static/`.
