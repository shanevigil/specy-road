## Intent

M22.81 fixes the two paths M16.7.7's properties tested. The same Python defaults (read_text newline translation, str.splitlines) appear in 159 read_text and 143 splitlines calls across the package. Most only read for parsing and are harmless, but any other path that writes data and reads it back, or rewrites a user's file, can change text the same way. The maintainer asked for that audit before 0.3.1 (2026-11-20: "c3 before 0.3.1").

## Approach

- List every read_text, write_text and splitlines call site, classify it read-only, round-trip or rewrite, and record the list with file:line in the summary.
- Move each round-trip and rewrite site onto the M22.81 helper, or record why its input can only be \n-only text specy-road wrote itself.
- One round-trip test per changed site through its public interface.
- Depends on: M22.81. The 0.3.1 tag gate (M16.8.9) depends on this leaf; it is not an RC5 blocker.

## Tier

behavioural.

## If this fails

If a site cannot keep exact text without changing an on-disk format adopters rely on, stop and report that site; do not change formats.
