## Intent

Every later M16 leaf moves or merges code and must prove it changed no behaviour. Today that proof is spread over about 4,400 test items that pin internals; a small harness at the user-visible surface (command surface, the leaf loop, the generated files) gives one fast, stable answer. It also absorbs the inventory half of held leaf M12.6.

## Approach

- Build the command list from `cli.py`'s tables (and each group's subparsers) so the inventory cannot drift from the CLI.
- Normalise argparse width (`COLUMNS=100`) and program names before comparing transcripts.
- Reuse the dogfood fixture copy and the existing offline PR-mode path; no network, no `gh`.
- Goldens are data files, not tests: one parametrised test per surface.
- Revision 1: the inventory is compared both ways and aliases are part of the set (Sol 18); command_map.yaml is the only way a later leaf may change a transcript (Sol 20); history-derived digest sections are excluded because they made roadmap-context.md branch-dependent tonight.
- M16.1.7 re-runs the harness at the recorded baseline commit (rc4 delivered); the rc3-shaped upgrade fixture stays as an extra migration case.
- Depends on: none. The last acceptance line is an informational line-change estimate, not a gate; report `scripts/lean_metrics.py --check` deltas in READY once M16.1.7 has landed.
- Behaviour-preserving: the parity harness (M16.1.1) and the review-gate decision table (M16.1.2) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines.
- Alignment review (2026-11-05): S3 accepted: A1 reads command names through `cli.registered_agent_command_names()` and public parser builders or help output, never `cli._known_commands()`, so the private-reference gate and M16.7.6's empty baseline hold. Decision table in the M16 phase sheet.

## Tier

behavioural: about forty later leaves use this harness as their proof of no behaviour change, so a harness that cannot detect a change would still pass.

## Done but wrong

- The inventory misses part of the surface: forwarded commands (history, digest, search, brainstorm), shared-parser subcommands (roadmap_query_cli) or aliases. Check: the inventory lists every alias in `cli.py`'s tables and at least one subcommand option of a forwarded command, and removing one option from a scratch copy fails the test, naming it.
- Normalisation hides a real change. Check: changing one option's help text in a scratch copy fails the transcript test.
- The leaf loop goes green without exercising the gate. Check: the merge run fails at the gate when one of the two review records is left out.

## If this fails

The assumption most likely to break is that finish with `on_complete: pr` runs to the end offline, with a local bare remote and no `gh`. If it calls out to a hosting service, record the run up to the last offline step and note where it stops. The coordinator decides whether the pr run ends there.

## Accepted limits

- Transcripts are pinned at `COLUMNS=100` only.
- Digest sections derived from git history are not compared.
