## Intent

A grind leaf gets one or two fix rounds. Today a fix after a block needs a full review from both families again, because `delta_problem` accepts a delta only when it touches at most `DELTA_MAX_FILES` documentation or test files. A code fix therefore resets the approval the other family already gave, and each round costs two full reviews. The maintainer approved a fix-check on 2026-11-09: the blocking reviewer checks only its own findings against the fix, and the other family's approval carries. Source: the governance compatibility plan, section D.

## Approach

The executor names the block it answers with `fix_of: <reviewer>@<commit>` in READY. The gate counts the other family's approval at that commit across the fix delta under three conditions: every changed path is in the leaf's zones, the sheet's tier on the integration branch is not trust boundary, and a `fix_of` is present. Under these conditions the docs-or-tests and file-count limits of `delta_problem` are skipped; otherwise today's rule holds unchanged. The blocking reviewer's prompt lists its findings and the fix diff, and asks for a verdict on each finding and for new findings only where the fix broke something.

## Tasks / checklist

- [ ] Gate: `fix_of` carry with the zone and tier conditions; today's rule otherwise
- [ ] Prompt: the blocking reviewer's fix-check section
- [ ] Tests (carry, trust refusal, out-of-zone refusal, new finding, missing `fix_of`), docs, CHANGELOG

## Tier

trust boundary: the review gate decides which approvals count.

## Done but wrong

- The carry ignores the tier: a leaf whose sheet on the integration branch names trust boundary, but whose branch copy says plain, still carries. Check: the trust-refusal test edits only the branch copy of the sheet.
- A path outside the zones carries: the out-of-zone test changes one file outside the leaf's zones and the approval does not count.
- A READY without `fix_of` carries: with `fix_of` absent the gate gives the same result as today on the same delta.

## If this fails

Assumption: the gate can read the tier from the integration branch's copy of the sheet without a new git helper. If it cannot, stop and name the helper needed; the coordinator decides before any file outside the zones is added.

## Accepted limits

- One block, answered by one fix commit, at a time. A fix that answers two blocks needs today's full reviews.
- A fix that breaks something the blocking reviewer does not look at is caught only by later review or tests.
- Trust-boundary leaves keep today's rule.
