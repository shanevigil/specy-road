## Dispatcher table

Recorded with the process corpus (`tests/parity/process/`, A1). `specy-road <command> <words>` imports `specy_road.bundled_scripts.<module>` and calls its `main(argv)` in the CLI's own process, with `sys.argv` set to `[program, *argv]` while it runs, as the child interpreter had it, so argparse names the program as before. The prefix is what `argv` starts with before `<words>`:

- **—**: nothing; the program is `specy-road <command>`.
- **name**: the command name, because the module's parser has one subcommand per command it serves; the program is `specy-road`.
- **`guard`**: the dispatcher requires `guard` as the first word and passes the words after it; any other first word prints `usage: specy-road orchestration guard --format …` and exits 2, as before.

`scaffold-constitution`, `init` and `gui` stay functions in `cli.py`; `gui` still launches uvicorn in a child interpreter.

## Tier

trust boundary: The gate-closing command (`mark-implementation-reviewed --yes`), finish and the guard CLI stop running in a child interpreter and lose their cwd globals, so their exit and nested-failure handling changes. The recorded corpus is success-path only (sheet), and the milestone path must still stop before committing when validate fails. (Raised from behavioural by the tier review in spirit, 2026-11-09; was: the process boundary gave each command fresh cwd, globals and exit handling, and the success-path corpus does not exercise nested failures.)

## Done but wrong

- A command still runs in a child interpreter in another form. `cli._run` today uses `python -c` with runpy, not `-m`, so a test that looks only for `-m specy_road` passes on it. Check: the corpus passes with every launch of the Python interpreter refused, except the GUI's uvicorn launch.
- A nested failure behaves differently. doctor captures registry_prune's output and reports it as a finding, and the milestone path of mark-implementation-reviewed stops before committing when validate, export or digest fails. Check: a failing nested prune prints the same line and doctor goes on to the next item; a failing validate in the milestone path exits as before and makes no commit.

## If this fails

The assumption most likely to break is that module-level state (the `ROOT` globals, caches, `os.environ` edits) can be made per call inside the zoned modules. If a module outside the dispatcher table holds such state, the coordinator decides whether to widen the table. If output would change, the maintainer decides.
