## Intent

Every command currently runs in a second interpreter (about 400 ms for `--help`), and code exists only to pass arguments across that boundary. Fifteen unrelated error classes and 226 exit sites hand-roll the same catch-print-exit.

## Done but wrong

- A command still runs in a child interpreter in another form. `cli._run` today uses `python -c` with runpy, not `-m`, so a test that looks only for `-m specy_road` passes on it. Check: the corpus passes with every launch of the Python interpreter refused, except the GUI's uvicorn launch.
- A nested failure behaves differently. doctor captures registry_prune's output and reports it as a finding, and the milestone path of mark-implementation-reviewed stops before committing when validate, export or digest fails. Check: a failing nested prune prints the same line and doctor goes on to the next item; a failing validate in the milestone path exits as before and makes no commit.

## If this fails

The assumption most likely to break is that module-level state (the `ROOT` globals, caches, `os.environ` edits) can be made per call inside the zoned modules. If a module outside the dispatcher table holds such state, the coordinator decides whether to widen the table. If output would change, the maintainer decides.
