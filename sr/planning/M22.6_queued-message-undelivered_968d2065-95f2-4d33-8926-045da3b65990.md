## Intent

An adopter repo reported a worker's queued follow-up (`worker message` sent while the turn was running) that was never delivered: when the wrapper tried to send it as the next turn, origin rejected the worker's lease. The only trace was an `error` event in the log. Nothing in `worker list`, `worker status` or `handoff status` showed it. The worker sat idle with a follow-up nobody knew was stuck.

Found in the code (2026-11-05):

- `worker_runner.deliver_queued_message` clears `queued_message`, calls `worker_ops_message._send`, and on a `WorkerError` puts the text back and logs `queued message not delivered: <e>`. `_deliver_queued` (called from `_exit_state`) swallows it. A lease rejection is a `WorkerError` from `worker_lease.acquire_lease` ("<remote> rejected the lease for W ..."), so the text survives. But no flag is set. Any other exception from `_send` (`Unsupported` subclasses `Exception`, not `WorkerError`; an `OSError` writing the prompt) loses the text, and the exception escapes the wrapper's exit path.
- Delivery is attempted only when a turn ends. Once the worker is `idle`, the queued text just sits there. A later `worker message` or `worker resume` sends only its own prompt, and the stored text is never sent.
- `worker list` and `worker status` already print `queued: ...` and `[flags]` (worker_cli_render `_line`). `handoff status --json` lists `workers[]` via `WorkerRecord.to_dict()`, which carries `flags`. So a new flag shows in all of them with no renderer change.

Out of scope: retry loops or timers, a new `--retry` option, lease failures outside queued delivery (delegate, adopt), the text `handoff status` renderer (review_cli.py), and M18.11's `worker message --interrupt`.

Overlaps checked (2026-11-05): M22.5 (steering guard) adds `steering_changed` to the same flags enum in worker-record.schema.json. M18.23 (account pools) also edits that schema. Whichever lands second rebases the one enum line, so no dependency is needed. M18.11 adds `--interrupt` to `worker message` in worker_ops_message.py: different code, no conflict expected. M16.3.1 and M16.2.1/M16.2.2 later move or trim worker_state.py; this leaf adds one constant. M16.4.3 renames `handoff status` to `review status` later; the JSON field is the same record dict. M22.1 to M22.4 do not touch workers.

## Approach

- **Smallest consistent behaviour, no new option.** The text is kept on the record, as today. A sticky `message_undelivered` flag says it is stuck. The next turn that `message` or `resume` launches on that worker sends it first.
- `worker_state.py`: `FLAG_UNDELIVERED = "message_undelivered"`. Schema: add it to the `flags` enum with a description.
- `worker_runner.deliver_queued_message`: treat any exception from `_send` as a delivery failure. Restore the text unless the worker is terminated, `add_flag(FLAG_UNDELIVERED)`, log the existing `error` event, and re-raise `WorkerError`s as now. `_deliver_queued` also swallows the non-`WorkerError` case after it is recorded, so the wrapper's exit path is unchanged.
- `worker_ops_message._send`, launch path (not the queue path): if `rec.queued_message` is set, the prompt text becomes `queued + "\n\n" + text`. Clear `queued_message` and `FLAG_UNDELIVERED` only after `spawn` returns. A refusal before spawn (lease, limit, slot, launch checks) leaves both. The delivery path itself clears `queued_message` before calling `_send`, so the text is never doubled.
- `worker_ops_lifecycle` terminate: it already drops the text, and now it also clears the flag.
