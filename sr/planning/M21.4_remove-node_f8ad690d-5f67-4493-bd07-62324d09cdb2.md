## Intent

rc4 roadmap-tooling fix (maintainer 2026-11-05), filed in M16's fix intake. Removing an empty, never-started node needs `archive-node --hard-remove`, which help calls "legacy". Its check (`can_hard_remove` in roadmap_crud_delete.py) refuses children and dependents but not a registry claim or a started node, and stops at the first blocker. The PM GUI's `DELETE /nodes/{id}` calls the same `delete_roadmap_node_hard`, so it can also drop a claimed node.

Evidence: regrouping M16 into sub-milestones using only specy-road commands (scratch run, 2026-11-05) took about 85 commands, a temporary holder node and about 100 s, and left about 950 stale id mentions in prose. Earlier related fix: M16.67 (move-node renumbers only the moved subtree; whole-outline renumber became explicit).

## Approach

- `remove-node <ID> [--dry-run]` as the supported command over one function: refuse unless status is Not Started and the node has no children, no registry claim and no dependents; the refusal lists every blocker.
- `DELETE /nodes/{id}` and `archive-node --hard-remove` call the same function; response shape unchanged.
- Command renames and alias retirement stay with M16.45.
