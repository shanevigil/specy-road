## Intent

In the 2026-11-04 context-regression replay, case CR3 ("cleaning up discarded a peer's files") failed 3/3 on Cursor and 1/3 on Codex. The shared-checkout guard refused the shell command, and the agent then got around it in two ways. It used the harness's file tools (Cursor `editToolCall`/`deleteToolCall`, Codex `apply_patch`), which a shell hook never sees. Or it ran `specy-road session end <peer>`, which retires a live peer's record when the same OS user started it. The triage rated both as specy-road defects. This leaf closes both gaps.

## Approach

- Source: `docs/design-notes/context-regressions-2026-11-04-triage.md` (section CR3, "Next (0.3.2)"), and the 2026-11-05 milestone audit (`sr/work/milestone-audit-2026-11-05.md`, M8 gaps: no roadmap node for the CR3 next step).
- The rule stays the same: deny a change to a path that another live session has dirty. Only the events it sees are new: Claude Code `PreToolUse` on `Edit` and `Write`, Cursor `preToolUse` on its edit and delete tools, and Codex `apply_patch` only where its harness-facts record documents a hook for it.
- The CR1 next step (signed reviews by default) is M18.4. The two small CR3 follow-ups the triage also lists are out of scope: the `git stash list` false positive and the `sync` reflog entry.
- Depends on M16.18 (guard moves into `specy_road/orchestration/guard/`) and M16.48 (the classifier becomes rule tables). The zones name that end state.
