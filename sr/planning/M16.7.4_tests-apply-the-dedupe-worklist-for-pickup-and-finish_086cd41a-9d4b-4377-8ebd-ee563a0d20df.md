## Tier

behavioural: the leaf deletes tests, and a suite with fewer tests still passes; the arc check shows execution, not checking.

## Done but wrong

- A fold loses an input or an expected value. Check: each removed test's input and expected result appears as a row of its fold table.
- A delete relies on an assertion that is no longer there, for example one M16.7.2 or M16.7.3 removed. Check: the assertion each delete row names is present at head in the surviving test.

## If this fails

The assumption most likely to break is that each row's named assertion still covers the removed test at apply time. When it does not, the test stays (an undecided row is keep) and the summary lists the row. The coordinator updates planned_test_changes.
