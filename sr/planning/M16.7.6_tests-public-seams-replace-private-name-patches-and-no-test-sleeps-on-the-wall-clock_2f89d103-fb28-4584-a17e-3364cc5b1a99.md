## Intent

Private patches make tests load-bearing on internals; 16 files sleep; parsers are tested one input at a time.

## Approach

- Revision 1: property tests are their own leaf (M16.7.7) with a fixed list of invariants (Grok 15); this leaf follows the client, worker and guard moves it needs (Grok 2, Sol 22).
- Depends on: M16.7.5. The last acceptance line is an informational line-change estimate, not a gate; report `scripts/lean_metrics.py --check` deltas in READY once M16.1.7 has landed.
- Behaviour-preserving: the parity harness (M16.1.1) and the review-gate decision table (M16.1.2) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines.

## Tier

behavioural: production gains seams, and about 120 baseline references are rewritten, so a rewritten test can pass while reaching less code, and a seam can change a default.

## Done but wrong

- A seam changes what production does by default. Check: the parity harness and the M16.1.2 decision table stay green, and production callers pass no new argument.
- A rewritten test no longer reaches the code it used to patch. Check: the covered-arc set of each module with a new seam is unchanged across the leaf.
- A logical timeout or stall test still waits on real time. Check: each converted test finishes in much less wall time than the timeout it simulates.

## If this fails

The assumption most likely to break is that every private reference has a public seam that needs no behaviour change and no test removal. When one does not, the leaf stops with blocked_on (M16.7 phase sheet, G6). The coordinator decides; if the baseline cannot reach empty, the maintainer decides, because that changes acceptance.
