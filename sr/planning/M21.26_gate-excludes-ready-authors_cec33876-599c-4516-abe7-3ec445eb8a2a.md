## Intent

Defect D3 (Medium-High, security) from the rc4 real-harness checks (pre-release evidence 2026-11-05, grind §7, calculator M3.3). Executor claude-opus-5-5 wrote `READY-claude-opus-5-5.md` (`agent: claude-opus-5-5`) at 4cfdcb1. A fresh claude-opus-5-5 reviewer session then filed a signed approval, and the gate counted it: `review list M3.3 --ref 4cfdcb1` reported "2/2 distinct-family approvals … met", and the merge carried `Reviewed-by: claude-opus-5-5 (anthropic) approve 4cfdcb1…`.

docs/orchestration.md:9 says "The executor never reviews its own leaf … the gate checks it". `handoff status` already marks a READY author as excluded (M2.3 showed "composer-2.5 (cursor): excluded — executor of the leaf", review_eligible.py). The gate itself, though, reads only the record's self-attested `authored_fix: false`.

Decision on model or family: the exclusion is by **model id**. The docs rule is about the executor itself. Family independence among reviewers is what `reviewers_distinct_families` already judges. Another model of the executor's family is not the executor, so it counts as it does today. Any model that filed a READY on the leaf is excluded, the executor and a fix author alike: this is the same set `handoff status` excludes.

Out of scope: making READY authorship tamper-proof. A READY is an unsigned file the executor writes, so the docs state the check is cooperative unless signing keys are out of the executor's reach. Also out of scope: the RCA-analyst eligibility rule and orchestrate plan's executor exclusion (both unchanged).

Overlaps checked (2026-11-05): M21.18 edits review_deferral.py, review_next_step.py and rework_rca.py, but not review_gate.py (the gate only calls `apply_deferrals`). M21.23 edits docs/orchestration-review.md, which this leaf does not touch. ## Approach

- Make `_writers` (review_eligible.py:42-58) the one public helper, model -> why (executor of the leaf / wrote a fix commit). `handoff status` keeps its wording.
- `evaluate_gate` (review_gate.py:312) calls it with the gate's `branch`. A record whose `model` is a key goes to `ineligible` with `<model> wrote <READY file> on this leaf; the executor never reviews its own leaf`. This holds whatever its flags, verdict or signature, and runs before `_eligibility`. review_eligible.py imports no gate module, so there is no import cycle.
- `review delegate --model M`: refuse before the packet, the lock or any RUN file when M is a writer, naming the READY file (DelegateError, exit non-zero).
