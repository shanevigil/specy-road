## Intent

M16.63 reads both roster forms; this leaf moves every roster to the new one, so the version-1 reader can go when the alias window closes (M16.62). Kestra's 2.0 is the failure mode to avoid: configs that stopped parsing after an upgrade with no migration.

## Approach

- `upgrade` does the rewrite, as it does for the `checks:` block (M16.14) and the grind keys (M16.50), and reports it in the one upgrade report (M16.12).
- The expected output is pinned by files, not prose: the before files are the toolkit's own roster as of pickup and a 0.3.1-shaped sample, and the after files are M16.63's hand-written version-2 equivalents, adjusted here only for comment placement.
- Comments carry vendor quirks in the toolkit's roster, so none may be lost; the fixtures pin where each one lands.
- The toolkit's live `sr/roadmap/orchestration.yaml` is read by the running coordinator, so this leaf does not rewrite it; the maintainer runs `upgrade` on it after merge.
- Depends on: M16.63. The last acceptance line is an informational line-change estimate, not a gate; report `scripts/lean_metrics.py --check` deltas in READY once M16.2 has landed.
- Behaviour-preserving: the parity harness (M16.0) and the review-gate decision table (M16.1) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines.
