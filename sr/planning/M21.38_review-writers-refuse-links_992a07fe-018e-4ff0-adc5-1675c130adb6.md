## Intent

rc4 final review (§3.2, 2026-11-06), the prior-F2 class on the review hand-off. A worker that can plant a symlink under `work/` can make a later review command create or overwrite a file outside the checkout. The affected commands are `review record`, `review accept-policy`, `mark-implementation-reviewed`, a refusal marker, a history copy, delegate's prompt files and the packet, and `prompt --run`'s prompt file. Every writer below moves onto the M21.37 rule (`specy_road/safe_write.py`). Its owned root is the project directory that holds `work/`: `reviews_dir(...).parents[2]`, which is the main checkout's project when a linked worktree asks.

Decisions:

- **Refuse, do not replace.** A symlink at the record, marker, approval, acceptance, packet, prompt or lock name refuses the command with exit 1 and the path named, before anything is written. Dangling links and in-repo links are refused too.
- **Refusals are CLI errors.** `SafeWriteError` is not `ReviewRunBusy`, which is all today's lock callers catch. `review_cli` (review record, accept-policy), `role_prompt` (`prompt --run`) and `mark_implementation_reviewed` translate it at the CLI boundary: `error: <message>` on stderr, exit 1, no traceback. Delegate does the same in `review_delegate`.
- **Live and history together.** `review record` preflights both the live `REVIEW-<model>.md` and the `history/` destination before it writes the live record or clears `REJECTED-<model>.md`. A linked `history/` therefore leaves the old record, the marker and the gate exactly as they were.
- **The tripwire restore keeps its behavior, from a verified root.** `Snapshot` keeps the owned root. Before `Snapshot.restore` traverses anything after a reviewer run (`_symlinks`, unlink, `real_dirs`, `_own_records`), it walks `work` and `work/reviews` with `lstat` from that root. A linked ancestor makes the run a `review_failure` without reading, deleting or writing through it. Below a verified root, `real_dirs` and `replace_file` still replace a final link the reviewer planted, which the run reports as a review failure as today. `replace_file` and `append_log` gain the ancestor walk.
- **`review_run_lock` keeps its signature.** It derives the owned root from `reviews`, so delegate, `prompt --run`, `review record`, accept-policy and the human approval all inherit the lock fix; only their error handling changes.
- **`prompt`'s default file.** `role_prompt` writes `work/prompt-<node>-<role>-<model>.md` (the default when `-o` is omitted, or any `-o` inside the project) through `safe_write` from the project root, before launching. An explicit `-o` outside the project is the person's own destination and stays today's write.
- **`refused_link`.** Its callers in this leaf move to `safe_write`. Remove `refused_link` if nothing else calls it after M21.37 and this leaf.

Out of scope: authenticating who files (policy-sol F1 to F4, honour-system as documented); case-variant names and unreadable acceptance inputs (M22.19).

Overlaps: M21.42 (parse-failure repair turn) edits review_delegate.py first, so this leaf depends on it. M22.16 (rc5) and M22.19 come later.

## Approach

- `review_lock.review_run_lock`:
  - `safe_write.mkdirs(owned, reviews)` replaces `mkdir(exist_ok=True)`.
  - `safe_write.open_lock` replaces `open("a+")` (M21.37's Windows fallback included).
- CLI boundary: `review_cli.cmd_review_record_locked` and the accept-policy command, `role_prompt.main`, `mark_implementation_reviewed._gate_or_human_approval`, and `review_delegate` catch `SafeWriteError` at each lock site and each write site.
- `review_policy_pin.cmd_accept_policy` (POLICY-ACCEPTED.yaml) and `review_gate_ready.write_human_approval` (REVIEW-human.md) write through `safe_write.write`.
- `review_rejected.write_rejected`: the check comes before any mkdir, from the owned root, not the hand-off directory.
- `review_rejected._review_record_finish`: `safe_write.check` on the live record and the history destination first; then write, clear the marker, archive.
- `review_files.write_review` and `archive_review`:
  - `safe_write.check` from the project root before `mkdir` and before the case-variant loop, so the directory listed is a verified real directory.
  - The case-variant unlink removes only an entry whose `lstat` is a regular file or a symlink, as an entry.
  - A dangling link at the name is refused, not written through. `archive_review`'s history mkdir uses the same order.
- `review_delegate._prompt_file` (prompt, `-resume`, `-repair-full`, `-repair`): the write is refused before any launch, so delegate exits 1 without launching. This covers `--resume` with a stored refusal.
- `review_delegate_packet.ensure_packet`: checked from the owned root, so a symlinked `work/reviews/<node>`, `work/reviews` or `work` is refused before the packet is written.
- `role_prompt.main`: the prompt file through `safe_write.write` when it is inside the project.
- `review_write_check`: `Snapshot` keeps the owned root; `restore` verifies `work` and `work/reviews` first; `replace_file` and `append_log` walk the ancestors from the owned root.
