## Intent

rc4 final review (§3.2, 2026-11-06), the prior-F2 class on the review hand-off. A worker that can plant a symlink under `work/` can make a later review command create or overwrite a file outside the checkout. The affected commands are `review record`, `review accept-policy`, `mark-implementation-reviewed`, a refusal marker, a history copy, delegate's prompt files and the packet. Every writer below moves onto the M21.37 rule (`specy_road/safe_write.py`). Its owned root is the project directory that holds `work/`: `reviews_dir(...).parents[2]`, which is the main checkout's project when a linked worktree asks.

Decisions:

- **Refuse, do not replace.** A symlink at the record, marker, approval, acceptance, packet, prompt or lock name refuses the command with exit 1 and the path named, before anything is written. Dangling links and in-repo links are refused too.
- **The tripwire restore keeps its behavior.** `Snapshot.restore` after a reviewer run still removes reviewer-planted links: `real_dirs` and `replace_file` replace a final link, which the run then reports as a review failure. `replace_file` and `append_log` gain the ancestor walk from the owned root, so a symlinked `work/` or `work/reviews` is refused there too.
- **`review_run_lock` keeps its signature.** It derives the owned root from `reviews`, so delegate, `prompt --run` (role_prompt.py:354), `review record`, accept-policy and the human approval all inherit the lock fix with no change to their callers.
- **`refused_link`.** Its callers in this leaf move to `safe_write`. Remove `refused_link` if nothing else calls it after M21.37 and this leaf.

Out of scope: authenticating who files (policy-sol F1 to F4, honour-system as documented); case-variant names and unreadable acceptance inputs (M22.19).

Overlaps: M21.42 (parse-failure repair turn) edits review_delegate.py first, so this leaf depends on it. M22.16 (rc5) and M22.19 come later.

## Approach

- `review_lock.review_run_lock`:
  - `safe_write.mkdirs(owned, reviews)` replaces `mkdir(exist_ok=True)`.
  - `safe_write.open_lock` replaces `open("a+")`, with `O_NOFOLLOW` and a regular-file check. On Windows, a link is refused before open.
  - A refusal is a normal CLI error: `filing_busy`-style wording, no traceback.
- `review_policy_pin.cmd_accept_policy` (POLICY-ACCEPTED.yaml) and `review_gate_ready.write_human_approval` (REVIEW-human.md) write through `safe_write.write`.
- `review_rejected.write_rejected`: the check comes before any mkdir, from the owned root, not the hand-off directory.
- `review_files.write_review` and `archive_review`:
  - The case-variant unlink stays, and it never follows a link.
  - A dangling link at the name is refused, not written through.
- `review_delegate._prompt_file` (prompt, `-resume`, `-repair-full`, `-repair`): the write is refused before any launch, so delegate exits 1 without launching. This covers `--resume` with a stored refusal.
- `review_delegate_packet.ensure_packet`: checked from the owned root, so a symlinked `work/reviews/<node>`, `work/reviews` or `work` is refused before the packet is written.
- `review_write_check.replace_file` and `append_log`: walk the ancestors from the owned root; behavior at the final path is unchanged.
