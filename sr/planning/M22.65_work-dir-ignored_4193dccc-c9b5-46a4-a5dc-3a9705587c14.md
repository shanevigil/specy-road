## Intent

`chore start` writes `work/chores/<slug>.json` and `chore close` writes `work/chores/<slug>.md`. Nothing ignores them, so a reviewer of an unrelated leaf in the same clone finds untracked files, fails its clean-tree precondition and blocks without reading the diff. Found in field use of 0.3.1rc4.

Maintainer decision (2026-11-09): everything in `work/` is gitignored, child directories included. So a chore record never shows as untracked work, and every clean-tree check agrees with git without a list of its own. Implementation summaries are therefore no longer committed by default.

## Approach

- **The ignore rule.** The `.gitignore` rules a project gets are the managed block that `init project`, `specyrd init` and `refresh-stubs` write from `agent_ignores.GITIGNORE_LINES` (`specy_road/agent_ignores.py:78-89`; `templates/project/.gitignore` holds only the comments above it). Today the block lists `work/` paths one by one: session files, `work/reviews/`, `.sessions/`, `.workers/`, `.worktrees/`, `work/chores/.garden.json` ("chore records beside it are left to the project", `:82`) and the brainstorm prompts. One line, `work/*`, replaces all of them. That covers every file and child directory, `work/chores/` and `work/done/` included. `work/*` is used rather than `work/` so that the re-include lines below work, since git cannot re-include under an excluded directory, and `*` does not cross `/`.
- **Scaffold files stay tracked.** `init project` ships `work/README.md`, `work/.gitkeep` and three top-level `work/*.template.md` files that prompts cite by project path (`work/review-record.template.md`, `role_prompt_rca.py:229`; `work/handoff-ready.template.md`, `do_next_prompt.py:287`). Ignored, they would be missing from a fresh clone or linked worktree until `upgrade` restored them. The block re-includes exactly those (`!work/README.md`, `!work/.gitkeep`, `!work/*.template.md`). They are specy-road's scaffold, not work, and the exception is needed under today's design (moving the templates into the package is M23). `_prefixed` (`agent_ignores.py:100`) today does `prefix + line`, which would write `sr/!work/README.md`; it learns to put the project prefix after a leading `!` (nested layout: `!sr/work/README.md`).
- **The clean-tree checks need no code change.** The reviewer's check is `git status --porcelain --untracked-files=all` (`role_prompt_rca.dirty_check`, `:63`), and reconcile lists untracked files with `--exclude-standard` (`worker_reconcile._untracked`, `:79-84`). Both hide ignored paths, and both still see changes to files git tracks. `RUNTIME_WORK_DIRS` and the per-leaf exclusions stay as they are, for repositories whose block has not been refreshed yet.
- **The implementation summary is no longer committed by default.** With `work/*` ignored, `work/implementation-summary-<ID>.md` is ignored. Prompts already follow the ignore rule and never tell a worker to force-add (`git-workflow.schema.json` `implementation_summary`; `workflow_prefs.implementation_summary_rule`, `:100`), and with `work/*` ignored the rule already resolves to local (`workflow_prefs.py:109-110`). But `validate` prints a notice when the setting is `commit`, which is the default, and the summary is ignored (`summary_rule_notice`, `:114`). The project template's `roadmap/git-workflow.yaml` therefore sets `implementation_summary: local`, so a new project starts quiet; an existing project gets the notice, which names the fix. **A reviewer in another clone does not see the summary**: the review packet reads it from the leaf's worktree (`review_packet_uncommitted_refs.py:93-103`). The docs say so in those words.
- **Template comments and docs.** The comment block in `templates/project/.gitignore`, `templates/project/work/README.md`, `docs/git-workflow.md` (the `cleanup_work_artifacts_on_finish` paragraph and the `work/done/` archive) and `docs/git-workflow-preferences.md` say: `work/` runtime artifacts are ignored by default; `README.md`, `.gitkeep` and the top-level `*.template.md` files stay tracked as scaffold; a project may re-include other paths (`work/worker-logs/`, `work/done/`) after the block; files already tracked under `work/` stay tracked until the printed `git rm --cached`; implementation summaries are local by default, and a reviewer in another clone does not see them. Today's text that keeps briefs, summaries and brainstorm sessions tracked on purpose goes.
- **Upgrade path, no new code.** `upgrade` runs `refresh-stubs`, which rewrites the block through `apply_and_report` (`agent_ignores.py:176`). That already lists the tracked files the new rules reach and prints the `git rm --cached -- <paths>` command, never running it (`ignore_report`). Git keeps tracking those files until the adopter runs it. The CHANGELOG entry says so, and says the summary default changed.
- **The toolkit's own checkout.** The root `.gitignore` managed block is re-rendered by `refresh-stubs` (`sr/` layout). In the same change, the toolkit's tracked `sr/work/done/` archive is untracked with `git rm --cached -r sr/work/done/`, its files kept on disk (maintainer decision). `sr/` is stripped before promotion, so this does not ship. The other files the toolkit tracks under `sr/work/` are not part of this leaf and stay tracked.

## Tier

trust boundary: with `work/` ignored, the reviewer precondition, `delegate`'s uncommitted-work check and reconcile stop seeing untracked files under `work/`, and the implementation summary is no longer bound to the commit.

## Done but wrong

- `work/` (not `work/*`) is written, so no project can re-include `work/worker-logs/` or the scaffold: the re-include row.
- The scaffold templates are ignored, and a fresh clone's prompts cite missing files: the scaffold row.
- The checks' own exclusion lists are widened to all of `work/`, which hides changes to files a project still tracks under `work/`: the tracked-still-seen row, and `RUNTIME_WORK_DIRS` and `dirty_check` stay source-identical.
- `upgrade` runs `git rm --cached` itself: the upgrade row expects the command printed and the file still tracked.
- The docs keep saying the summary is committed, or say nothing about a reviewer in another clone: the acceptance names that sentence.

## Zones

Zone changes are the coordinator's. The coordinator adds any needed exact path (a parity golden or transcript under `tests/parity/`, the rc3 consumer fixture's `.gitignore`) before execution. Otherwise the executor stops and names the path and its before/after fragment; it does not edit the node.

## If this fails

Assumption: no specy-road command needs a `work/` file other than the scaffold to be committed. Known users of committed `work/` files are the summary archive under `work/done/` (`finish_work_artifacts._archive_tracked_summary`), the worker-log commit (`worker_logs_to_stage`) and the packet's committed-summary read (`review_packet_uncommitted_refs._committed_or_disk`). Each of them already skips or falls back when the path is ignored or untracked. If a test shows a command failing rather than falling back, stop and name the command; the coordinator decides.

## Accepted limits

- A reviewer in another clone does not see the executor's summary; the packet reads it from the leaf's worktree, as `implementation_summary: local` already does.
- Brainstorm sessions (`work/brainstorm-*.yaml`) and new `work/done/` archives are no longer committed by default. A project that wants them adds its own re-include after the block.
- Files a project already tracks under `work/` stay tracked until it runs the printed `git rm --cached`.
