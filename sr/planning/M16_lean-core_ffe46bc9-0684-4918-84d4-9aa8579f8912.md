## Intent

Make specy-road smaller and more coherent without removing any delivered capability. Growth since v0.2.3 (package 31k to 65k lines, tests 25k to 65k, 45 to 68 top-level commands) came mostly from orchestration and the review gate, which the maintainer ruled canonical core (2026-11-05, decision D1), and from narrow patches per review round. M16 consolidates structure, commands, config, tests and docs; workers and orchestration stay in core and get one internal subpackage with one state model that the 0.3.2 PM GUI can read. Planned for release candidate rc5 (rc4 is fixes only); version numbers stay with the maintainer.

## Approach

- **Rules for every leaf.** Behaviour-preserving (the parity harness M16.0 and the review-gate decision table M16.1 stay green); a declared expected net line delta, met or explained (only M16.0, M16.1, M16.2, M16.20, M16.22, M16.26 and M16.27 are additive, by design); no new config key, policy key or command without retiring one (the `checks:` block in M16.14 is the named exception); old commands and config forms stay as one-release aliases until M16.33; adopter feedback is parked until M16 ends.
- **Post-fix refactor (maintainer, 2026-11-05).** No leaf's diff raises a function above its merge-base C901 score or adds `noqa: C901`; fix rounds end with a consolidation step. M16.22 makes this a product gate.
- **Order and lanes.** Pass 0 (M16.0-M16.2) gates everything. Code lane: dead code, helpers and the roadmap index (M16.3-M16.5, parallel), then layering (M16.6, serial), in-process dispatch (M16.7), folds (M16.9, M16.10), surface (M16.11-M16.13, serial on cli.py), config (M16.14), orchestration (M16.15 interface first, then M16.16-M16.19 one sub-area each), review (M16.20 evidence, M16.21 fold), complexity gate (M16.22). Test lane (M16.23-M16.28) runs alongside from M16.2. Docs lane (M16.29-M16.32) runs alongside from the start; prompts wait for the final command names. M16.33 closes the alias window after a release; M16.34 is the maintainer's triage of held leaves.
- **File size.** The toolkit cap is already 1,000 lines with a 750 warning (commit 1d4af684). M16.8 adds the 100-character width rule with a shrink-only baseline; folds target files under 750 lines and rewrap what they touch.
- **Orchestration restructure** is the riskiest pass: interface and state model first (M16.15), then move code behind it one sub-area at a time, each behind the parity harness. The snapshot model is the interface for the 0.3.2 GUI orchestration and worktree views.
