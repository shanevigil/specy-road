## Intent

Today a leaf is escalated by round count (`escalate_review_rounds`, `policy.max_fix_rounds`). The 2026-11-11 review-blocks retrospective found the risk in what a candidate changes: one rc5 escape came from a fix round on review-gate code, and 24 of 174 landings carried integrity findings that nobody judged. This leaf reports, for the whole candidate diff, the triggers a project may later hold on (M18.31): tests weakened, a plan change, a risk path, a declared file. It reports only; nothing it prints changes an exit code or the gate. It is the report half of the landing holds in `sr/work/planner-2026-11-11-review-rules/proposal-v2.md`.

**Out of scope:** holding the gate (M18.31); the grind's trust replay; changing `escalate_*` or `max_fix_rounds`; sending fix rounds (M18.21).

## Approach

- New `specy_road/review_fix_risk.py`. The diff is merge base to commit, minus files whose only change came from merging the integration branch. Earlier blocked commits come from `history/`, as `handoff status` counts rounds, and only say when each trigger first appeared.
- Reuse the `specy-road integrity` checks for `test_weakened`; do not write a second detector.
- Read `planned_test_changes`, acceptance, zones, dependencies and the sheet's Tier from the integration branch with git, never from the leaf branch, so an executor cannot exempt its own change.
- A trigger that cannot be computed is `unknown`, never an empty list.
- The two glob lists go in `orchestration.yaml` with the other `policy.*` keys (schema, template and `sr/` copy).

## Tier

trust boundary: the leaf changes what `handoff status` reports and lives in review code (`review_cli.py`, a TRUST path in `sr/tools/tier.py`).
