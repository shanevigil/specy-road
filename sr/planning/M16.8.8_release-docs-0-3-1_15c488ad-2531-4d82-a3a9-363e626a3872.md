## 1. Section 3 intro: after the paragraph ending "This is a release-readiness branch, not the release branch."

An agent runs this section in agentic sandbox guests
([agentic-sandbox-runbook.md](agentic-sandbox-runbook.md), "Driving a guest
over MCP"), before Section A, on a wheel built from the candidate branch head.
No harness credential, key or token is copied to a guest: a step that needs a
harness login (the 3.2 review skills, signed-in harness scenarios) runs in a
session that already has one, or is recorded as skipped with that reason.

the toolkit tree (for example under `/tmp/specy-road-pre-release-apps/`):

## 3. Section 3.3, replace the paragraph beginning "Install the candidate toolkit from the `WIP/pre-release-checks` checkout"

Build a wheel at the `WIP/pre-release-checks` head (`python -m build --wheel`),
install it with the `[gui]` extra into a fresh virtual environment on the
guest, and use that `specy-road` executable for all app tests, never an
editable install. Record the commit, the wheel file name and its sha256. Each
app must be a real git repo with a configured remote (a local bare remote is
fine) so registry and branch workflows exercise the same assumptions as users'
repos.
