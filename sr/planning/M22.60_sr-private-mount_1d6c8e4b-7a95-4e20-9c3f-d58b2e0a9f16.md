## Intent

The toolkit's own roadmap, `sr/`, is tracked on the WIP line, which is the remote's default branch. Its planning sheets, work summaries, tools and roster carry process content and past personal data. In the final pass, before the 0.3.1 tag, `sr/` moves to a private, separately cloned repository mounted at `sr/`. The toolkit repository then holds no roadmap, and the coordinator's roadmap commands, grind tooling and worker wrappers keep working from the mount. This leaf is held for the maintainer: the coordinator dispatches it only on the maintainer's word. Source: the maintainer's scrub plan (private), sections 3 and 4, approved 2026-11-09.

## Approach

- **Private repository:** create a local clone that starts from the WIP `sr/` tree. Whether that is a history import or a fresh first commit is the coordinator's choice. No tracked file, commit message or sheet names the repository or its URL. Creating the private remote is the operator's step; until the operator gives a remote, the leaf works against a local bare repository.
- **Toolkit repository:** `git rm -r --cached sr/` and `.specyrd/manifest.json`; add `/sr/` and `.specyrd/manifest.json` to `.gitignore`; drop the `sr/` lines in `.gitignore` and `.cursorindexingignore` that only served the tracked tree. The local `.specyrd/manifest.json` keeps `project_root: sr`.
- **Keep the tooling working from the mount:** validate, export, digest, brief, pickup with `--worktree`, finish, review-packet, `grind-session --plan`, and worker delegate and sync. A leaf's worktree needs its own `sr/` mount; claims and roadmap bookkeeping commit to the private repository; code lands in the toolkit repository. The `sr/tools` wrappers run from the mount.
- **Docs:** `docs/toolkit-development.md` and AGENTS.md say how a maintainer mounts `sr/`, without naming the repository. AGENTS.md's load-order line for `sr/` work points at the mount.

## Tasks / checklist

- [ ] Private clone from the WIP `sr/` tree (local bare remote until the operator provides one)
- [ ] Untrack and ignore `sr/` and `.specyrd/manifest.json`; prune the old ignore lines

- [ ] Run each listed command once from a mounted checkout and record the result in this sheet; docs

## Tier

trust boundary: it moves the registry, claims and review bookkeeping that the gate and finish read, and a mistake can lose roadmap state or land code against the wrong roadmap.

## Done but wrong

- Roadmap state is lost: after the move, `validate`, `export --check` and `digest --check` from the mounted checkout pass, and the private repository's tree equals the WIP `sr/` tree at the leaf's base, file for file.
- A worker leaf sees no roadmap: a `do-next-available-task --worktree` leaf worktree has `sr/` mounted, its claim commit is in the private repository, and `finish-this-task` lands its code in the toolkit repository and its status in the private one.
- The name leaks: `git grep` over the toolkit tree and `git log --format=%B` over the leaf's commits find no private repository name or URL.

## If this fails

Assumption: the toolkit can run with a project root that is its own git repository, separate from the code repository, the way `nested_repos` handles repositories below the project root. If a command assumes one repository for both (registry commits, finish landing, review-packet diffs, worker reconcile), stop and list each command and the module; the coordinator decides whether a product fix comes first.

## Accepted limits

- History is untouched here: `sr/` stays in the toolkit repository's history until the rewrite (M22.58, M22.59).
- Every machine and worktree needs a one-time mount; the docs say how, and M22.59 re-clones them anyway.
- Leaves that name `sr/` paths in their zones keep them; the paths resolve in the mount.
