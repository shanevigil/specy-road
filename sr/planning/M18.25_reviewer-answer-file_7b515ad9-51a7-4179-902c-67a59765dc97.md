## Intent

A reviewer launched through a `channels.cli` command must today print exactly one JSON object and nothing else (review_answer's generic row), so every wrapper re-implements answer extraction and transcript keeping: `codex-review.sh` prints only `codex -o`'s file, `cursor-review.sh` and `claude-review.sh` pipe through `last-json.py`, and each keeps a side transcript. Give the channel an `{answer}` file the way the native codex reviewer already has one, and keep the transcript beside the run record.

**Out of scope:** relaxing M8.3's strict final-answer rule (the answer file must still be one complete JSON object); the native reviewer commands; executor channels.

## Approach

- `{answer}` reuses `answer_scratch` (the path native codex `-o` writes to, outside the checked tree). With it, stdout and stderr are transcript only, written to `RUN-<model>.log`.
- An empty answer file shows the transcript tail, because a provider usage-limit or capacity message was otherwise hidden behind "output ends with no JSON object" (RE 2026-11-04 Ubuntu; RE Open on reviewer runs ending without a record).
- Two validate warnings from the Linux session: `<prompt>` as text fails with E2BIG above 128 KiB, and codex `workspace-write` makes the post-run write check refuse (RE 2026-11-04 Ubuntu). `placeholder_problem` already inspects channel templates.
- Depends on M16.5.3 (role prompts move into orchestration), M16.5.5 (`run:` command field) and M18.16 (a RUN record for every channel).
