## Intent

After M22.60, the current tree is clean, but history still holds the process content, past home paths, private identities and session links. The rewrite and the force-push are operator-only and irreversible, so the operator needs evidence before running them: a rehearsal on a mirror, a passing scan over every reachable commit, and a script that prints the publication commands without running them. Final pass, before the 0.3.1 tag. Source: the maintainer's scrub plan (private), sections 3 and 4, approved 2026-11-09.

## Approach

**Preconditions.** The operator has set the public author identity in M22.54's allow file and decided whether the personal address is on the local list. Commit objects rewritten to a placeholder cannot be repaired later, so the rehearsal stops before filter-repo while the entry is the placeholder or absent. `git-filter-repo` is installed in the rehearsal environment and is not added to the project.

Work only on a fresh `git clone --mirror` with the pull-request refs fetched. Never use a working checkout, and never push. First record every head, tag and pull-request ref with its SHA (`git ls-remote origin` saved before the rewrite, since filter-repo removes `origin`). Then run `git filter-repo` with:

- `--invert-paths` for these repo-root prefixes: `sr/`, `docs/design-notes/`, `scripts/census/`, `scripts/review_effort_study.py`, `.cursor/rules/`, and the pre-`sr` roots of the old toolkit roadmap (`planning/`, `roadmap/`, `work/`, `prompts/`, `gui-spike/`, `vision.md`, `project-design-for-claudeandcursor.md`). A prefix with no commit in history is omitted and named in the evidence. A path the WIP tip still tracks is never inverted: `work/.gitkeep` and `work/README.md` are product files, so `work/` is inverted except those (a path regex, not a plain `--path`). `scripts/lean_metrics.py` is inverted only when the tip no longer tracks it.
- `--replace-text` for home paths, and for account-directory and private names read from M22.54's untracked local list.
- `--mailmap` that maps only the identities on M22.54's local list (university domain, hostname, localhost, and the personal address only when the list holds it) to the operator-set public identity. The callback reads the same list and embeds no name.
- `--message-callback` that deletes `Claude-Session:` lines, rewrites `sr/work`, `sr/planning`, `sr/roadmap` and `sr/tools` mentions to `<private>`, and removes local-list names. `Co-Authored-By:` tool trailers stay.

**Scan.** Over an explicit inventory of all mirror refs, run M22.54's applicable rules, with no WIP `sr/` exemption, on every reachable commit: its paths and text blobs (each blob once), its message and its author and committer identities. Tips alone are not enough: a value added and deleted in between is still retrievable. The checkout scanner reads `git ls-files`, which a bare mirror does not have, so an untracked rehearsal driver feeds blobs and messages to M22.54's rules through M22.57's no-index directory mode and `--commit-msg`. A hit at one of the shipped product paths still on the pre-rewrite tip and not inverted (`specy_road/templates/project/research/README.md`, `…/work/handoff-ready.template.md`, `specy_road/templates/specyrd/commands/specyrd-prompt.md`, `…/specyrd-handoff-status.md`, and their copies under `tests/parity/fixtures/rc3_consumer/`) is recorded, not failed. Any other hit, or a scan or read failure, stops the rehearsal. A local fixture with a forbidden value introduced and deleted before the tip must fail the scan.

**Evidence** goes to an untracked folder outside every tracked tree and is never committed:

- the recorded source ref SHAs;
- the old-to-new SHA map for every branch and tag;
- the saved `refs/pull/*` list (pull-request refs still holding old commits);
- the scan output;
- the operator script.

The implementation summary records the folder as a placeholder path, and the sha256 of the script and of the scan output, so reviewers and the operator inspect the same files.

**Operator script.** It never pushes. It refuses while the public identity is unset or differs from the mailmap target, and when the source's heads and tags differ from the recorded inventory (moved, added or removed); drift needs a new rehearsal. Otherwise it stops after checking the rewritten mirror and the map, and prints, in separate sections:

1. branch updates for `refs/heads/*`, each with an expected-old-tip lease, under a note that a push to `main` runs `.github/workflows/main-release-tag-gate.yml`, which can create a tag;
2. tag updates, under a warning that pushing `v*` tags starts `.github/workflows/release-publish.yml` (an RC tag publishes to TestPyPI with no reviewer), so the operator disables or guards that workflow first;
3. the new-repository commands; a new destination must be selected explicitly and verified empty.

`refs/pull/*` are listed for the Support request and never pushed.

## Tier

trust boundary: it prepares an irreversible history rewrite of the public repository; the operator acts on its evidence.

## Done but wrong

- The rewrite misses a ref: the SHA map has one row for every branch and tag in the recorded inventory, and the scan output covers each of them.
- Only the tips were cleaned: the added-then-deleted fixture fails the scan, and the real scan reports per-commit coverage.
- File content changed beyond the rules: for the WIP tip, `git diff --stat <old> <new>` is empty apart from the inverted paths and the listed replace-text substitutions.
- A product path was inverted: `work/.gitkeep` or `work/README.md` is absent from the rewritten WIP tip.
- The script can publish: with the identity unset it exits non-zero and prints nothing pushable; with the identity set and a moved source ref it refuses; with everything matching it executes no `git push` and no `gh` call, and its tag section carries the release-publish warning.

## If this fails

Assumption: the operator has replaced the public-identity placeholder before the run, and filter-repo can rewrite the mirror in one run. If a ref cannot be rewritten, list it and stop; the operator chooses the route. If the history-wide scan cannot finish in one run, stop and name the ref it stopped on; do not narrow the scan to tips.

## Accepted limits

- Pull-request refs on GitHub cannot be force-pushed; only the Support request (M22.59) purges them.
- Forks and existing clones keep old history.
- Binary blobs are scanned for paths only, not content.
- Removing paths changes every commit since 2026-04 and every tag, including releases published on PyPI; provenance that cites old SHAs breaks.
