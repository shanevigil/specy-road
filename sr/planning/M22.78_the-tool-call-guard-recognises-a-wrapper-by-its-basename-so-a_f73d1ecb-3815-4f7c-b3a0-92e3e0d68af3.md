## Intent

The fourth gap in the tool-call guard, found 2026-11-19 after M22.77. The guard reads git by the basename of the word, but its wrapper list (env, sudo, command and the rest) matches the bare word only, so `/usr/bin/env -S "git stash"` and the other path-qualified spellings classify as allowed. This leaf reads every wrapper by its basename, as git already is, and the enumerated wrapper test from M22.77 gains the path-qualified forms, so a new spelling of an existing case cannot slip past. Operator: "M22.78 ok" (RC blocker).

## Approach

- Reduce a wrapper word to its basename where the guard already does this for git; reuse that helper rather than adding one.
- Extend the M22.77 enumerated test with `/usr/bin/<w>`, `/bin/<w>` and `./<w>` forms; compare each wrapped verdict and reason with the bare form.
- No rule-table rewrite; that is M23.8.
- Depends on: M22.77. M16.8.4 depends on this leaf.

## Tier

trust: it changes the guard that refuses destructive commands.
