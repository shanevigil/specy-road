## Added 2026-11-07 (maintainer)

A field run found the default launch (`--sandbox enabled`, no `--force`) could not commit in a linked worktree: `git add` failed on `index.lock`, and no `permission_denied` event was logged. Adding `--add-dir` for the git directories fixed it, still sandboxed. Check this on the sandbox machine and fix it here. The default grants only the reviews folder (`_add_dir`), which matches the report.

## Tier

trust boundary: acceptance line 4 changes what the default Cursor launch lets a sandboxed worker write, or adds a delegate refusal.

## Done but wrong

- The commit works because the run was not sandboxed: the launch argv in the run log has `--sandbox enabled` and no `--force`.
- The grant reaches more than the worker needs: an executor launch adds only the reviews folder plus the worktree's gitdir and common dir; a reviewer launch adds nothing new.
- A denial stays silent: a run with the git grant removed emits `permission_denied` in the worker events.

## If this fails

Most likely to break: no machine where the sandbox starts is available, or the sandbox still denies git with the grant. Then the leaf takes acceptance's other branch: delegate refuses an executor that cannot commit. The maintainer decides which branch ships.
