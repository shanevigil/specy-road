## Intent

Make every refusal a user hits actionable: a non-zero exit says what failed, why, and the next command to run. The three cases here come from rc3 sandbox notes and each cost a round trip to diagnose: `remove-dependency` reported `[ok] … did not list` and exited 0 when given a display id (N1); `abort-task-pickup`'s hint printed a `git worktree remove` that git refuses because pickup leaves an untracked `work/brief-<ID>.md` in the worktree (N3); and `mark-implementation-reviewed` said "working tree is not clean" without naming a single path (N7). The leaf fixes those three and writes the rule down with a test that keeps them honest.

## Approach

- **remove-dependency (N1).** In `cmd_remove_dependency()` in `specy_road/bundled_scripts/roadmap_crud_dependency_ops.py`, resolve the argument with the existing `resolve_dependency_refs()` (the helper `cmd_add_dependency()` already uses), so a display id, a node_key and an archived key behave as in add-dependency. When the resolved key is not in the node's list, exit 1 and print the node's actual dependencies as `id (node_key)` pairs (or "none"), plus `specy-road list-dependencies <ID>`. An argument that resolves to nothing keeps `resolve_dependency_refs()`'s ValueError text, printed as an `error:` line, exit 1.
- **mark-implementation-reviewed (N7).** Add a small helper in `specy_road/bundled_scripts/repo_ops.py` (next to `working_tree_clean()` / `assert_working_tree_clean()`) that returns the porcelain paths outside `work/` (reuse `_OUTSIDE_WORK`), and a formatter that lists at most 20 then "… and N more". Use it at both "working tree is not clean" sites in `specy_road/bundled_scripts/mark_implementation_reviewed.py` (leaf approve and milestone full review) and in `assert_working_tree_clean()` so every caller gains the list. The message says how to clear them: commit, `git stash -u`, or discard, and that `work/` is ignored by the check.
- **abort-task-pickup (N3).** In `_exit_if_base_checked_out_elsewhere()` in `specy_road/bundled_scripts/abort_task_pickup.py`, print a command that works on the worktree pickup left: `git worktree remove --force <path>` (the only untracked content pickup itself writes is `work/brief-<ID>.md`; state that `--force` also discards any other untracked file there, so the hint first prints `git -C <path> status --short` to show what would be lost). A test creates a linked worktree with the untracked brief, runs the printed command string, and asserts the worktree is gone.
- **Rule and test.** `docs/contributor-guide.md` gains a short "Refusals" rule under Project stewardship: non-zero exit prints what failed, why, and a runnable next step. A parametrized test (new `tests/test_refusals_name_their_fix.py`) drives each refusal above through the CLI entry (`specy_road.cli` / subprocess on a temp repo) and asserts exit 1 and that stderr contains a backticked or line-leading `specy-road …` / `git …` command.
- Reuse existing test fixtures in `tests/test_abort_task_pickup.py` and `tests/test_mark_implementation_reviewed_gate.py`; no new entrypoints.
- **Verify.** `pytest -n auto` on the touched tests, `specy-road file-limits`.

## Tasks / checklist

- [ ] A1 — `specy-road remove-dependency <ID> <DISPLAY_ID>` removes the dependency exactly as when given its node_key; naming one the node does not list exits 1 and lists the actual dependencies (no `[ok] … did not list`). Test covers display id, node_key, and unlisted dependency.
- [ ] A2 — Both "working tree is not clean" refusals in `mark-implementation-reviewed` list offending paths outside `work/` (cap 20, then "… and N more") and how to clear them. Test with 1 and with 25 dirty paths.
- [ ] A3 — `abort-task-pickup`'s worktree hint prints a command that succeeds on a worktree holding pickup's untracked `work/brief-<ID>.md`; a test runs the printed command.
- [ ] A4 — `docs/contributor-guide.md` states the rule; one parametrized test runs A1–A3's refusals through the CLI and asserts exit 1 and a runnable next step in the message.
- Out of scope: auditing every other refusal in the toolkit (that is gardening work for M12.3), changing pickup so it stops writing the brief, changing exit codes of any command not listed above, and rewording success output.
