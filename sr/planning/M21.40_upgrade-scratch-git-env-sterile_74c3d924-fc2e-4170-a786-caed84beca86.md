## Intent

rc4 final review (§3.2, 2026-11-06), prior F1 remainder. `upgrade`'s scratch git environment drops only five variables (`_REPO_ENV`, ignore_report.py:57). It keeps every other `GIT_*` variable. With `GIT_CONFIG_COUNT` defining `filter.<x>.clean` and `core.attributesFile`, the scratch `git add` ran a command. With `core.fsmonitor`, `git status` ran a command. Sol also showed that `core.worktree` and `core.hooksPath` survive the strip; a post-commit hook is not suppressed by `--no-verify`. `GIT_CEILING_DIRECTORIES` survives too, so it can hide `.git` from `regenerate`'s `git ls-files`. The scratch git calls also have no timeout, and a failed `add` or `commit` is ignored.

Decisions:

- **Drop by prefix.** Drop every variable whose name starts with `GIT_`, rather than growing the denylist.
- **The scratch repository reads no caller config.** Dropping `GIT_CONFIG_GLOBAL` / `GIT_CONFIG_SYSTEM` / `GIT_CONFIG_NOSYSTEM` does not make the global and system files unreachable: git then reads the defaults (`$HOME/.gitconfig`, the XDG file, `/etc/gitconfig`), and a `core.fsmonitor` or `filter.<x>.clean` there still runs on the scratch `git add`. So after the strip, the scratch environment sets `GIT_CONFIG_NOSYSTEM=1` and points `GIT_CONFIG_GLOBAL` at an empty file in the scratch temp directory. `scratch_environ` installs this for the whole dry run, so validate's own git calls on the copy read no caller config either. The scratch commit already passes its own `user.name`, `user.email` and `commit.gpgsign`.
- **The live checkout keeps the caller's config.** `regenerate`'s `ls-files` runs in the caller's checkout (`tracked_in`), not the scratch copy. It uses the prefix strip of the caller's environment, without the config isolation, so the caller's own global config (for example `safe.directory`) still applies there, and `GIT_CEILING_DIRECTORIES` no longer hides `.git`.
- **No hooks.** The scratch repository gets no hooks. `git init` uses `--template=<an empty directory in the scratch temp>`, and every scratch call (`init`, `add`, `commit`) passes `-c core.hooksPath=<an empty scratch directory>`.
- **Timeouts and failures.** Route upgrade's git calls through `git_subprocess.run`, which has a 60 s default timeout and gains an `env=` keyword. `ignore_report._git` already passes `timeout=60`; it keeps its own call, needs the stdin bytes, and uses the new env. A timeout or a non-zero exit of scratch `init`, `add` or `commit` prints `error: git <command> failed in the temporary copy (<reason>)`, returns 2, and neither applies the plan to the copy nor validates it. For `ls-files --error-unmatch`, exit 1 means untracked, as today; any other exit or a timeout aborts with the same error before a generated file is written.

## Approach

- `ignore_report.scratch_git_env(isolate: Path | None = None)`: `{k: v for k, v in os.environ.items() if not k.startswith("GIT_")}`; with `isolate`, also `GIT_CONFIG_NOSYSTEM=1` and `GIT_CONFIG_GLOBAL=<isolate>/empty-gitconfig` (created empty). `_REPO_ENV` is removed.
- `upgrade_generated.scratch_environ(tmp)`: installs the isolated environment for the dry run and keeps the caller's saved environment, from which `regenerate` builds the prefix-stripped env for the live `ls-files`.
- `git_subprocess.run(..., env=None)`; `env=None` keeps today's inherit for other callers.
- These calls go through `git_subprocess.run`:
  - `upgrade_plan` Mirror `git init` (with `--template=<empty dir>` and `core.hooksPath`);
  - `upgrade.py`'s `add` and `commit` (with `core.hooksPath`);
  - `upgrade_generated.regenerate`'s `ls-files` (live checkout, prefix strip only).
- `upgrade.py`'s dry run checks each scratch call's result as above, replacing today's `.git`-exists check.
