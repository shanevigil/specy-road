## Intent

rc4 final review (§3.2, 2026-11-06), prior F1 remainder. `upgrade`'s scratch git environment drops only five variables (`_REPO_ENV`, ignore_report.py:57). It keeps every other `GIT_*` variable. With `GIT_CONFIG_COUNT` defining `filter.<x>.clean` and `core.attributesFile`, the scratch `git add` ran a command. With `core.fsmonitor`, `git status` ran a command. Sol also showed that `core.worktree` and `core.hooksPath` survive the strip; a post-commit hook is not suppressed by `--no-verify`. `GIT_CEILING_DIRECTORIES` survives too, so it can hide `.git` from `regenerate`'s `git ls-files`. The scratch git calls also have no timeout.

Decisions:

- **Drop by prefix.** Drop every variable whose name starts with `GIT_`, rather than growing the denylist.
- **No hooks.** The scratch repository gets no hooks: `git init --template=` with an empty scratch template, and the preview commit runs with `-c core.hooksPath=<empty scratch dir>`.
- **Timeouts.** Route upgrade's scratch git calls through `git_subprocess.run`, which has a 60 s default timeout and gains an `env=` keyword. `ignore_report._git` already passes `timeout=60`; it keeps its own call, needs the stdin bytes, and uses the new env.

Out of scope: the caller's own global or system git config (not reachable through the environment once `GIT_CONFIG_GLOBAL` / `GIT_CONFIG_SYSTEM` are dropped).

## Approach

- `ignore_report.scratch_git_env()`: `{k: v for k, v in os.environ.items() if not k.startswith("GIT_")}`, and `_REPO_ENV` is removed. `upgrade_generated.scratch_environ` already installs this environment for the whole dry run, `validate` included.
- `git_subprocess.run(..., env=None)`.
- These calls go through `git_subprocess.run(env=scratch_git_env())`:
  - `upgrade_plan` Mirror `git init` (with `--template=`);
  - `upgrade.py`'s `add` and `commit` (commit with `core.hooksPath`);
  - `upgrade_generated.regenerate`'s `ls-files`.
- A timeout or failure is reported the way a failed scratch `git init` is today; nothing hangs.
