## Intent

Three lows in reviewer runs (rc4 re-test 2026-11-06):

- **D15c, Low: the refusal summary is cut mid-word.** The summary reads "review record refused the output: indings entry and every observation line…" or "…: eds that line: say on it…". `file_review` keeps the last 400 characters of `review record`'s output (`said[-400:]`), so the line starts at an arbitrary offset. The full text is only in `REJECTED-<model>.md`.
- **D17, Low: a capacity failure gets a false second reason.** After four `RetriableError: [resource_exhausted]` attempts on Cursor, the summary read "capacity error after 4 attempt(s): …; rerun requested: line 15 of the final turn is not one JSON object (a cut-off or stray line)". Line 15 was the harness's error line. There was no final answer, but `_delegate_locked` still parsed the last attempt's output and joined that reason.
- **D18, Medium-Low: Cursor reviewer children outlive the run.** After a Cursor `review delegate` exited, its `worker-server` (ppid 1) and that process's `typescript-language-server --stdio` children were still alive. They were in the delegate's own process group, with their cwd in the checkout. `run_logged` launches the reviewer in the caller's process group and only waits for the main process. M21.29 fixed the same thing for `worker terminate` (the group, then descendants outside it).

Decisions:

- **D15c.** The summary names the first offending line whole and points to `REJECTED-<model>.md` for the rest. M21.35 already sends the whole text to the repair turn.
- **D17.** A run whose last attempt ended with a capacity error has no answer to parse.
- **D18.** The reviewer gets a session and process group of its own (`start_new_session=True`), and specy-road ends that group when the run ends. Ending the group is what catches a child that re-parented to init but stayed in the group, the observed case. Descendants that left the group with `setsid` before the harness exited lose their parent link at exit. They are out of scope here; M21.29's descendant walk needs a live parent.

Overlaps checked (2026-11-06):

- M21.35 (rc4) edits review_record_write.py and review_delegate.py, so this leaf depends on it.
- M21.29 (landed) owns worker_process.py's group-ending code. This leaf only lets that code take a pgid without a worker record.
- M16.2.2 (after 0.3.1) lists reviewer_run_failure.py, which this leaf does not touch.

## Approach

- **D15c.** `file_review`'s refusal Outcome reason is built by a helper:
  - It takes the first offending line from `review record`'s output (`offending_lines` format), verbatim with no length cap, plus a count of the rest and the REJECTED path.
  - `review_delegate.py:308` (immediate and resumed repair failures) uses the same helper instead of `[-400:]`.
  - `Outcome.refusal`, from M21.35, keeps the whole text.
- **D17.** In `_delegate_locked` and in `_repair` (immediate and resumed), when `reason` comes from a capacity error, the answer passed to `file_review` is a `Rerun` with an empty reason. The run reason is then the capacity reason alone, and no snapshot or tripwire behaviour changes.
- **D18.** In `run_logged` and `delegate_turn` (review delegate's own Popen):
  - `Popen(..., start_new_session=True)`, with the pgid kept.
  - Watch the direct child's exit apart from stdout EOF (a background child holding the pipe would otherwise block the drain). On its exit, an interrupt, or an exception while reading output, call a pgid-level helper split out of `worker_process._end_group`: SIGTERM, a grace period of 5 s, then SIGKILL, then drain the rest within a bound. Signal only while the group has a member (an empty group's id can be reused), never the caller's own group; `kill_group`'s identity checks stay. `ProcessLookupError` means the group is gone.
  - Because the reviewer no longer receives the terminal's Ctrl-C directly, the interrupt path ends its group.
