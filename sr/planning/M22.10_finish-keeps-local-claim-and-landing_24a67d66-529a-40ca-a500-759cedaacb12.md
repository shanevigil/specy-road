## Intent

Two finish-path warnings from the rc4 checks, deferred to rc5.

- Finish W1 (grok and sol). For a leaf that still holds its claim, `reconcile-branch` passes `drop_row=False` (reconcile_branch.py:79-80). That only clears the codename. `_registry_from` (finish_pr_merge.py:56-86) still checks out the fetched integration registry byte for byte. After a `do-next-available-task --local` pickup, the claim was never pushed. If the remote integration branch has moved, the reconcile merge replaces the branch's registry and the unfinished leaf's claim disappears. Finish then cannot find the row. `test_reconcile_keeps_the_row_of_a_leaf_that_has_not_finished` covers only a claim already on the remote.
- Finish W3 (sol). Both landing paths return failure when the final `git checkout <feature>` fails after the integration merge succeeded (finish_land_local.py:70-75; finish_land_integration.py:378, which in push mode has also already pushed). In merge mode, `merge_landing_failed` then runs `undo_bookkeeping` (finish_modes.py:371-377) and resets the feature branch to its pre-finish snapshot, while integration keeps the completion. One reachable trigger: a `post-checkout` hook that exits non-zero.

Out of scope: the rest of the reconcile merge (registry rows of other leaves still come from the integration ref); PR mode; nested-repo landing; retry or recovery commands.

Overlaps checked (2026-11-05): M21.22 (rc4) changes only the schema text and the finish stub. M21.14 (Complete) changed finish's chunk-conflict resolution in finish_pr_merge; this leaf touches `_registry_from` only.

## Approach

- `_registry_from` when the leaf keeps its row: start from the integration ref's registry and, when it lacks this leaf's codename, add the leaf's row from `HEAD`'s registry. The written file stays valid. Extend tests/test_reconcile_branch.py: a `--local` pickup (claim only on the branch), then an independent remote commit on the integration branch. After `reconcile-branch`, the branch's registry still has the row and finish finds it.
- Landing: return a distinct outcome when the merge (and push) succeeded but the final checkout failed, for example `(True, warning)` or a small result type. finish_modes reports the landing as done, prints the checkout warning with the command to run (`git checkout <feature>`), and skips `undo_bookkeeping`. Extend tests/test_finish_merge_failure_undo.py: a `post-checkout` hook that exits 1 only when switching to the feature branch, in both `land: local` and push (bare remote). Integration contains the completion. The feature branch keeps its bookkeeping commit and is not reset. Finish exits 0 (or the documented warning code) with the warning, and no "run finish again" advice.
- docs/git-workflow-parallel-prs.md (reconcile-branch) and docs/git-workflow.md (finish landing): one line each where they describe the behaviour.
