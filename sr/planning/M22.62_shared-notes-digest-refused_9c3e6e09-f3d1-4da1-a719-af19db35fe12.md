## Intent

Two reviewers from different families filed different notes for one commit, yet both REVIEW records carry the same `notes_sha256`. Someone checking independence reads that as one reviewer's notes filed twice. Found in field use of 0.3.1rc4.

`notes_sha256` is the SHA-256 of the Markdown body below the front matter, normalised (`review_signing.notes_digest`, `specy_road/review_signing.py:53`). It is written by `review record` (`review_rejected.py:194`) and re-checked by the gate (`review_gate.py:233`, via `notes_problem`). It does not cover the front matter. The review-record schema also accepts notes in a front-matter `notes` list (`specy_road/schemas/review-record.schema.json:59`). So two records whose notes sit only in the front matter both have an empty body. Both then carry the digest of the empty string, `e3b0c442…b855`, while the files themselves differ in size and hash, which matches the report. The other explanation is that one body was filed twice. This leaf refuses both cases at `review record` and says in the docs what the field covers.

## Approach

All checks go in `review record`'s validation in `specy_road/review_rejected.py` (`_review_record_validate`, next to where the digest is computed). The gate is unchanged, so records already filed keep counting exactly as today.

- **B1, empty notes.** `review record` refuses a record whose body below the front matter is empty after `notes_digest`'s normalisation. The message says that the notes go below the front matter and that `notes_sha256` covers only that body. The refusal goes through `trace.refuse`, so `REJECTED-<model>.md` is written as for any other refusal. `review delegate` already passes the answer's `notes` into the body (`review_record_write.py:288`); a whitespace-only `notes` now gets this refusal, which is a rerun.
- **B2, a digest another model already filed.** `review record` refuses a record whose (non-empty) `notes_sha256` equals the digest of another model's valid record for the same leaf at the same commit, naming both models. A model re-filing its own record is not refused.
- **Docs.** `docs/orchestration-reviewer-output.md` says what `notes_sha256` covers (the body below the front matter, normalised) and what it does not (the front matter, the file as a whole).

## Test table

Temporary review repos, as `tests/test_review_record_write.py` builds them. The tests go through `review record` and `file_review`, and assert the exit code, the refusal naming the models, and the record that is or is not written. No sleep, no network.

| Row | Setup | Expect |
|---|---|---|
| empty body | `review record` with notes only in a front-matter `notes` list | Refused; `REJECTED-<model>.md` written; no REVIEW record |
| whitespace notes | `file_review` with an answer whose `notes` is whitespace | Refused as above (a rerun outcome) |
| shared digest | Model A filed; model B files a file with A's body at the same commit | Refused, naming A and B |
| own re-file | Model A re-files its own record at the same commit | Filed (today's behaviour) |
| other commit | B's body equals A's record at an older commit | Filed |
| two reviewers | Two `file_review` calls with different notes at one commit | Two records with different `notes_sha256` |
| gate unchanged | An existing record with an empty body, filed before this change | Counts in the gate as today |

## Tier

trust boundary: changes what the record checks accept.

## Done but wrong

- The check is added to the gate, so records already filed stop counting: the gate-unchanged row.
- A model cannot re-file its own record after a rerun: the own-re-file row.
- The empty-body refusal is phrased as a digest problem and says nothing about where the notes go: the row asserts the refusal names the body below the front matter.
- The digest definition changes: every existing signed record would then fail `notes_problem`. The digest function is unchanged.

## If this fails

Assumption: the reproduction shows two empty-body records sharing the empty-string digest. If it does not, and no path files two models' records with one body, the cause is elsewhere. In that case land B2 and the docs only, and report what the reproduction showed; the coordinator decides on B1.

## Accepted limits

- Two reviewers who really write identical notes are refused; one of them reruns. Identical notes from two families are not independent review evidence.
- Records filed before this change are not re-checked.
