## Intent

The sixth gap in the tool-call guard, found 2026-11-20 by the second reviewer on M16.7.7 and reproduced on WIP. `sudo -Q $X` is refused because `-Q` is an option sudo's table does not list and the next word could be git. Inside a subshell whose closing paren touches that word, `(sudo -Q $X)`, the same command is allowed: the check that asks "could a later word be git?" sees `$X)` and does not recognise it. It is a working way past the guard, not only a theoretical one: `nice -5` is real GNU nice syntax the table does not list, so `X='git stash'; (nice -5 $X)` passes and runs. This leaf makes that check strip the trailing paren the way the rest of the guard already does. Maintainer 2026-11-20: "A ok, guard fix plan ok, trust zone ok, risk ok".

## Approach

- The guard strips a trailing `)` from each word in one place (`_unwrap`) and not in the could-be-git check behind the unlisted-option refusal (`_hides_git`). Lift that strip into one helper and use it in both; add no second rule.
- Extend `test_unlisted_wrapper_option_is_opaque` with the refused and the still-allowed rows the acceptance names. No new test function.
- Out of scope: the `case` arm gap (`case a in a) $X;; esac` is allowed) is a different cause and gets its own leaf; the rule-table rewrite is M23.8; no option is added to any wrapper table here.
- Order: this leaf lands before M16.7.7 and M16.7.8 (paired, this one first). M16.7.7 then merges it and moves the commands of the three tests M22.79 added (`test_unlisted_wrapper_option_is_opaque`, `test_split_string_options_are_parsed_before_the_command`, `test_env_split_escapes_and_pre_leaf_refusals`) into its guard property's case tables.
- Verify: the enumerated wrapper tests and both guard test files pass unchanged apart from the added rows.

## Tier

trust: it changes the guard that refuses destructive commands.

## Done but wrong

- The new rows pass but a command that was allowed is now refused: the allowed rows `(sudo -Q ls)` and `(sudo -Q ls )` and the ordinary-commands table must stay allowed.
- The strip is copied instead of shared, and the two copies drift: one helper, called from both places.
- Only `sudo` is covered: the rows include env (its own table path), nohup, doas and nice.
- A lone `)` word is stripped to an empty word and reads as "could be git": `(sudo -Q ls )` must stay allowed.

## If this fails

If sharing the strip changes the verdict of any existing guard test row, stop and report the row; do not edit an existing row's expected verdict.

## Accepted limits

- A quoted or escaped literal `)` ending a could-be-git word after an unlisted option (`sudo -Q 'g)'`) is now refused. shlex drops the quoting, so the guard cannot tell it from a subshell's paren; refusing is the safe side.
- The check drew the wrappers and word shapes named in the acceptance. It is not a claim that no other enclosing form reaches the same check.
