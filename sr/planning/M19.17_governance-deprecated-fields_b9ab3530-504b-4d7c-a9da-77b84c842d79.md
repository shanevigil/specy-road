## Intent

A consumer repo's constitution can require a node field that specy-road deletes. In one adopter repo, `constitution/principles.md` required `agentic_checklist.contract_citation` on every leaf. `validate_self_heal` strips `agentic_checklist` from roadmap chunks, so that principle could never be met, and nothing said so. This leaf makes validate point at governance text that names a field validate strips, and say what replaced it.

**Out of scope:**
- Editing governance files.
- Scanning `docs/`, planning sheets or code.
- Changing which fields are stripped.
- The agent-file structure notices of M19.7, which check how AGENTS.md and CLAUDE.md fit together, not field names.

## Approach

- Source: adopter feedback on 0.3.1rc3 (item 27, sanitized), filed 2026-11-05.
- Turn `_DEPRECATED_FIELDS` into a field-to-replacement table, so the strip list and the notice share one source:
  - `agentic_checklist` and `agentic_checklist.contract_citation` → cite contracts in the planning sheet's `## References`. This is the contract-citation design described in `specy_road/contract_citations.py`.
  - `execution_subtask` → the "Execution type tagging" table in `docs/roadmap-authoring.md`.
- Scan `constitution/**`, `constraints/**` and the root `AGENTS.md`, skipping the managed specy-road block. Match whole words, so the dotted form matches too.
- Code goes in a new `validate_governance_fields.py`, with one call line in `validate_roadmap.py`.
- Depends on M16.44, which folds `validate_notices.py` into `validate_roadmap.py`. M16.29 and M16.30 rewrite this repo's own governing docs and are not affected.
