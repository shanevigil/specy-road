## Intent

Restores the steering classes other than git that the 2026-11-06 split took off feature/rm-steering-file-guard: harness config and hooks, the roadmap policy files, other leaves' registry entries, `work/reviews/` files, shell startup files, `env_bin` and symlinks. Each becomes a `steering_file` finding after a worker turn, on top of M22.5's git-steering list, post-turn order and sticky `steering_changed` flag. Detection only; the finish refusal is M22.31 and the launch denies are M22.32.

## Approach

- **First commit:** the leaf starts from the integration branch with `git revert` of R30 (the commit under `## Source`). Conflicts are resolved in that commit by keeping everything predecessors already landed (narrowed M22.5) and adding only this leaf's classes; no file is taken from narrowed M22.5's version where a predecessor has changed it since. Review covers this leaf's own diff from its merge base.
- **The classes**, added to M22.5's list in `specy_road/steering_paths.py` and snapshotted per worker in the worktree and in the main checkout:
  - harness config and hooks: `.claude/settings*.json`, `.claude/hooks/**`, `.codex/**`, `.cursor/*.json`, `.cursor/hooks/**`;
  - the toolkit's policy and record inputs: `roadmap/orchestration.yaml`, `roadmap/orchestration.local.yaml` and `roadmap/git-workflow.yaml` in the tree (`policy_tree`) and as the blob at the local integration branch tip, no fetch (`policy_blob`), so a roster commit made from another checkout shows; `roadmap/registry.yaml` `entries` items whose `node_id` is another leaf (`registry`); every file under `work/reviews/` except the leaf's own READY (`review_file`);
  - shell and env: root shell startup files (`.bashrc`, `.bash_profile`, `.profile`, `.zshrc`, `.zshenv`, `.envrc`) (`shell_startup`); for each `env_setup.link` target, its `bin/` entry names, types, link text and resolved regular-file sha256 (`env_bin`), so a write through an unchanged `.venv/bin/python` link changes the digest, not the link;
  - symlinks: a porcelain entry in either checkout, new or retargeted during the turn, whose target resolves outside the worker's git root. No directory walk; gitignored paths and links created then removed within one turn are outside detection scope, and docs/orchestration-steering-files.md says so.
- **After each turn:** `close_turn` compares these after the existing git probes; when M22.5 skipped the probes, it compares them without `policy_blob` and symlink. Each change is one `steering_file` finding (`path`, `class`, `before`, `after`) that replaces any porcelain or `committed_outside_zones` finding for the same path; a path two classes reach is one finding, of the class listed first. Each finding sets the sticky `steering_changed` flag. An unreadable input of these classes is one `check_error` naming the path and class, and the rest is still compared.
- **Docs:** docs/orchestration-steering-files.md and docs/orchestration-workers.md list the classes and the symlink scope limits.
- **Out of scope:** the finish refusal (M22.31), the launch denies (M22.32), OS-level isolation, signing, the M20 posture model and doctor probes, and restoring a changed file.
- **Verify:** the tests below, then one full Sol sweep of the merged result.
