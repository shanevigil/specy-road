## Intent

Keep `worktree prune` from deleting work that belongs to another repository. Without `nested_repos`, its preview listed sibling worktree directories among the ignored files removal would delete, with no check for commits that exist only there.

## Approach

- In `plan_prune()` (`specy_road/worktree_prune.py`), after `_status()` collects the ignored paths, find every directory among them (and among their parents up to the leaf worktree) that contains a `.git` entry. For a `.git` file, read its `gitdir:` to find the owning repository; for a `.git` directory, it is a checkout of its own. Record each as a blocking problem on the plan: path, owning repository, branch (`git -C <dir> rev-parse --abbrev-ref HEAD`), and commits its upstream lacks (`git -C <dir> log --oneline @{u}..` when an upstream exists, else commits not on any remote ref, reusing `_held()` / `_lost_tips()` logic).
- `remove()` and the CLI (`specy_road/bundled_scripts/worktree_cli.py`) refuse when the plan has such a problem: exit 1, nothing deleted, with the next step (land or push the listed commits, then `git -C <owner repo> worktree remove <dir>`).
- Configured nested repos keep the existing `_check_nested()` path.
- **Verify.** Test: a leaf worktree containing a linked worktree of a second repository with one unpushed commit → preview lists the refusal and the commit; removal refuses; directory still exists.

## Tasks / checklist

- [ ] A1 — Prune refuses directories with another repository's `.git`, naming repo, branch and unlanded commits, with the next step; nothing deleted.
- [ ] A2 — Test with a linked sibling worktree; configured nested repos unchanged. Out of scope: pruning sibling worktrees itself.
