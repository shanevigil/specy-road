## Intent

Security leaf in M22's fix intake, first after M21.37 in the upgrade series (M22.25, then M22.11, then M22.21). Only `upgrade --dry-run` runs inside `scratch_environ` (`upgrade.py:342`). A real `specy-road upgrade` makes the same plan outside it, so its git calls follow the caller's `GIT_*` variables and config. The delta review and the sandbox re-test found these:

- **The real run's planning-mirror refresh reads caller config** (Sol W1). `Mirror.build` isolates only the mirror's `git init` (`upgrade_plan.py:161`). Every git call the refresh makes afterwards, the ignore note's included, reads the caller's `GIT_CONFIG_COUNT` and global and system config.
- **With `GIT_DIR` and `GIT_WORK_TREE` naming a second repository, a real run writes into that repository** (Grok FAIL 1). The plan's refresh created `.gitignore`, `.cursorindexingignore` and `.specyrd/manifest.json` in that work tree. Validate then died with an uncaught `ValueError` in `validate_stale_commands.py`, because the project is not under the git toplevel those variables name.
- **The checkout's own git calls keep `GIT_CONFIG_COUNT`** (sandbox re-test). A `core.fsmonitor` injected that way ran six times during a real upgrade: four times from `git -C <project> check-ignore --stdin -z`, which is `file_limits_engine.git_ignored_paths` called by `_capped_lines`, and twice from `git ls-files -z`.
- **`git_ignored_paths` has no timeout** (Sol W2), so the `[Unreleased]` claim that upgrade's git calls time out after 60 s is not yet true.
- **`upgrade --help` does not state exit 2 for any failed git call** (Grok WARNING 1). It names exit 2 only for a temporary copy's `init`, `add` or `commit`.

This leaf gives upgrade one environment rule, for real runs and dry runs alike:

- no git call it makes sees a `GIT_` variable of the caller's;
- the two scratch repositories (the plan's mirror and the dry run's copy) also read no global or system config and run no hook;
- the checkout reads the caller's own config files, as any git command run there does;
- every git call it makes in the project is bounded by a timeout.

M16.2.3, which routes git queries through one helper, then preserves this rule as a parity line. M22.11 and M22.21 build on the same modules after it.

**What must stay fail-closed** (the leaf fails review if any of these loosens):

- A failed or timed-out `git init`, `add` or `commit` in either temporary copy still exits 2 before anything is applied or validated.
- A failed or timed-out `ls-files --error-unmatch roadmap.md` still exits 2 before a generated file is written. Exit 1 still means untracked.
- The environment and the ignore-report isolation are restored on every exit path (`finally`). A nested isolation restores the outer one and never clears it.
- The dry run's "modified the checkout" bug check (`plan.changed_since`) is unchanged.
- A `check-ignore` that times out or fails gives the file-limits scan no ignored set. The scan then counts those files, which for the file-limits gate is the stricter direction and never hides an over-cap file.

## Approach

- **One context for both environments** (`upgrade_generated.scratch_environ`). It becomes `scratch_environ(tmp: Path | None)`:
  - with `None`, `os.environ` is replaced by `scratch_git_env()`: `GIT_` variables dropped, the caller's config files still read, no isolation;
  - with a path, it behaves as today (also `GIT_CONFIG_NOSYSTEM=1`, an empty `GIT_CONFIG_GLOBAL`, and `isolate_git(tmp)`).

  On exit it restores the previous `os.environ` and the previous ignore-report isolation. `ignore_report.isolate_git` returns the value it replaces, so the context restores it instead of setting `None`, and a nested isolation keeps working. It still yields the caller's environment with `GIT_` dropped, for `regenerate`.
- **The whole run is stripped** (acceptance lines 2 and 4). `run_upgrade` runs `_upgrade` inside `scratch_environ(None)`. Every git call of the run is covered, including:
  - `project_root` and `_resolve_root`;
  - `_capped_lines`' `check-ignore`, before and after the writes;
  - `validate_at` and the `digest --check`;
  - `regenerate`'s `ls-files`, which keeps its `-c core.fsmonitor=false`;
  - `_other_worktrees`.

  With `GIT_DIR`, `GIT_WORK_TREE` or `GIT_CONFIG_COUNT` set, the real run therefore validates the project's own repository and raises no traceback.
- **The planning mirror is isolated in both runs** (acceptance line 1). `upgrade_plan.make_plan` wraps only its `refresh(...)` call in `scratch_environ(Path(tmp))`, using the plan's own temporary directory. When it returns, the stripped caller environment is back before `apply_plan`, `copy_missing_work_templates`, the line-cap scan and validate run in the checkout. In the dry run this nests inside the dry run's own isolation and restores it.
  - Known effect: the refresh's ignore note, which runs in the mirror, now reads no global excludes file in a real run either, the same as the dry run. M22.11 makes that notice describe the checkout.
- **A timeout on the checkout's `check-ignore`.** `file_limits_engine.git_ignored_paths` passes `timeout=git_subprocess.DEFAULT_TIMEOUT` and treats `subprocess.TimeoutExpired` like every other answer it cannot trust (an empty set, as its docstring says). It still inherits the environment, which under upgrade is the stripped one. `specy-road file-limits` changes only by the bound. It stays a direct `subprocess.run`, because `git_subprocess.run` takes no stdin and is outside the zones.
- **`--help` and the claims** (acceptance line 4). Rewrite the upgrade module docstring, which is `--help`, to one environment sentence and one exit-code sentence:
  - every git call runs with every `GIT_` variable of the caller's removed and a timeout;
  - in the plan's mirror and the dry run's copy, git also reads no global or system config and runs no hook;
  - in the checkout, the caller's own config files apply;
  - the exit code is 2 when a git call it depends on fails or times out, 1 when validate fails or a write is refused, and 0 otherwise.

  `docs/install-and-usage.md` (lines 144-146) speaks only of `--dry-run`. It stays true, and it is outside the zones.
- **CHANGELOG.** Amend the existing `[Unreleased]` upgrade Security bullet (the one saying "Upgrade's git calls time out after 60 s") to name the real run and the checkout's `check-ignore`. List each git spawn upgrade reaches: grep `["git"` in the modules `upgrade.py`, `upgrade_plan.py`, `upgrade_generated.py` and the refresh steps import. Each must have a timeout; otherwise the sentence names the exception instead of claiming every call. Do not add a version heading.
- **Verify:** `pytest -n auto` (which includes `tests/test_upgrade_preview.py`), `specy-road file-limits`, and `specy-road validate --repo-root tests/fixtures/specy_road_dogfood`. Rows extend the file's existing parametrized tests with `dry_run` in `[True, False]`, through `run_upgrade` and `upgrade.main`. Stubs sit only at the subprocess boundary (`git_subprocess.run`, and `subprocess.run` for the one `check-ignore`) and never sleep. Tests never import or patch a `_`-prefixed name.
