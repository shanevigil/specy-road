## Intent

Stop `doctor` from offering to delete a running leaf. It listed a live worker's worktree as "branch … is merged" with a removal note, because the branch had no commits yet and so was trivially an ancestor of the integration branch; `doctor --fix` asks once per kind, so one hurried "yes" could remove a leaf mid-run.

## Approach

- **Room.** `specy_road/bundled_scripts/doctor.py` is at 398 lines. Move `_worktrees`, `_worktree_reason`, `_ignored_note`, `_keep_detached`, `_remove_worktree` and `_worktree_findings` to new `specy_road/doctor_worktrees.py`; doctor imports them.
- **Live check.** A branch is live when the registry has an entry with that branch (the `ctx.live` set `_branch_reason` already uses) or `worker_state.list_records()` has a record for it whose state is not in `TERMINAL_STATES`. Live worktrees and branches get a finding without a fix: "live: claimed by <node>" / "live: worker <W> (<state>)".
- **Own commits.** Before calling a branch merged (both in `_worktree_reason` and in the branch findings that build `merged_local`), require at least one commit of its own: its reflog (`git reflog show --format=%H refs/heads/<b>`) has more than the creation entry, or, with no reflog, its tip differs from the merge-base with the integration branch at creation. Otherwise report "no commits yet" without a fix.
- **Verify.** Tests under `tests/`: claimed leaf on a fresh branch with a worktree → doctor lists it as live, `--fix` leaves it; running worker record → same; a merged branch with commits and no claim → still offered (unchanged).

## Tasks / checklist

- [ ] A1 — Claimed or worker-held worktrees and branches are never listed as merged nor fixed.
- [ ] A2 — Merged requires a commit of its own; commit-less branches show "no commits yet"; test with a claimed fresh worktree.
- [ ] A3 — doctor.py ≤ 400 lines via `doctor_worktrees.py`. Out of scope: other doctor findings.
