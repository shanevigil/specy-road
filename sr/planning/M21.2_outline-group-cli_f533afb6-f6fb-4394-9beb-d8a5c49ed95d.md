## Intent

rc4 roadmap-tooling fix (maintainer 2026-11-05), filed in M16's fix intake. Re-levelling from the CLI means one `move-node` per node, and each move validates the whole roadmap (`plan.commit(run_validate_raise)`, about 1.3 s on sr/). The GUI already has indent/outdent (`apply_indent` / `apply_outdent` in roadmap_outline_ops.py) but nothing exposes them to the CLI, and there is no way to create a parent and move siblings under it in one step.

Evidence: regrouping M16 into sub-milestones using only specy-road commands (scratch run, 2026-11-05) took about 85 commands, a temporary holder node and about 100 s, and left about 950 stale id mentions in prose. Earlier related fix: M16.67 (move-node renumbers only the moved subtree; whole-outline renumber became explicit).

## Approach

- Add a multi-move primitive in roadmap_move_node.py (`move_nodes(root, moves)`): every move applied in memory, every chunk, sheet rename and registry rewrite staged in one `AtomicWritePlan`, one validation. `move_node`, indent and outdent become one-move calls of it.
- CLI `indent <ID>`, `outdent <ID>` call the GUI's `apply_indent` / `apply_outdent`.
- CLI `group-nodes --into-new <NEW_ID> --title <T> [--type milestone] <ID...>`: create the parent and move the listed siblings under it in one transaction.
- Additive GUI endpoint `POST /outline/group` calling the same function; no frontend control in this leaf.
