## Intent

M17.9's browser run (RESULTS.md, 2026-11-15) found two places where the orchestration view does not do what docs/pm-gui.md says. The drawer's leaf groups follow the Gantt's dependency-step order instead of the outline's row order. The outline badges appear only after the drawer has been opened, because only the drawer fetches GET /api/orchestration. This leaf makes both match the docs, so M17.9's re-run can pass items 3 and 12.

Out of scope: the snapshot, the server routes, badge precedence, the drawer's 15 s poll, and docs/pm-gui.md (it already states the intended behaviour).

## Approach

- Drawer order: build the groups from the outline's row order, not from `displayData.nodes` (App.tsx passes the Gantt's node order today). Reuse the order OutlineTable already renders rather than sorting again.
- Badge loading: request GET /api/orchestration when the roadmap loads and on each roadmap reload, through the existing `loadOrchestration` and its subscribers (App already subscribes the outline). Add no new timer.
- Tests: one that fails on the old drawer order and one that fails when the outline has no snapshot until the drawer opens.
- Run npm ci, lint, test and build in gui/pm-gantt, and commit the rebuilt bundle under specy_road/pm_gantt_static/.
- Check against a live read-only server if a browser is available; otherwise curl the API and confirm the built bundle requests the route on load.

## Done but wrong

- The drawer order is fixed by sorting on node id: M0.10 would then sort before M0.2, and a moved node would not follow its outline position. The order must come from the outline's rows.
- Badges load on page load but not on a roadmap reload, or a new interval timer is added.
- The bundle is stale: the committed pm_gantt_static is not rebuilt from the changed source.
