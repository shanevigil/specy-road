## Intent

rc4 final review (§3.2, 2026-11-06), the prior-F2 class, still open: writers follow symlinks out of the repo. M21.17 closed the generated-file wrapper and a final-component link on three review files. It did not close the class. Each writer checks in its own way: `managed_block.resolves_outside`, `refused_link` with whatever root the caller passes, `review_write_check.replace_file` (immediate parent only), `refresh_profiles._contained`, and finish's `irregular_destination`. Many writers do not check at all. Grok reproduced a real `upgrade` overwriting a file outside the checkout through `schemas/roadmap.schema.json`.

This leaf adds **one shared rule** and moves the setup and upgrade writers onto it. M21.38 (review writers) and M21.39 (publish, finish, pickup) build on it in parallel.

The rule (`specy_road/safe_write.py`): before any mkdir, write or delete, walk with `lstat` from the owned root (resolved once; nothing above it is inspected) to the destination. Every component on the way must be a real directory and the destination absent or a regular file. Refused, with an `OSError` subclass naming the path and what it is:

- a symlink anywhere on the path, at the destination or any ancestor below the root, whether dangling, pointing inside the repo or pointing out;
- a non-directory where a directory belongs;
- a non-regular destination;
- a lexical `..` that leaves the root.

Writes are atomic: a temp file created exclusively in the verified parent, the destination and parent re-checked with `lstat` right before `os.replace`. Locks open with `O_NOFOLLOW` and must be regular files. Deletes remove the entry itself, never through a link.

Decisions:

- **In-repo links are refused too.** Finish already refuses them for `roadmap.md` / `roadmap-context.md` (`irregular_destination`); Publish must refuse them as well (ops-grok FAIL). `refused_generated_files` switches to the rule, so the `link_in` rows in tests/test_writers_refuse_links_out.py for generated files become refusals. This is a behavior change; record it in the CHANGELOG.
- **Upgrade backstop.** `apply_plan` refuses any entry whose target is not under the checkout through real directories before its first change. A refresher that bypasses the rule can no longer reach outside.
- **Kept on `resolves_outside` (out of scope):** `agents_md_block`, `specyrd_skills` (it creates skill symlinks on purpose), `upgrade_templates`, and `refresh_profiles._contained`. The reviewers checked those writers and found them OK. Under `upgrade` they run inside the mirror, so the `apply_plan` invariant covers them.
- **Race (deferred).** Descriptor-anchored traversal (openat with `O_NOFOLLOW` per component) is M22.21. This leaf narrows the window with the re-check right before replace.

## Approach

- `safe_write.py`:
  - `check(root, path)`, `mkdirs(root, d)`, `write(root, path, data, mode=None)`, `copy(root, src, dst)`, `remove(root, path)`, `open_lock(root, path)`, and `SafeWriteError(OSError)`.
  - The walk follows the same shape as `finish_bookkeeping_undo.irregular_destination`. M21.39 moves that function onto this module.
- `managed_block.refused_link` returns the module's refusal text: any symlink on the path is refused, whatever `any_link` says. `resolves_outside` stays for the callers listed above.
- `init_project._copy_templates`:
  - A dangling destination link counts as present (`lexists`) and is refused, never created through.
  - A symlinked parent is refused before `mkdir`.
- `refresh_schemas`, `specyrd_init._save_manifest`, `export_roadmap_md` (`reexport_roadmap_md` and `main`'s index write), `digest_cli` (default and `-o FILE`, which is repo-relative; `-` stays stdout), `generated_files.regenerate_generated_files`, `upgrade_generated.regenerate`: all write through `safe_write.write`.
- `do_next_task_register` (pickup) regenerates through `generated_files`, not its own `write_text`.
- `refresh_stubs._write_if_changed` and `_prune`: a recorded orphan under a symlinked directory is refused, not deleted. An orphan that is itself a symlink is removed as an entry. Empty-parent cleanup never follows a link.
- `archive_restore`:
  - `_restore_planning_sheets` and `_write_back` check `stored` and `origin` lexically under the root (no `resolve()` first).
  - A record that points outside or through a link refuses the restore before any move.
- `upgrade_plan.apply_plan`: one pass over `plan.changes()` before any change. Every `write`, `link`, `mkdir` and `remove` target (declined and `mirror.outside` entries included) must pass `check(checkout, target)`. Otherwise it raises, naming each path, and nothing is applied. `upgrade` prints the refusal and exits non-zero, and `--dry-run` reports the same refusal.
