## Intent

specy-road's review records carry `fresh_session`, but the value is self-attested. The Elephant-Goldfish project's own testing (issue #237) reports that "fresh" Codex CLI 0.166.0 subagents and Antigravity subagents still load `AGENTS.md` (and `GEMINI.md`), even with history disabled. Only Claude Code's `omitClaudeMd` is a verified exclusion. If a leaf edits `AGENTS.md` or `CLAUDE.md`, a reviewer that loads it reads text the branch wrote — the same concern behind running Claude reviewers with `--bare`. This leaf measures, per harness and CLI version, whether instruction files reach a reviewer launched the way `review delegate` launches it, and warns when a record's `fresh_session: true` comes from a harness known to leak.

## Approach

- Source: `sr/docs/research/elephant-goldfish-2026-11-05.md` (sections 1 and 4, item 2). Not yet verified for specy-road's own Codex reviewer command (`codex exec`, not a subagent); the probe settles that.
- Probe: in a scratch git repo, plant a canary instruction (a per-run nonce the reviewer is told to echo) in `AGENTS.md` and `CLAUDE.md`, launch each rostered reviewer harness with exactly the command line `review delegate` builds, and check the output for the nonce. Automated where the harness has a headless reviewer command; a runbook step otherwise.
- Results are harness facts (M18.2's records), labelled with the CLI version and the capture date. A harness with no capture stays `unverified`.
- No new top-level entrypoint: the probe is a subcommand of an existing CLI group. Tests use stub harness commands, never a real CLI or the network.
- Depends on M18.2 (harness-facts records for Copilot and agy, and the facts layout after M16.5.3). The phase starts after the 0.3.1 tag gate.
