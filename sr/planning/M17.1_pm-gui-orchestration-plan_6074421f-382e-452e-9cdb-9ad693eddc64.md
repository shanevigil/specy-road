## Approach

Proposed information design (the maintainer approves or edits it here):

- **Orchestration drawer** (header button, beside Workers): one group per leaf with orchestration state, in outline order, then "No leaf" for leafless workers (chores). Leaf header: display id, title, one leaf badge, claim (codename, branch, registered age). Worker rows: worker id, harness / model, account, status (claimed, running, exited_ok, exited_failed, abandoned, unknown), last activity age, started / ended, one badge per worker flag, verbatim (stalled, steering_changed once M22.5 adds it, any other); exited_failed shows in the status column. Clicking a leaf id opens the node's edit modal; clicking a worker opens the existing Workers drawer on it.
- **Leaf detail** (in the drawer for a selected leaf and as a collapsed read-only "Orchestration" section in a leaf's edit modal): worktrees (path, branch, dirty, ahead / behind the integration branch), the newest READY (commit, model, age), review records (model, verdict, commit, fresh for HEAD; stale ones marked; blocking verdicts first) and the gate summary (state, approvals, blocks, fresh for HEAD), plus holds (open gates the leaf waits on).
- **Outline badge**: at most one per leaf row, in the row's existing Task cell (no new column), precedence blocked / held (blocked: gate state blocked or executor_blocked), exited_failed, stalled, running, READY awaiting review, approved, claimed, abandoned, unknown; hover lists the details; click opens the drawer filtered to that leaf.
- **Unknown and missing**: a snapshot `unknown` shows "unknown"; a field a schema 1 server does not send, or null, shows "—"; neither is shown as false, 0 or "clean".
- **Read-only**: GET only; refresh on open and on Refresh, plus once per roadmap refresh for the outline badge; no new polling interval.
