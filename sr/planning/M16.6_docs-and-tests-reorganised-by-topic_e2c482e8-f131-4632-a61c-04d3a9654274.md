## Intent

After the code lane, reorganise the docs (design notes out, one workers doc, no RC pins, archived-milestone tidy) and the suggested prompts. Then build tests/support and move test files into lanes and per-module files. The docs leaf goes first because it edits the tests that open moved docs (M16.6.5 depends on M16.6.1).

## Approach

Leaves run in id order, which is chain order: every leaf's prerequisites have a smaller id, and no edge points to a later group. There are no group-level dependencies; the leaf edges give the order.

Why together: All six are "reorganise by topic, behaviour unchanged" passes, run on stable production code. Keeping M16.6.1 and M16.6.5 in one group makes the docs-before-test-moves edge internal, so no group depends on a later one and no inherited cycle can form.
