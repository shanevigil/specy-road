## Intent

Cap what one leaf's implement/review loop may spend. Today a leaf whose reviewers keep finding a *new* input class each round (the shape the RCA design note calls `specification`) loops until a human intervenes: deferred leaf M8.3 ran five blocking rounds from one reviewer, each naming a different input class, before the maintainer stopped it by hand (`work/reviews/M8.3/REVIEW-gpt-6.1-sol-27d39730-deferred.md`, `work/coordinator-rough-edges.md`). This leaf turns that manual call into a recorded, auditable step: an opt-in round budget, an RCA action that proposes deferring genuinely new findings to a follow-up leaf, and a human-only command that applies it. Projects that leave the budget unset see no change.

The rule this leaf defines, because "input class" is recorded nowhere today (it is prose in the RCA analyst prompt in `specy_road/review_rca.py`):

- **Input class** is a short free-text label the RCA analyst writes for each deferred finding (for example `CRLF line endings`, `empty final message`). It is stored, not inferred.
- Two input classes **match** when they are equal after lower-casing and collapsing runs of whitespace to one space, with leading/trailing whitespace stripped. No fuzzy or semantic matching.
- A finding **may be deferred** only when its input class matches no input class recorded in any earlier RCA record or applied deferral for the same leaf, and it is not a `correctness` finding on an acceptance id that some earlier round's record marked `pass`.

## Approach

- **Budget.** Add optional `policy.max_fix_rounds` (integer ≥ 1) to `specy_road/templates/project/schemas/orchestration.schema.json`. Read it with `policy.get("max_fix_rounds")` so no default is added (unset = current behaviour). Count blocking rounds on the leaf from `review_rounds()` in `specy_road/review_rca.py` (a round counts when any record in it blocks). When the count reaches the budget, `_node_status()` / `_render()` in `specy_road/bundled_scripts/review_cli.py` add `fix_round_budget_spent` and print the next command: run the RCA (`specy-road prompt --role rca --force --reason "fix-round budget spent"`) if no RCA covers the latest round, otherwise the apply command below.
- **Schema.** In `specy_road/schemas/rca-record.schema.json`, add `defer_findings` to `recommended_action.type` and a `deferred_findings` array, required when the type is `defer_findings` (same `if/then` pattern the `trigger.reason` rule uses). Each item: `finding` (round/reviewer: text, as `finding_disposition` cites it), `reviewer` (roster id), `commit`, `category` (one of the review-record finding keys: correctness, regression, boundary, test_integrity), `acceptance_id`, `input_class`, `follow_up_title`, `follow_up_acceptance`. Also allow an optional `input_class` on `criterion_rewrite.finding_disposition` items so non-defer RCAs can record classes too. Extend `_skeleton()` / `rca_preamble()` so the analyst is told the rule above and the new shape; `ACTIONS` gains the new type.
- **Refusal rule.** One pure function in `specy_road/review_rca.py`, e.g. `deferral_problems(rounds, rcas, applied, item) -> list[str]`, implementing the two "never deferrable" checks: normalised input-class match against every earlier RCA's `deferred_findings` / `finding_disposition` and every applied deferral; `category == correctness` on an acceptance id any earlier `ReviewFile` marked `pass`. Each problem string names the earlier round/record it collides with.
- **Apply command.** `specy-road review defer <NODE_ID> --rca <RCA file>` as a new subcommand in `specy_road/bundled_scripts/review_cli.py` (no new entrypoint in `cli.py`). Human-only exactly as `mark-implementation-reviewed` does it for the human approval: refuse unless `sys.stdin.isatty()`, with no `--yes` override, and show the findings and ask for confirmation. It refuses the whole record if `deferral_problems()` returns anything. Otherwise it: (1) adds the follow-up leaf through the same write `specy-road add-node` and `brainstorm_promote.py` use (`append_node_to_chunk` in `roadmap_crud_ops.py`, `next_child_id`, `derive_codename_with_collision_suffix`) as a sibling of the leaf, title and one acceptance line per item; group items that share a title); (2) writes a `decision` entry via `specy_road/decisions.add_entry()` then closes it with `close_entry()`, answer naming each deferred finding, the follow-up leaf id and the approver (git `user.name`/`user.email`); (3) writes an applied-deferral marker next to the RCA record in the leaf's review directory (gitignored, like the reviews it qualifies) naming the decision id, reviewer and commit.
- **Gate.** In `evaluate_gate()` in `specy_road/review_gate.py`, a block from reviewer M at commit C moves to `ineligible` with reason "deferred by <decision id>" only when an applied marker names (M, C) and the named decision exists closed in `decisions.yaml`. Every other block still counts; a new commit makes the marker irrelevant because it names C.
- **Docs.** `docs/orchestration-review.md` gains a "Fix-round budget and deferral" section; `docs/design-notes/review-loop-rca.md` gains the `defer_findings` action, the input-class rule and the audit trail (RCA record → decision entry → follow-up leaf).
- **Independence from M8.3.** M8.3 is unmerged; nothing here imports or extends its files (`review_record_write.py` and similar). Build on `review_rca.py`, `review_gate.py`, `review_files.py` as they are on the integration branch.
- **Verify.** New tests under `tests/` (extend `tests/test_review_rca.py`; add a gate/CLI test beside `tests/test_mark_implementation_reviewed_gate.py`), `pytest -n auto` on the touched tests, `specy-road file-limits`.

## Tasks / checklist

- [ ] A1 — `policy.max_fix_rounds` in the orchestration schema; with it set to N, after N blocking rounds `specy-road handoff status <ID>` (text and `--json`) reports `fix_round_budget_spent` and prints the resolving command. Test: unset budget → status output identical to today's for the same history.
- [ ] A2 — `rca-record.schema.json` accepts `recommended_action.type: defer_findings` with a non-empty `deferred_findings` list, each item carrying `input_class`, `follow_up_title`, `follow_up_acceptance` (plus reviewer, commit, category, acceptance id); a record of that type without the list is invalid. Test: schema accepts/rejects both shapes.
- [ ] A3 — `specy-road review defer` refuses a non-TTY run (exit 1, says to run it interactively as a human); on a TTY it adds the follow-up leaf via add-node, writes a closed decision entry naming the findings and approver, and afterwards the gate treats only the deferring reviewer's block at that commit as resolved. Test: another reviewer's block on the same commit, and the same reviewer's block on a later commit, still count.
- [ ] A4 — Refusals pinned by tests: (a) an item whose input class matches an earlier record's after case/whitespace normalisation (`"Empty  Final message"` vs `"empty final message"`); (b) a `correctness` item on an acceptance id an earlier round marked `pass`. Each refusal names the colliding round/record and exits 1 without writing anything.
- [ ] A5 — `docs/orchestration-review.md` and `docs/design-notes/review-loop-rca.md` describe budget, deferral and audit trail; existing review/RCA tests pass unchanged.
- Out of scope: inferring or clustering input classes automatically; semantic matching; letting an agent or `--yes` apply a deferral; changing escalation thresholds (`escalate_*`); deferring on the strength of one reviewer while another reviewer's block stands; anything in M8.3's unmerged files.
