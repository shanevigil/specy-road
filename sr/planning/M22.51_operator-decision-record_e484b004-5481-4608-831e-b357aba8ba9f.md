## Intent

The operator owns the rules and must be able to decide a leaf's review outcome directly, without turning that decision into reviewer paperwork. On 2026-11-08 and 09 the maintainer accepted M16.1.6 as-is, and the tool still refused: a human approval only fills a missing reviewer family, and `review defer` needs an RCA record and refuses correctness findings. Source: the governance analysis, `~/WORKSPACE/specy-road-research/inbox/2026-11-09-governance-analysis-work-account.md`, section 4.

## Approach

Reuse `review defer`'s decision-entry and marker machinery (`review_deferral.py`, read-only reference), without its RCA requirement and refusal rules. The marker is a cache and the decision entry is the authority, as with deferral. Agents can never run it: interactive terminal only.

## Tasks / checklist

- [ ] `review override` command
- [ ] Gate and status read the override
- [ ] Tests, docs, CHANGELOG

## Tier

trust boundary: review records and the gate.

## Done but wrong

- An agent can create an override: a non-interactive run is refused, and a hand-written marker without its decision entry has no effect.
- An override outlives its commit: after a new commit, the gate counts reviews again.

## If this fails

If the gate cannot read the override without widening into other gate modules, stop and name them; the maintainer decides.

## Accepted limits

- No bulk override across leaves; one leaf and one commit at a time.
