## Intent

Defect D4 (Medium) from the rc4 real-harness checks (pre-release evidence 2026-11-05, runbook §2, calculator M2.3). A Codex `review delegate M2.3` ran while a separate Claude reviewer session filed its own record with `review record`. The delegate then discarded its own valid run: "review failure: the reviewer run wrote work/reviews/M2.3/REVIEW-claude-opus-5-5.md, …/history/…, …/notes-claude-opus-5-5.md; a reviewer writes nothing". Run alone, it was complete.

`review delegate` and `prompt --channel cli --run` hold the per-leaf `review_run_lock` for the whole run. `review record` and the human approval of `mark-implementation-reviewed` write into the same hand-off directory without taking that lock, so the tripwire reads their files as the reviewer's own writes.

Fix: every filing into `work/reviews/<ID>/` takes the same per-leaf lock. A filing waits briefly for the lock (two quick filings both succeed). It refuses with a clear message, writing nothing, while a reviewer run holds the lock. The run is never voided by someone else's filing. The tripwire rule is unchanged.

Out of scope: running two delegated reviewers of one leaf at once (still refused by the lock, as today); the tripwire's file list; per-run directories.

Overlaps checked (2026-11-05): M21.17 edits review_rejected.py (`write_rejected`, where `run_review_record` lives), so this leaf takes the lock in the CLI wrapper `cmd_review_record` (review_cli.py) instead. M21.24 and M21.26 edit review_delegate.py, which this leaf does not. M21.26 also edits docs/orchestration.md (other sections).

## Approach

- review_record_write.py: give `review_run_lock` an optional `wait` (seconds; default 0 keeps today's immediate `ReviewRunBusy`) that retries the non-blocking flock until the deadline.
- `cmd_review_record` (review_cli.py:262) wraps `run_review_record` in `review_run_lock(reviews_dir(root, node), wait=FILING_WAIT)` (module constant, 10 s). On busy it exits 1 with `a reviewer run on <ID> holds work/reviews/<ID>/; nothing was written — file again when it ends (review list <ID>)`.
- `write_human_approval` (review_gate_ready.py:32) takes the same lock with the same wait.
- The delegate's own `file_review` path runs inside the lock it already holds and must not take it again. The test shows the delegate still files.
