## Intent

A field run showed a worker that could not commit still reach review. `ready` wrote READY with `commit` equal to `base` and no changed paths, its `--run` checks passed against uncommitted files, and `handoff status` showed `ok` and offered review. Confirmed in `cmd_ready`: nothing refuses an empty leaf.

## Approach

Add one refusal in `cmd_ready`, before the `--run` commands, so a bad state costs no test run: HEAD equal to the merge base, or uncommitted changes inside the touch zones. Name the paths. Keep `blocked_on` working. Make the READY check that `handoff status` uses report an old empty READY as not ready.

## Tasks / checklist

- [ ] Refuse an empty or dirty leaf in `ready`
- [ ] Stop showing ok for an empty READY
- [ ] Tests, docs, CHANGELOG

## Tier

behavioural: a new refusal in `ready`; a test of the simple case can pass while the zone match is wrong for others.

## Done but wrong

- Zone matching is too broad or too narrow: a dirty file under a directory zone is named, and a dirty file outside every zone, including one whose path starts with a zone's name, does not refuse.
- Old READYs are misjudged: an empty READY is no longer offered in either `handoff status` text or `--json`, and an old non-empty READY still shows ok.

## If this fails

Most likely to break: a leaf's work is always in the root repository (see Concerns). The maintainer decides.
