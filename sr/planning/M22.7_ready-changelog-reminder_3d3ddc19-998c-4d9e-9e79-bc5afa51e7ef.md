## Intent

During rc4 release prep, 60 of the 67 leaves merged since rc3 had no CHANGELOG entry, so the release notes had to be rebuilt from git history. Nothing reminded executors when it would have been cheap: at hand-off time. This leaf adds a reminder to `specy-road ready`. It warns, never refuses, in keeping with "recommend, not enforce". It fires when the branch changes product files and adds no line under `CHANGELOG.md`'s `## [Unreleased]` heading.

Why `ready` and not finish-this-task: `ready` is where the executor still owns the branch and can add the line before review. It already prints one post-write advisory, the trial-merge warning in review_ready_merge.cmd_ready, and this goes next to it. At finish, the review has already approved the commit, and an added line would make the reviews stale.

Out of scope: finish-this-task, the review packet, handoff status, a config switch, refusing, checking the entry's wording or category, and M18.27's append-only merge of CHANGELOG.md.

Overlaps checked (2026-11-05): M16.5.14 (post-fix refactor gate) adds a complexity report to `ready` and the packet, and M16.4.5/M16.4.6 change the checks in review_gate_ready.py. This leaf touches only review_ready_merge.py and a new module, so no shared file. M18.9 adds a zone refusal to ready in review_gate_ready.py: different file. M18.27 makes CHANGELOG.md append-only for merges, which complements this. M16.8.8 consolidates [Unreleased] at release. M22.1 to M22.5 do not touch ready.

## Approach

- New `specy_road/changelog_check.py` with one pure function, `missing_entry_warning(changed, prefix, base_text, head_text, exempt_text) -> str | None`. A path is a product path unless it is `CHANGELOG.md`, under `tests/`, or bookkeeping. In a nested layout, bookkeeping is everything under the project prefix (`sr/` here). Unnested, it is `is_trial_merge_bookkeeping` (roadmap/, planning/, work/, roadmap.md, roadmap-context.md). The section is the lines after `## [Unreleased]` up to the next `## ` heading. It counts as having an entry when the HEAD section has a non-blank line the base section lacks. No CHANGELOG.md or no heading at HEAD: None.
- `review_ready_merge.cmd_ready`: on exit 0, after the trial-merge lines, resolve the target once. Read `CHANGELOG.md` at base and HEAD with `git show`, take the base...HEAD paths (the `diff_paths` call ready already uses), and build the exemption text from the node's acceptance plus its planning sheet. Print the warning to stderr. It names up to three product paths and `## [Unreleased]`, and says how to exempt the leaf.
- A git error on any read: no warning (advisory only).
