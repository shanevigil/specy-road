## Intent

The tool-call guard stops agents running destructive git commands in a shared checkout. It can be bypassed: wrapping a destructive command in a subshell behind an opener (`! (git stash)`), or putting `env -S` or `GIT_CONFIG*` behind a wrapper, assignment or subshell, gets it classified as allowed. The M16.7.7 planner found this on 2026-11-18 while trying a guard property, and the coordinator verified it with `classify`. The operator made it a blocker for the 0.3.1 release candidate ("RC blockers: guard, frontmatter").

## Approach

- Cause, from the planner's trial: `_opaque` and `env_config` read the raw tokens before `_unwrap`, so a leading `(`, wrapper or assignment hides the `env -S` and `GIT_CONFIG*` checks. An opener followed by `(` is not stripped.
- Fix it there: the checks run on the unwrapped tokens, and an opener plus `(` is stripped. No new classifier and no rewrite: the rule-table rewrite is M23.8.
- Add each bypass form as a row of the existing destructive-command tables. Keep every current row unchanged.
- Depends on: nothing. M16.8.4 (the pre-release pass) depends on this leaf.
- Evidence: sr/work/planner-2026-11-18-M16.7.7/ (report.md, properties.md, trials/).

## Tier

trust: it changes the guard that refuses destructive commands (tool_call_guard paths match the trust rule).
