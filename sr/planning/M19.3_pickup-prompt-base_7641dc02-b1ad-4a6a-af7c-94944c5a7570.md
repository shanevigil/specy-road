## Intent

The managed AGENTS.md block tells an agent that a plan or prompt should name its commit (`base: <sha>`) and to ask when it does not. The prompt that pickup writes (`work/prompt-<NODE_ID>.md`) names no commit, so an agent that follows the rule exactly stops to ask before writing code. In the M5.7 study one Codex run did this and lost the leaf. This leaf makes the pickup prompt name its base commit, which fixes the conflict for every harness at once.

## Approach

- Source: `docs/design-notes/managed-section-ablation.md` ("Test further", item 1: "Settle the base-commit clause"), and the 2026-11-05 milestone audit (`sr/work/milestone-audit-2026-11-05.md`, M5 gaps), which found the clause still says "if it does not, ask" and `do_next_prompt.py` still writes no `base:`.
- The study offers two fixes: the prompt carries `base:`, or the clause exempts toolkit-written prompts. Take the prompt side, as the study recommends. `specy-road prompt` already writes `base: <commit>` (`role_prompt.py`), so only the pickup prompt needs it.
- The base is the commit the leaf branch starts from. When pickup resumes an existing branch, it is that branch's merge base with the integration branch.
- Keep the clause's "ask" for plans and prompts that come from somewhere else, and say that toolkit-written prompts carry the line.
- Out of scope: any change to `specy-road prompt`, to the brief, or to how pickup chooses or creates its branch.
- Depends on M16.30, which rewrites the same managed-block template (AGENTS.md as the single entry). The phase starts after the 0.3.1 tag gate.
