## Intent

rc4 roadmap-tooling fix (maintainer 2026-11-05), filed in M16's fix intake. `apply CHANGES.yaml` (roadmap_crud_dependency_ops.py) accepts only add-node, edit-node and add-dependency (`APPLY_OPS`), so a restructure cannot be rehearsed with --dry-run or applied all-or-nothing. Each entry also commits and validates on its own (`_run_changes` runs each command's `func`), so a batch pays one whole-roadmap validation per entry.

Evidence: regrouping M16 into sub-milestones using only specy-road commands (scratch run, 2026-11-05) took about 85 commands, a temporary holder node and about 100 s, and left about 950 stale id mentions in prose. Earlier related fix: M16.67 (move-node renumbers only the moved subtree; whole-outline renumber became explicit).

## Approach

- Add ops: move-node, group-nodes, indent, outdent, remove-node, archive. Each entry still goes through the real subcommand parser before anything runs.
- Validate once: inside `_run_changes` per-command validation is deferred (one in-process switch read by `run_validate_raise` callers), then one validation of the final graph; on failure the existing snapshot restore runs.
- --dry-run prints the combined old -> new id map plus the waves.
