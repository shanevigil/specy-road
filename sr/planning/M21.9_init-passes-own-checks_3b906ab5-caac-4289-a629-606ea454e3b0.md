## Intent

A clean-VM rehearsal of rc4 (sr/work/sandbox-feedback/2026-11-05-rc4-trial-1da375e1.md, findings 1 and 3) ran `init project` and then the project's own checks: `export --check` and `digest --check` exited 1 because roadmap.md and roadmap-context.md did not exist yet, init printed no next step, and `validate` printed two notices about the scaffold itself (the placeholder roster entry `my-executor`, with an unrelated model profile offered as its closest match, and `vision.md` as an unknown touch zone). After this leaf a new project passes all four checks with nothing to read past.

Decision: init **generates** both files rather than printing next steps. `generated_files.regenerate_generated_files(root)` already re-renders both from the graph on disk (archive and restore-archive use it), so the change is a call plus two entries in the written list. Verified by hand on a scratch repo: files rendered before the first commit still pass `digest --check` and `export --check` after it.

`vision.md` touch-zone notice: verified by hand that it is untracked-only and clears after the first commit, so the zone check is not changed; the test commits once before running the checks (the normal first step), and the docs line says so.

Out of scope: changing the touch-zone check, the roster schema, the model-profile matching rules for real ids, any new init flag or prompt, the version string (finding 5, handled at the cut), and the toolkit's own fixture.

## Approach

1. `init_project.run_init_project`: after the templates, AGENTS.md and ignore blocks are written, call `regenerate_generated_files(dst)` (skip under `--dry-run`) and append `roadmap.md` and `roadmap-context.md` (with the nested-layout prefix) to `written`, so `--dry-run` and the real run report the same paths. Import it lazily if an import cycle appears.
2. `model_profiles.roster_profile_gaps`: skip the starter placeholder. Prefer a rule that needs no new config: an entry that is not launchable (`_launchable` false) and whose id is the template's placeholder id. Keep the placeholder id in one named constant and assert in a test that the template's orchestration.yaml uses it, so the two cannot drift. Real unmatched ids still get the notice.
3. `closest_profile` (or its caller in `roster_profile_gaps`): show the "closest profile is ..." hint only above a SequenceMatcher cutoff (start at 0.6, the difflib default used elsewhere in the CLI); below it, fall back to the existing "add one or give the entry `profile:`" wording.
4. Tests, docs line, CHANGELOG.

Verify: the new test, `pytest tests/test_init_project*.py tests/test_model_profile_aliases.py tests/test_refresh_profiles_roster.py tests/test_roster_generate.py`, then a manual init into a scratch repo with the four commands.
