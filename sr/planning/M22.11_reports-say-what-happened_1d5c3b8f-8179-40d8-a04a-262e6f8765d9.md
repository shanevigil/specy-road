## Intent

Three places where a report says something other than what happened. All are rc4 check warnings deferred to rc5.

- Review W5 (grok). `tally_trailers` (review_tally.py:92-97) catches every `Exception` and returns no trailer. The leaf then counts as "landed with no tally", is left out of block rate, mean rounds, integrity and RCA in `area_quality`, and nothing is printed.
- Roadmap W2 (sol). The rename-refs fence scanner (planning_rename.py:54-75) knows only backtick fences (`_FENCE = ^\s*`{3,}`) and closes on any later backtick fence. A `~~~` block is rewritten as prose. A four-backtick block containing a three-backtick line closes early, so ids inside the rest of the code are rewritten.
- CLI W1 (sol). `upgrade` builds its plan on a mirror with an empty git index (upgrade_plan.py:226, upgrade.py:275). The ignore notices it prints describe the mirror, not the checkout. For example, a tracked file that a new `.gitignore` rule matches is reported as "untracked; now hidden" instead of "still tracked", with no untrack guidance.

Out of scope: the gate's own decision (a tally failure never refuses `mark-implementation-reviewed`); other Markdown constructs (indented code, HTML blocks); the dry run's validation copy; the scratch-git environment (M21.16).

Overlaps checked (2026-11-05): depends on M21.16 (rc4), which edits upgrade.py and upgrade_plan.py first. M21.18 edits review_deferral / next step / rework, not review_tally.py. M22.2 and M22.3 change move rewriting of zones and decisions, not planning_rename's prose scanner.

## Approach

- `tally_trailers`: keep the gate closing. On an exception, print one stderr line (`review tally: <type>: <message>; the leaf's quality numbers will be missing`) and return a trailer that `parse_tally` reads as "unreadable" (for example `Review-tally: <ID> unreadable`). `area_quality` counts that leaf as unreadable, apart from `no_tally` (a trailer never written). `digest.py` shows the unreadable count apart from `no_tally`; both stay out of the rates, and the "landed before tallies were recorded" footnote covers `no_tally` only. Test: a raising `leaf_tally` gives the stderr line and the unreadable trailer, and the digest shows it apart from an absent tally. A normal tally is unchanged.
- Fences: recognise backtick and tilde fences (CommonMark: up to three spaces of indent, three or more of the same character). Remember the opening character and length, and close only on a line of the same character, at least as long, with nothing else after it but spaces. Extend tests/test_rename_refs.py's parameterized case with `~~~` blocks, a four-backtick block holding a three-backtick line, and an unclosed tilde fence (protected to the end), a fence indented three spaces, and a fence-like line with trailing words that does not close the block. docs/roadmap-authoring.md's rename-refs paragraph describes the fence rule.
- Upgrade ignore notices: on a real run, take the ignore observations from the checkout around the actual `.gitignore` write (`git ls-files` before and after on the checkout, as `ignore_report` already does for `refresh-stubs`), not from the mirror. On `--dry-run`, label the mirror-derived notice as an estimate (the `ESTIMATE_HEADER` wording ignore_report already has). Test through `run_upgrade` with a tracked file a new rule matches: the real run says it stays tracked and prints the untrack command; the dry run prints the estimate header.
