## Intent

The rc2, rc3 and rc4 promotions merged the WIP line's history into main, so `sr/` is absent from main's files but present in its history: thousands of commits that touch `sr/` are reachable from the rc4 tag. Every promotion done that way brings the process history back. Promotion must become one commit built from the WIP tree without WIP history, and CI must refuse a pull request to main that carries denied paths. Publish must also scan what it uploads. First pass of the sweep, inside RC5; it changes the runbook, so it lands before M16.8.8. Source: the maintainer's scrub plan (private), sections 3 and 5, approved 2026-11-09.

## Approach

- **Runbook:** `docs/release-runbook.md` and `docs/toolkit-development.md` describe promotion in an isolated release worktree. The candidate tree is built exactly from the selected WIP snapshot (for example `git read-tree -u --reset <WIP>`), not overlaid with `git checkout <WIP> -- .`: an overlay keeps a main-only file that WIP deleted, and the release would resurrect it. Then every M22.54 denied path is removed, and the commit's sole parent is main's recorded tip. The release PR may land by squash or by GitHub's merge commit; either is accepted as long as no WIP commit becomes reachable. The page names which resulting main commit is tagged. No step merges the WIP line into `chore/release-*` or main. Both pages drop their links to this repository's `.cursor/rules/` (M22.55 leaves these two files to this leaf).
- **CI on pull requests and pushes to main:** `validate.yml` checks out with `fetch-depth: 0`; a shallow checkout cannot see the range, and a check that cannot decide must fail, not pass. It walks every commit in `base..head` (side branches too; merges diffed with `-m`). An addition, modification or rename destination at a denied path is refused; a deletion-only entry passes, so the first promotion's removal of `docs/design-notes/` from main is accepted. M22.54's message and identity checks also apply. The script and allowlist come from the base commit when it has them, so a broad exception added in the candidate does not weaken the check that judges it.
- **Publish:** in the existing build job, before either publish job, `release-publish.yml` unpacks the built sdist and wheel into plain directories and runs M22.54's `--promotion` file and path checks over them without consulting a git index. Member paths are relative to the distribution root (the sdist's single top directory removed). `scripts/verify_wheel_contents.py` also checks both archives for denied member paths. Any failure stops the publish.

## Tier

trust boundary (release): the promotion and publish path decides what reaches main and the package index.

## Done but wrong

- A WIP merge still passes: a range in a temporary repository containing a merge of a branch whose history touched `sr/` is refused, even when the tip tree has no `sr/`; and a repository that lacks the base commit exits 1 rather than passing, as a depth-1 checkout would.
- The promotion keeps or resurrects a path: a promotion built by the runbook steps from a WIP tree holding `sr/` and `docs/design-notes/` has neither in `git ls-tree -r`, has exactly one parent, and does not contain a main-only file that WIP deleted.
- A correct promotion is refused: deletion-only cleanup of a denied path on main, and a two-parent landing merge with no WIP history, are accepted.
- Publish scans the wrong thing: an sdist containing a denied path fails the release job before the upload step, and the wheel check alone would not have caught it (tar fixture, not a real publish).

## If this fails

Assumption: the scan is a step in the existing build job before upload and does not change the OIDC publisher. If it needs a separate job or a change to the publisher binding, stop and record it; the operator decides.

## Accepted limits

- The squash loses per-commit WIP history on main by design; the WIP line keeps it until the rewrite.
- Candidates already published (rc1 to rc4) are not rescanned here, and the publish scan does not judge archives already on TestPyPI; M22.59 holds the operator's TestPyPI decision.
- The range check relies on M22.54's path denylist, so `scripts/lean_metrics.py` is not refused while it stays tracked.
- The first promotion after this leaf runs the candidate's own script and allowlist, because main has none yet; the operator reviews that first policy. Changing the policy later is a normal reviewed change that lands on main before it applies.
- Deliberate modification of trusted repository administration (branch protection, workflow permissions) is outside this plan's ordinary-work threat model.
