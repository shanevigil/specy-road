## Intent

The rc2, rc3 and rc4 promotions merged the WIP line's history into main, so `sr/` is absent from main's files but present in its history: thousands of commits that touch `sr/` are reachable from the rc4 tag. Every promotion done that way brings the process history back. Promotion must become one squashed commit without WIP history, and CI must refuse a pull request to main that carries denied paths. Publish must also scan what it uploads. First pass of the sweep, inside RC5; it changes the runbook, so it lands before M16.8.8. Source: the maintainer's scrub plan (private), sections 3 and 5, approved 2026-11-09.

## Approach

- **Runbook:** `docs/release-runbook.md` and `docs/toolkit-development.md` describe promotion as one commit whose only parent is main's tip, built from the WIP tree with M22.54's denied paths removed (`git checkout <WIP> -- .`, then `git rm -r --cached` of each denied path). No step merges the WIP line into `chore/release-*` or main.
- **CI on pull requests to main:** fail when any commit in `base..head` touches a denied path, or fails M22.54's message and identity check. A WIP merge brings `sr/` history into the range, so this catches it.
- **Publish:** `release-publish.yml` unpacks the built sdist and wheel and runs M22.54's gate over both before the upload step. `scripts/verify_wheel_contents.py` also checks both archives for denied paths. A failure stops the publish.

## Tasks / checklist

- [ ] Runbook and toolkit-development promotion steps
- [ ] PR-to-main range check in validate.yml
- [ ] sdist and wheel scan before upload; `verify_wheel_contents.py` for both archives
- [ ] Tests with temporary repositories and built-archive fixtures

## Tier

trust boundary (release): the promotion and publish path decides what reaches main and the package index.

## Done but wrong

- A WIP merge still passes: a range in a temporary repository containing a merge of a branch whose history touched `sr/` is refused, even when the tip tree has no `sr/`.
- The squash keeps a denied path: a promotion built by the runbook steps from a WIP tree holding `sr/` and `docs/design-notes/` has neither in `git ls-tree -r` and has exactly one parent.
- Publish scans the wrong thing: an sdist containing a denied path fails the release job before the upload step, and the wheel check alone would not have caught it.

## If this fails

Assumption: the existing publish job can unpack the sdist before upload without changing trusted publishing. If the scan needs a separate job or a change to the publisher binding, stop and record it; the operator decides.

## Accepted limits

- The squash loses per-commit WIP history on main by design; the WIP line keeps it until the rewrite.
- Candidates already published (rc1 to rc4) are not rescanned here; M22.59 holds the operator's TestPyPI decision.
- The range check relies on M22.54's path denylist, so `scripts/lean_metrics.py` is not refused while it stays tracked.
