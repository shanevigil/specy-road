trust boundary: in block mode it refuses `ready` and refuses an approval at the gate.

## Done but wrong

- Growth is measured against the wrong base: with the integration branch moved past the leaf's fork and the same function changed there, only the leaf's own growth is listed.
- Moves are misread: a function moved unchanged to another file is not listed, and a moved function with one added branch is.
- An approval passes without a result: the gate refuses an approval whose commit has no result, a failed one, or one for another commit, with block mode set as in sr/.

## If this fails

Most likely to break: name matching across moves is good enough that sr/'s block mode does not refuse unrelated leaves. If false growth shows up, switch sr/ to report mode and record the cases; the maintainer decides.

## Accepted limits

- Functions sharing a qualified name in one file (conditional definitions) are matched by the rule as written, without a guarantee that the right pair is matched.
