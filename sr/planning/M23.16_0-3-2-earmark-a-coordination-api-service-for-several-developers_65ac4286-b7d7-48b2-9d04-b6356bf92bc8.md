## Intent

An earmark for 0.3.2, in the maintainer's words (2026-11-20): "add an api server that allows for multiple devs' orchestrators to be coordinated. This feature isn't supposed to replace git based worktree and file orchestration for a single dev. However, when multiple devs are doing the same things--that can get difficult to manage in files. So, I'd like a coordination service that assists and excels where git struggles. It augments. And when one or more PMs are working with multiple devs, they need to be able to see the big picture, so this api would assist them as well--potentially routing overall design decisions to them."

## Approach

- Nothing is built here. This node holds the earmark until the multi-operator brainstorm (M23.10) runs after RC5; the planner gives it to that session as a maintainer seed and the resulting plan promotes it to build leaves or records why not.
- Boundaries to keep: it augments git and files, never replaces single-developer orchestration; it must degrade to today's behaviour when the service is absent.
- It revisits two 2026-10-27 decisions (no MCP server, no daemon); the plan says so explicitly and what changes.
- Open questions for the brainstorm: who hosts the service and how developers authenticate; what state it owns versus what stays in git (claims, presence, leases, review queue, decisions); how PM decisions are routed and recorded; how the PM GUI uses it; what happens on a network split.

## Tier

plain: a planning earmark; no product change.
