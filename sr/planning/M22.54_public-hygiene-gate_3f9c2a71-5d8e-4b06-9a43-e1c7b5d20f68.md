## Intent

Personal data, machine setup and development-process content have reached the public tree and its history: email identities in commit metadata, session links in commit messages, home paths and private names in roadmap files, and process notes on main. Today's `check_machine_paths.py` catches only home paths and Mac hostnames in files. A gate must refuse new leaks in tracked files and in commit messages, so the later steps do not have to be repeated. It lands right after the first cleanup (M22.55 untracks the process content, M22.56 neutralises the test identities), so it enforces on a tree that already passes; until then today's machine-path check stays in force. First pass of the sweep, inside RC5. Source: the maintainer's scrub plan (private), sections 2 and 5, approved 2026-11-09.

## Approach

Extend the existing gate rather than adding a second one: rename `scripts/check_machine_paths.py` to `scripts/check_public_hygiene.py` and give it three categories, each bounded so product paths and names pass.

- **(a) Personal data:** emails not in the allowlist. Name tokens and the username, from the local list or CI secret only, as whole words: in text, as `owner:` values, and in presence names `<username>-s<digits>` (the shape `session_presence.default_agent_id` builds; the format string in source is not a hit). A github.com URL owned by the repo-owner handle is not a name hit. Neutral test identities (Alice, Test User) need no entry, because only local-list tokens are name hits.
- **(b) Machine setup:** today's path patterns (`-MacBook…`, `/private/tmp/claude-<uid>`); a bare `.local` token is not a hostname, so `AGENTS.local.md`, `settings.local.json`, `CLAUDE.local.md` and `orchestration.local.yaml` pass. A `~/` path fails only when its first component is an account-directory name from the local list: the product docs name `~/.claude`, `~/.specy-road`, `~/.codex`, `~/.cursor`, `~/.config`, `~/.local`, `~/.ssh` and others, and those pass. `CLAUDE_CONFIG_DIR=` fails only with a value starting with `/` or `~`; the apparmor sysctl fails only with a literal number; apparmor profile and machine names come from the local list.
- **(c) Process content:** the text denylist (`deep-research report`, `claude.ai/code/session_`, `Claude-Session:`, local-list phrases) in tracked files outside `sr/` and in commit messages. Mentions of `sr/work`, `sr/planning`, `sr/roadmap` and `sr/tools` are checked in commit messages only: product text and tests use `sr/` as a nested project-root example. The path denylist runs only under `--promotion`, on tracked paths and archive member names, never on file text, and never under `specy_road/templates/` or `tests/parity/` (they ship `research/README.md`, `handoff-ready.template.md` and `specyrd-prompt.md`).

**Modes:** default mode scans tracked files, skips the `sr/` tree and applies no path denylist; that is what pre-commit and the WIP line run, because `sr/` is legitimately tracked there until M22.60. `--promotion` adds the path denylist and the identity check; validate.yml passes it for a pull request or push to main, and M22.57's release step passes it. Branch names are not inspected: a promotion PR's head is still the WIP branch. A `workflow_call` run performs the file check only and does not invent a range.

**Identity:** `scripts/public_hygiene_allow.txt` ships the public-author entry as `PUBLIC_IDENTITY_UNSET`. While it is the placeholder, the identity check is advisory: it reports the identities it would refuse and exits 0. Once the operator sets the public identity, `--promotion` fails any other non-bot identity in the checked range. The WIP line never runs the identity check, because the maintainer's WIP commits carry private identities until the rewrite (M22.58).

**Self-description:** the script, its docs and its tests build each denied literal by concatenation (as `tests/test_lean_gates.py` does today for the MacBook row), so the scanner passes its own files without an allow entry.

## Tier

behavioural: a pattern gate whose failure is a missed leak or a blocked commit, checked by table rows; it decides nothing about review or landing.

## Done but wrong

- The gate leaks what it guards: with the local list present, a whole-word scan of tracked files outside `sr/` finds none of its tokens (`git grep` of `sr/` is not a failure while `sr/` is tracked).
- The placeholder blocks the WIP line: with the entry still the placeholder, default mode and the identity report exit 0 on a range authored by a non-allowlisted address.
- Product content fails: the `~/.<tool>` mentions, `*.local.*` names, product `*@specy-road.invalid` addresses, `sr/` examples in product text and the shipped template paths all pass with no file-level allow entry.

## If this fails

Assumption: default mode exits 0 on this tree outside `sr/` with the bounded rules, once M22.55 and M22.56 have landed. If it does not, stop and list the hits; the coordinator narrows a rule. Do not add file-level allow entries.

## Accepted limits

- History before the checked range is not scanned; M22.58 rehearses the rewrite.
- Name tokens are skipped when the local list and the CI secret are both unset; emails, paths and the other bounded rules still run.
- On the WIP line, default mode skips the tracked `sr/` tree and applies no path denylist; a new process-content path on WIP is refused only at a pull request to main.
- The identity check is advisory until the operator sets the public identity.
- `scripts/lean_metrics.py` stays off the path denylist while it is tracked.
- An email-shaped token whose domain is a file name or decorator (`n@pytest.mark…`, `x@AGENTS.team.md`) is not an email; the implementation's email pattern must not match those.
