## Intent

Personal data, machine setup and development-process content have reached the public tree and its history: email identities in commit metadata, session links in commit messages, home paths and private names in roadmap files, and process notes on main. Today's `check_machine_paths.py` catches only home paths and Mac hostnames in files. Before anything else in the sweep moves, a gate must refuse new leaks in tracked files and in commit messages, so the later steps do not have to be repeated. First pass of the sweep, inside RC5. Source: the maintainer's scrub plan (private), sections 2 and 5, approved 2026-11-09.

## Approach

Extend the existing gate rather than adding a second one: rename `scripts/check_machine_paths.py` to `scripts/check_public_hygiene.py` and give it three categories, each a regex list.

- **(a) Personal data:** email addresses not in the allowlist; registry `owner:` values; presence session names built from the username; the maintainer's name tokens and username.
- **(b) Machine setup:** today's path patterns; `~/` paths outside allowlisted tool config directories; account-directory names; `CLAUDE_CONFIG_DIR=` with a literal value; home-prefixed conda or venv paths; apparmor.d profile names and `kernel.apparmor_restrict_unprivileged_userns` values; `-MacBook` and `.local` hostnames; machine names; `/tmp/claude-<uid>`.
- **(c) Process content:** a path denylist (`sr/`, `docs/design-notes/`, `scripts/census/`, `scripts/review_effort_study.py`, any `research/` directory, `*-prompt.md`, `handoff-*`) and a text denylist (`deep-research report`, `claude\.ai/code/session_`, `Claude-Session:`, `\bsr/(work|planning|roadmap|tools)` outside `.gitignore`, and private names and phrases).

Values that would themselves leak (name tokens, username, machine names, account-directory names, private names) are read at run time from git config, the environment, an untracked local list, or a CI secret. They never sit in a tracked file. `scripts/public_hygiene_allow.txt` holds only allowlist patterns:

- `noreply@anthropic.com`, `*@users.noreply.github.com`, `noreply@github.com`, `cursoragent@cursor.com` and the dependabot address;
- the placeholders `x` and `<name>`, and test identities such as Alice and Test User;
- the repo-owner handle in github.com URLs (allowed while the repo lives under that account);
- one **public author identity** entry, shipped as an explicit placeholder that the operator fills in.

While that entry holds the placeholder, the gate treats the public identity as unset and fails closed on the author and committer identities of new commits, that is commits in the checked range. It never checks earlier history; the rewrite (M22.58) handles that.

The same checks run over commit messages (`git log --format=%B base..head`). Pre-commit runs the file check; a `commit-msg` hook runs the message check; `validate.yml` runs both, plus the identity check over the PR range. Until M22.60 lands, `sr/` is still tracked on the WIP line, so the file check skips `sr/` there and the path denylist applies only to pull requests to main and to release-publish. `scripts/lean_metrics.py` is not on the path denylist in this pass (see M22.55).

## Tier

behavioural: a pattern gate whose failure is a missed leak or a blocked commit, checked by table rows; it decides nothing about review or landing.

## Done but wrong

- The gate leaks what it guards: `git grep` over the tracked tree after the leaf finds none of the name tokens, username, machine names or private names the local list holds (the test fixtures build such values with string concatenation, as `tests/test_lean_gates.py` does today for the MacBook row).
- The placeholder passes: with the allowlist entry still the placeholder, a range commit authored by a non-allowlisted address fails, and a range commit authored by `noreply@anthropic.com` passes.
- Product docs fail: the `~/.specy-road`, `~/.claude` and `~/.cursor` mentions in CHANGELOG.md, docs/ and the GUI, and the nested `sr/` layout examples in product tests, pass, and each exception is a named allowlist pattern, not a skipped directory.

## If this fails

Assumption: the text denylist can be applied to the tracked tree outside `sr/` with a short allowlist. About 49 files outside `sr/` match the category (c) text patterns today, many of them product tests and parity records that use `sr/` as a nested project root example. If the allowlist needs more than a handful of file-level entries, or a parity golden would have to change, stop and list the files; the coordinator decides whether to narrow a pattern.

## Accepted limits

- History before the checked range is not scanned; M22.58 rehearses the rewrite.
- In CI without the secret, the name and username tokens are not checked; emails, paths and categories b and c still are.
- The tracked `sr/` tree on the WIP line is outside the file check until M22.60.
- `scripts/lean_metrics.py` stays off the path denylist while M22.55 keeps it tracked.
