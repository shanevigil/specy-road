## Intent

When an adopter runs `upgrade`, tell them what changed for their repo, not just which files were written: the behaviour changes since the version their block was stamped with, a pin left below the minimum the new block declares, an accurate list of the new untracked files, and (on request) paragraphs of their own text that restate the new rules file. Also let a deliberate release-candidate trial silence the pin-mismatch warning until the version changes.

## Approach

- Put the logic in new `specy_road/upgrade_report.py` so `upgrade.py` gains only calls (after M13.2 it will be larger).
- **Behaviour changes.** Before refreshing, read the version stamped in the existing managed block (`recorded_toolkit_version()` in `specy_road/version_skew.py`, or the `Written by` line) or, with no block, the pin (`version_pin.pinned_version()` from M13.8). Print every `behaviour_changes` entry (M13.8) whose `since` is newer, using the same version ordering as `version_skew._version_sort_key`.
- **Pin below minimum.** After writing, compare the pin with the "minimum" the new block declares; if lower, print the pin's file, both versions and what to change.
- **RC acknowledgement.** In `specy_road/version_pin.py`, `warn_if_pin_differs()` skips the warning when `.specyrd/manifest.json` records `pin_trial: <running version>`; a new flag (`upgrade --trial`) or documented manual key writes it. The marker stops applying when the running version changes. Pick the smaller surface and document it.
- **Closing hint.** Replace the fixed "new schema and skill files are untracked" step in `upgrade.py` with the kinds actually created, from the lists `_refresh()` already gets back (schemas, profiles, docs, stubs, `.specyrd/` files).
- **`--report-duplicates`.** Function in `specy_road/agent_text_report.py`: split project text outside the managed block and `.specyrd/AGENTS.md` into paragraphs, normalise (lower-case, strip punctuation and markdown), and report a pair whose word-set Jaccard overlap is at least a stated threshold (start at 0.6; the test fixes it). Output: `file:line ~ <rules heading>`. Report only.
- **Verify.** Tests: older stamp → listed changes; current stamp → none; pin below minimum; trial marker silences, version change re-arms; schemas-only upgrade hint; duplicate paragraph found, unrelated paragraph not.

## Tasks / checklist

- [ ] A1 — Behaviour changes since the stamped version (or pin) printed; none when current.
- [ ] A2 — Pin below the new minimum named plainly; RC pin warning can be acknowledged and re-arms on version change.
- [ ] A3 — Closing hint names only the kinds of new files created.
- [ ] A4 — `upgrade --report-duplicates` lists closely restated paragraphs with file:line; report only.
- Out of scope: rewriting or deleting project text; the heading-level notice (M13.3); changing which refreshes run.
