## Intent

Two review-path warnings from the rc4 checks.

- W1 (sol). `review delegate` builds its reviewer launch in `_Harness` (review_delegate_harness.py:23-50) and never calls `reviewer_command` (role_prompt_cli.py:124), the validator `prompt --channel cli` uses. As a result, a roster `channels.cli` such as `agent --force {prompt}` passes unchanged, because `reviewer_cli` refuses a bypass flag only for `agy`. A `generic` entry without `channels.cli` also falls back to the profile's `access.cli`, which `reviewer_command` refuses ("the profile's access.cli is never run for a reviewer"). One configured reviewer is refused by one entry point and launched with write permissions by the other.
- W2 (grok). `reported_models` (review_model_check.py:47) splits the harness log with `str.splitlines`, which also breaks on U+2028, U+2029 and other separators a JSON string may carry unescaped. A `result` event with a different model can then fail to parse, and the mismatch is hidden. `final_answer` and review usage already split on `\n` only (`review_answer.stream_lines`).

Choice for W2: split on `\n` only by reusing `stream_lines`. The record's structured field is filled from this same parse, so fixing the split fixes both.

Out of scope: the chore reviewer launch (`chore=True` keeps its documented launch, including Claude Code's bare reviewer command; stated in a test); Codex reviewer memory/home isolation (rc5 M22.9); the tripwire; docs (docs/orchestration-review.md:322's bare claim is M21.23).

Overlaps checked (2026-11-05): M21.18 edits review_deferral / next-step / rework files, not these. M21.17 edits review_delegate_packet.py, which `review delegate` calls before `_Harness`. No shared file.

## Approach

- `_Harness.__init__` (non-chore): call `reviewer_command(prof, entry, model)` and raise `HarnessSetupError(err)` when it refuses. Drop the generic `prof.cli()` fallback for non-chore reviewers. The error happens before any run artifact (`RUN-<model>.json`, log) is created and before `preflight` runs. The resume path is covered because both launch and resume use the same `_Harness`.
- `reported_models`: iterate `stream_lines(lines)` when given a str (import from review_answer, or move the helper to a shared spot without changing its behaviour).
- Tests:
  - Parametrize one refusal table over both entry points (`prompt --channel cli --run` and `review delegate`, the latter also with `--resume`) for `agent --force {prompt}`, `--yolo`, a line-continued `--for\<nl>ce`, and a generic entry with only a profile `access.cli`. Each is refused with the same reason text, no process started (fake harness binary never invoked) and no `RUN-<model>.json`.
  - A clean custom command still launches.
  - A `result` line containing U+2028 inside a string with a model differing from the roster's gives `check_run` → `mismatch`, and the filed record has `model_mismatch` and does not count.
