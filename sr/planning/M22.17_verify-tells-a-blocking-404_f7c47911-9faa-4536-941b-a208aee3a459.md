## Intent

D16b, Low (rc4 re-test 2026-11-06). Four of the eleven sources in the §6.6 evidence step were ftc.gov pages. The agent's WebFetch had read them, but ftc.gov answers `User-Agent: specy-road brainstorm verify` with HTTP 404 "Page Not Found" (curl's default user agent gets 403). Verify maps every non-200 status except 401, 403 and 429 to `not-found`, so these real pages were recorded as if their URLs did not exist. `not-found` on a URL reads as "the agent made this up"; `blocked` means "could not check", which is the honest state here.

Decision: on a 404 or 410 for a page, ask the same host for its root URL once. A host that also refuses its root is refusing verify, so the source is `blocked`. A host whose root answers 200 really has no such page, so the source stays `not-found`. The user agent is unchanged: verify keeps identifying itself. The extra request goes to a host the user already agreed to fetch from, and it follows the same allow-list, redirect, timeout and size rules. Its result is cached per host for the run.

Overlaps checked (2026-11-06): M21.36 (rc4) edits `_norm` in the same file, so this leaf depends on it. No other open leaf lists brainstorm_verify.py.

## Approach

- `check_source` takes an optional `roots: dict[str, bool]` cache, filled by `verify` for one run.
- On status 404 or 410, `host_answers(url, fetch, roots)` fetches `https://<host>/` through the same `fetch` and caches whether it returned 200.
  - False, or a fetch exception, gives `blocked`.
  - True gives `not-found`.
- Other statuses are unchanged.
