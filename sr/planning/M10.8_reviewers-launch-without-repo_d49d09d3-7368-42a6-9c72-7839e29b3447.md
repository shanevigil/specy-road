## Intent

Claude Code's headless docs say a `-p` session without `--bare` runs a project's hooks and connects its MCP servers even in an untrusted folder. A fresh-session reviewer reading a branch it did not write should not execute that branch's hooks. Running reviewers bare is also faster to start. The review record should say which mode the reviewer ran under.

## Approach

Add `launch_mode` to `review-record.schema.json` and `specy_road/review_files.py`; `review record --launch-mode` in `review_cli.py` (369 lines, cap 400: keep it to the flag). In `role_prompt.py`, the reviewer prompt asks for the flag; the default Claude Code reviewer command (no `channels.cli`) is built bare with `--add-dir` for the reviews directory. Update `sr/tools/claude-review.sh` to `--bare`. Docs in `docs/orchestration-review.md`. Depends on M9.4 and M9.5 landing (they edit `review_cli.py` and that doc). Verify with `pytest tests/test_review_files.py tests/test_models_and_prompt.py`.

Converge verdict (brainstorm `agentic-performance`): Principle 6 (fresh-session reviewer) and M8.3 (read-only reviewer) point the same way; record launch mode in the review file. Docs: orchestration-review.md record fields; orchestration-workers.md roster setup.
