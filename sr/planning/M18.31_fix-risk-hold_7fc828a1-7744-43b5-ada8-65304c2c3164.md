## Intent

M18.28 reports a leaf's fix-risk triggers and changes nothing. This leaf lets a project hold the gate on them: one operator answer, given once at the commit that would land ("may this land?"), instead of an operator answer per fix round. It is the product side of the landing holds T2 (tests weakened), T3 (baseline, permission or declared files) and T4 (plan change) in `sr/work/planner-2026-11-11-review-rules/proposal-v2.md`. The trust replay (T1) stays in the grind until it has run in shadow; this leaf adds no automatic clearance, so the product never clears on weaker evidence than the grind.

**Out of scope:** clearing by reviewer footers or a coordinator's standing rule; the trust replay; changing `max_fix_rounds` or the `escalate_*` keys; sending fix rounds (M18.21).

## Approach

- Read the triggers from M18.28's `review_fix_risk.py`. An `unknown` trigger holds, as a real one does.
- Clear through the existing `review operator-decision` route, extended so the answer can name `fix_risk` and the trigger kinds it settles. Only `decided_by: operator` clears; the coordinator form is refused here.
- `fix_risk_gate: true` with either list missing or empty is a policy error that holds every leaf in review, so a half-configured project fails closed.
- The gate (`review_gate.py`) and `mark-implementation-reviewed` read the same function, so `handoff status` and the gate never disagree.
