## Intent

D15, High (rc4 re-test 2026-11-06). `review delegate` loses most real reviews to the approve-notes rule in `specy_road/review_record_rules.py` (`clause_problem`, `_second_observation`): on an approve, every notes line or findings entry that is an observation needs "not a defect because <reason>", one explanation per clause. Two of five fresh Claude Code reviews and every Cursor review that produced an answer (3 of 3) were refused. The refused lines were ordinary approve output: summary sentences, "A1 (pass): …" lines with detail, and findings that carried the marker after a `;`-joined first clause.

`--resume` cannot repair a refusal. The resumed turn received only the continue prompt (`RESUME_PROMPT`), never the refusal reason, so the reviewer returned the same notes and was refused again.

specy-road's own coordinator avoids this in two ways: it appends the rules to the reviewer prompt in operational form (sr/tools/review-addendum.md), and it retries once after a refusal (sr/tools/rv.sh). Adopters get neither.

Decisions:

- **The rule is not loosened.** That is a separate maintainer decision. This leaf changes what the reviewer is told and when, and gives it one chance to repair.
- **Where the rules go.** They go in the prompt's last section (`schema_lines`), right before the JSON schema, which is what the reviewer reads immediately before writing its final answer. They are in the addendum's operational form. Rule 4 of PROBE_RULES_LINES, early in the prompt, keeps a one-line pointer to that section. No test sets a byte budget on the reviewer prompt today, so none changes.
- **One repair turn, only for a record refusal.** A parse or schema rerun request, a review failure (the run wrote a file) and a chore reviewer behave as today. The repair resumes the reported session when the harness can resume. Otherwise it is one fresh launch with the full prompt, with the refusal section added.
- **The refusal text is whole.** The repair prompt carries every offending line as `review record` printed it. Today's `said[-400:]` cut stays only in the one-line summary, which M22.16 fixes.

Out of scope:

- `prompt --channel cli --run`'s own retry. M18.16 makes every reviewer channel leave a run record, and that path can reuse this later.
- The coordinator's sr/tools addendum and rv.sh retry. The coordinator may drop them after this lands, but that is not part of the product change.

## Approach

- `review_record_rules.py`:
  - `NOTES_RULES_LINES`: the operational rules, worded from review-addendum.md's first block with the coordinator-specific parts removed.
  - Rule 4 of PROBE_RULES_LINES shortens to "List every defect under `required_changes` (and block); the last section before the schema says how to write each other line so `review record` accepts it."
- `review_record_write.py`:
  - `schema_lines()` puts NOTES_RULES_LINES before the schema block.
  - `Outcome` gains `refusal: str` (the full `review record` output), set by `file_review` on a refusal.
  - `repair_prompt(refusal)` returns the refusal section, the notes rules and "Send the whole corrected JSON object as your final message."
- `review_delegate._delegate_locked`:
  - When the outcome is a refusal and the reviewer is not a chore reviewer, write the repair prompt file (`-repair` suffix) and run `_attempts` once more. That turn resumes the session when it can, and otherwise launches with the full prompt plus the repair section.
  - Mark the new attempts `repair: true`, store `run["refusal"]`, re-snapshot, and file again.
  - On a second refusal, the reason joins both.
- `_start` with `--resume`: when the previous record has a `refusal` and is for the same commit, return the repair prompt instead of RESUME_PROMPT.
- tests/review_delegate_helpers.py: the fake harness gets a per-turn answer list.
