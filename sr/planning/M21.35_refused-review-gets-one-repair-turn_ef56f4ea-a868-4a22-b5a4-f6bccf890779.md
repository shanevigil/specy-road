## Intent

D15, High (rc4 re-test 2026-11-06). `review delegate` loses most real reviews to the approve-notes rule in `specy_road/review_record_rules.py` (`clause_problem`, `_second_observation`): on an approve, every notes line or findings entry that is an observation needs "not a defect because <reason>", one explanation per clause. Two of five fresh Claude Code reviews and every Cursor review that produced an answer (3 of 3) were refused. The refused lines were ordinary approve output: summary sentences, "A1 (pass): …" lines with detail, and findings that carried the marker after a `;`-joined first clause.

`--resume` cannot repair a refusal. The resumed turn received only the continue prompt (`RESUME_PROMPT`), never the refusal reason, so the reviewer returned the same notes and was refused again.

specy-road's own coordinator avoids this in two ways: it appends the rules to the reviewer prompt in operational form (sr/tools/review-addendum.md), and it retries once after a refusal (sr/tools/rv.sh). Adopters get neither.

Decisions:

- **The rule is not loosened.** Maintainer decision 2026-11-06: `clause_problem`, `_second_observation` and `note_problem` stay as they are, and tests/test_review_record_rules.py passes unmodified. This leaf changes what the reviewer is told and when, and gives it one chance to repair.
- **Where the rules go.** They go in the prompt's last section (`schema_lines`), right before the JSON schema, which is what the reviewer reads immediately before writing its final answer. They are in the addendum's operational form. Rule 4 of PROBE_RULES_LINES, early in the prompt, keeps its first sentence (asserted by `test_reviewer_prompt_carries_the_four_probe_rules`) and a pointer to that section in place of the rest. No test sets a byte budget on the reviewer prompt today, so none changes.
- **One repair turn, only for a record refusal.** A parse or schema rerun request, a review failure (the run wrote a file) and a chore reviewer behave as today. The repair resumes the reported session when the harness can resume. Otherwise it is one fresh launch with the full prompt, with the refusal section added. Capacity retries inside the repair phase keep the refusal text.
- **The repair turn is checked like the first.** A snapshot right before the repair launch, the existing write check after it, and `model_check` recomputed from the repair attempt's own log span; the launch keeps the same read-only restrictions.
- **The refusal text is whole.** The repair prompt carries every offending line as `review record` printed it, fenced as that command's output. Today's `said[-400:]` cut stays only in the one-line summary, which M22.16 fixes.
- **M18.24 defers to this leaf.** M18.24 (review run queue, after 0.3.1) planned its own refusal retry and `--refusal-retries`. Its acceptance now says record refusals are repaired by this leaf's turn, with no flag and no retry of its own, and it depends on this leaf.

Out of scope:

- `prompt --channel cli --run`'s own retry. M18.16 makes every reviewer channel leave a run record, and that path can reuse this later.
- The coordinator's sr/tools addendum and rv.sh retry. The coordinator may drop them after this lands, but that is not part of the product change.

## Approach

- `review_record_rules.py`:
  - `NOTES_RULES_LINES`: the operational rules, worded from review-addendum.md's first block with the coordinator-specific parts removed.
  - NOTES_RULES_LINES states how lines are split and checked: each clause split on `. `, `; ` or a conjunction (`and`, `but`, `while`) is checked on its own; the marker stands outside backticks; the reason names no defect; `A1: pass` followed by more words is an observation.
  - Rule 4 of PROBE_RULES_LINES keeps its first sentence ("List every defect your notes or findings describe under `required_changes` (and block), or explain on that same line why it is not one, starting `not a defect because`.") and replaces the rest with "The last section before the schema says how to write each other line so `review record` accepts it."
- `review_record_write.py`:
  - `schema_lines()` puts NOTES_RULES_LINES before the schema block.
  - `Outcome` gains `refusal: str` (the full `review record` output), set by `file_review` on a refusal.
  - `repair_prompt(refusal)` returns the refusal section (the text in a fence longer than any backtick run in it, introduced as `review record`'s output), the notes rules and "Send the whole corrected JSON object as your final message."
- `review_delegate._delegate_locked`:
  - When the outcome is a refusal and the reviewer is not a chore reviewer, write two prompt files: the full prompt plus the repair section (`-repair-full`) and the repair section alone (`-repair`). Call `_attempts` once more with that pair, so a resumed launch and every capacity retry carry the refusal (`_attempts` picks `prompts[1]` whenever a session is set).
  - Snapshot right before that call; after it, recompute `model_check` from the last repair attempt, snapshot again and file with the existing write check.
  - Mark the new attempts `repair: true`, store `run["refusal"]`.
  - On a second refusal, the reason joins both.
- `_start` with `--resume`: when the previous record's `state` is `incomplete`, its commit is the one under review and its `refusal` is a `str`, use the same repair file pair instead of RESUME_PROMPT. A complete run, a missing or non-string `refusal` (no traceback) keeps RESUME_PROMPT.
- tests/review_delegate_helpers.py: the fake harness gets a per-turn answer list and records the prompt each launch received.
