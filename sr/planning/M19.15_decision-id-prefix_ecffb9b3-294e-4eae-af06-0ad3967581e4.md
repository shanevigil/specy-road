## Intent

The ledger numbers new entries `D1`, `D2`, … (and `P1`, … for preferences). Projects often number their own decisions the same way in their docs. One adopter had a dozen governance files using `D1`–`D9` for its own decisions and had to rename about a hundred prose references and several acceptance strings to tell them apart from the ledger's ids. This leaf makes new ids namespaced by default and configurable per project. Existing ledgers keep the ids they already have.

**Out of scope:**
- Rewriting or migrating existing ids. Old `D#` and `P#` ids stay valid forever.
- Renaming references in project prose.
- Per-kind prefixes. A single prefix covers every kind; the entry's `kind` field already says what it is.

## Approach

- Source: adopter feedback on 0.3.1rc3 (item 24, sanitized), filed 2026-11-05.
- Prefix setting: an optional top-level `id_prefix` in `roadmap/decisions.yaml`, so the ledger declares its own ids and no second config file is involved. When it is unset, the default is `DEC-`.
- Numbering: n is one plus the largest integer matched by `([0-9]+)$` on any existing id, local ledger included (`decisions_local.next_id`). A `--local` add takes the local `id_prefix`, then the tracked one, then `DEC-`. A new `DEC-5` therefore never shares a number with an old `D5`.
- Read both forms: every command that takes an id (`close`, `--supersedes`, `list`) matches the stored id string exactly, as today. The only change is how new ids are generated.
- Clash warning: a literal search for the new id, bounded by characters outside `[A-Za-z0-9._-]`, in `constitution/`, `constraints/`, the root `AGENTS.md` and `planning/*.md`. It warns and never refuses, because a clash in prose does not make the ledger wrong.
- Schema: `id_prefix` must start with a letter and use the same character class as `id`. It goes in the bundled `decisions.schema.json` and this repo's `sr/schemas/` copy, and refresh-schemas or upgrade delivers it to consumers.
- Depends on M16.5.10 (decisions code moves to `specy_road/orchestration/records/` with byte-for-byte parity, which this leaf must not disturb for ledgers without `id_prefix`) and M16.4.3 (reshapes `decisions_cli.py`).
