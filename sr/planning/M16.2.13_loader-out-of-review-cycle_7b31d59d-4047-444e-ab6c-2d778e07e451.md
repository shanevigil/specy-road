## Intent

M16.2.7 was meant to take the graph loader out of the review stack's import cycle. It did not: the hold code moved into `milestone_review_hold`, which is still in the cycle, and the check passed because it was keyed on a module name (post-landing review F2). The maintainer chose option A on 2026-11-10: M16.2.7's cycle line now reads "`roadmap_load` shares no component with `review_gate`", and this leaf meets it. It also takes F5 (the import-layer test can pass vacuously) and F3's stray lazy import from the same review.

## Approach

- Depends on: M16.2.11, so after M16.2.12 too (M16.2.9 depends on M16.2.12). Placement is explained under Ordering below.
- Behaviour-preserving, in M16.2.7's style: the parity harness (M16.1.1) and the review-gate decision table (M16.1.2) stay green; no function rises above its merge-base complexity; docstrings and comments that explain intent are kept or improved, never cut to save lines. Report `scripts/lean_metrics.py --check` deltas in READY.
- **Direction.** The hold stays on the public loader: `roadmap_load` keeps importing `milestone_review_hold`, which needs `review_gate`. So the cycle can only be broken from the other side: nothing `review_gate` imports, directly or transitively, may import `roadmap_load`.
- **Size of the job, measured at 11b22cd7 (after M16.2.8)** with `scripts/check_import_layers.py`'s `scan_imports` and a max-flow cut. The component has 146 modules. `review_gate` reaches 244 modules, 28 of them import `roadmap_load` directly, but the minimum edge cut between them is 8 edges:
  - `review_policy_pin -> roadmap_load` (the accept-policy command path, `:305`, `:369`)
  - `review_override -> roadmap_load` (`cmd_operator_decision`, `:381`)
  - `review_tally -> roadmap_load` (`flagged_areas`, `:278`)
  - `orchestrate_plan -> roadmap_load` (`build_orchestration_plan`, `:149`) and `orchestrate_plan -> session_plan_git`
  - `agents_md_block -> digest` (a constant, `DEFAULT_OUTPUT`)
  - `init_project -> generated_files`
  - `worker_state -> worker_cli_sync` (a function-level import, `:302`)
  Removing those 8 edges in a scratch copy separates the two modules, and `review_gate` then reaches 109 modules. The edges M16.2.12 adds (`review_packet` and `worker_ops_launch` importing `roadmap_load`) are on the far side of that cut.
- **First commit:** recompute the cut at the pickup head (M16.2.9 to M16.2.12 change the graph) and record the edge list on this sheet, each with the planned move. Then for each edge, either:
  - move the importing function up into a module `review_gate` does not reach, normally the command module that calls it (for example `review_policy_pin`'s and `review_override`'s command handlers into their CLI modules); or
  - have its caller pass in the graph it already loaded from `roadmap_load`.
- Never switch a function to `roadmap_graph.load_roadmap`: that drops the hold, which is what F1 did. Importers of a moved name are updated; nothing re-exports the name from its old module, because a re-export restores the edge.
- **F5:** `tests/test_import_layers.py` keys the cycle check on the pair (`roadmap_load`, `review_gate`), for both the live report and the committed baseline. The entry-point check first asserts the report has edges. `ENTRY_POINT_STEMS` is used or removed. M16.2.8 has landed, so the `chore_cli` hold-over note no longer applies.
- **F3:** `held_milestones` imports `compute_rollup_status` from `roadmap_graph` at module level. `roadmap_graph` does not import the hold, so no cycle needs the lazy import.

## Ordering

- No sheet in M16.2.9 to M16.2.11 addresses this cycle, so placing it first would make one of them inherit the work.
- `review_gate` reaches `cli` today (`review_deferral -> decisions -> validate_stale_commands -> cli`). M16.2.9 makes `cli` import every command module, and many of those import `roadmap_load`. If this leaf landed first, M16.2.9 would re-merge the cycle and fail the new pair test, in a file (`validate_stale_commands.py`) outside its zones. M16.2.10's per-command `build_parser()` and import changes move the same edges again.
- So it goes last in M16.2, after M16.2.11, and works on the CLI shape those leaves leave behind.
- M16.3.1 (also after M16.2.11) is not made to depend on this leaf. It is on the path to the M17 GUI work, and its zones overlap this leaf's (`worker_state.py`, `orchestration_config.py`, the baseline), so the two leaves cannot run at the same time anyway. Whichever lands second keeps the pair test green.

## Tier

trust boundary: the moves touch review code (`review_policy_pin`, `review_override`, `review_tally`) and worker state on tier.py's trust path list. The obvious shortcut, using the loader without the hold, would silently show held milestones as Complete to the gate's callers, as F1 did.

## Done but wrong

- **The cycle is re-keyed on a new module name.** For example, the hold moves into a third module that `roadmap_load` imports, or `load_roadmap` moves into a module with another name and `roadmap_load` re-exports it. Check: the pair test names `roadmap_load` and `review_gate`, and `roadmap_load.load_roadmap` itself still calls the hold.
- **A function switches loaders.** Check: no function in this diff gains a `roadmap_graph` import in place of a `roadmap_load` one, and the hold tests stay green.
- **A moved name is re-exported from its old module.** Check: the regenerated report keeps the two modules apart.
- **The test checks only the committed baseline**, so code that re-merges the cycle passes until someone regenerates it. Check: the live-report row.

## If this fails

The assumption most likely to break is that the cut found at pickup can be removed by moves alone. Some cut edges may sit inside functions the gate itself calls, for example `review_tally.flagged_areas` for strong review, where the graph cannot come from a command-layer caller without a signature change through the gate. If an edge needs more than a move or a passed-in graph, stop and report the edge and the options; the coordinator decides. If meeting the line needs a new public loader, or moving the hold off `roadmap_load`, the maintainer decides.

## Accepted limits

- `roadmap_load` still reaches `review_gate` through the hold, so the graph loader still loads the review stack on first use. Option A asks only that the two share no component.
- Other cycles that remain in the component are not this leaf's: M16.3.3 takes the nested-repo cycle.
- F4 (dead re-exports in `generate_brief.py`, unused imports in `validate_roadmap.py`) is out of scope.
