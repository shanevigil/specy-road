## Intent

Reviewers today judge correctness against the acceptance lines. Code can pass that and still be poorly formed, and fix rounds tend to degrade it: a special-case branch per finding, a copied rule, a stripped comment, a new `noqa`. Give reviewers a bounded code-quality section beside correctness, so structure is checked on every review and a fix round is checked for degradation, with required changes that fix the class of defect rather than the instance.

## Approach

- Three parts, each a named section of the reviewer prompt and checklist: structure; fix-round degradation (a fixed list of signals); the complexity delta that M16.22 puts in the packet, blocking on growth only when policy says so.
- No new record-refusal rules: the record rules already cause reruns. The quality section changes what a reviewer looks for and writes, not what makes a record valid.
- Stopgap today: the coordinator's dispatcher already runs a post-fix complexity precheck before re-review; this leaf makes the check part of the product's reviewer prompt and packet.
- Related, not merged: M15.30 (the full-leaf checklist under delta review, also moved to M18) — keep the two consistent when both land.
- Depends on: M16.22 (complexity delta in ready and the packet) and M16.21 (review gate and packet fold), and the phase's dependency on the 0.3.1 tag gate M16.66.
