## Intent

When a reviewer blocks a leaf in the unattended loop, send the standard fix round automatically, cap the rounds with the existing fix-round budget, and park the leaf for a human when the budget is spent. Today the product has the pieces (`worker message --fix-round`, M14.11; `policy.max_fix_rounds` and its next-step table, M12.1), but a person has to notice each block and send the round. On 2026-11-05 five blocked leaves idled 20 to 30 minutes because nobody did (RE 15:23); the coordinator then ran `AUTO_FIX=1 AUTO_FIX_MAX=4` and a manual `fixrounds.py`.

**Out of scope:** the fix-round prompt text (M14.11; carrying blocks and a coordinator note is M18.15); launching a root-cause analyst (M18.10); a second cap besides `policy.max_fix_rounds`.

## Approach

- Opt-in `grind.auto_fix` in `git-workflow.yaml`; the cap is `policy.max_fix_rounds`, counted exactly as `handoff status` counts it. Turning auto-fix on without a budget is a validate error, so an unattended loop can never iterate without bound.
- One round per blocked commit, never while a review of the leaf or its worker is running: messaging a leaf mid-review made Grok and Sol review different commits (RE 2026-11-04, M12 orchestration, "sending a leaf back ... while its review was already running").
- A round is done only when the branch tip moved and READY names it (RE 2026-11-03 08:10: a completed state from the previous turn was taken as the fix).
- Escalation wins over a fix round (RE 2026-11-03 17:05: an RCA and a fix round cannot run at once).
- Parking writes the M18.20 hold list with the reason, as the overnight run did by hand (OD 03:17, 03:56, 07:00, 07:05).
- Depends on M18.20.
