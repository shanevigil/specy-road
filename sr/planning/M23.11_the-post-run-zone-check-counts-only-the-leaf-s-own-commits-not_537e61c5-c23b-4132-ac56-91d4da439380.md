## Intent

The post-run git check flags paths a worker turn "committed outside the touch zones". It collects paths over the turn's start HEAD to end HEAD. When the worker merges or fast-forwards the integration branch during the turn, commits already on that branch (for example a plan amendment made after claim) fall inside the range and are reported as the worker's own. The leaf is then not queued for review, and someone has to queue it by hand. Seen on a claimed leaf whose plan was amended after claim: the only finding was its own planning sheet, changed by the integration commit.

## Approach

In the outside-zones check, exclude commits reachable from the integration ref the worker state already reads (`git_state` records its tips), so the range is the leaf's own commits only. Keep a leaf's own out-of-zone commit a finding. An integration ref that cannot be read stays a `check_error`. The file moves under `orchestration/workers/` in M16.5.1, so this leaf follows it.

- [ ] Unreadable integration ref is a check_error, not a pass

## Done but wrong

- A leaf commit that also touches an out-of-zone file is hidden because the same path changed in an integration commit too: the check must exclude commits, not paths.

## If this fails

If the integration ref the state records is not the one the worker merged, stop and name the ref; do not guess a remote.
