## Intent

The managed block's "Task pickup" item explains `do-next-available-task --local` so that agents will avoid it. Naming the opt-out invites agents to use it. In the M5.7 study the one Cursor run that claimed with `--local` had read that item, and its claim never reached the remote. The block should say only that pickup pushes the claim and that the agent must not skip it.

## Approach

- Source: `docs/design-notes/managed-section-ablation.md` ("Test further", item 2: "Drop `--local` from the managed block … The block should keep only 'pickup pushes the claim; do not skip it'"), and the 2026-11-05 milestone audit (`sr/work/milestone-audit-2026-11-05.md`, M5 gaps: line 66 of `specy_road/templates/specyrd/agents-rules.md` still names `--local`).
- Exactly which text changes: the "Task pickup" bullet in `specy_road/templates/specyrd/agents-rules.md` and its `<!-- prevents … -->` provenance comment. The comment currently says "--local is the only opt-out".
- `--local` itself stays: `do-next-available-task --help` and `docs/dev-workflow.md` keep documenting it, and its behaviour is unchanged.
- Out of scope: `specy_road/templates/adoption/005-do-next-registry-publish.mdc`, which also names `--local`. The study covers only the managed block, so that file needs a separate decision.
- Depends on M19.3, which edits the same template, and on M16.30.
