## Intent

Found while coordinating M10 (2026-11-02). The wrapper is started as `python -m specy_road.worker_runner` with `cwd` set to the leaf's worktree. In module mode Python puts the current directory first on `sys.path`, ahead of the `PYTHONPATH` entry `worker_runner` sets for the launching package, so the wrapper imports the worktree's own `specy_road`. When the leaf's branch predates a change to the runner's arguments (here M10.4), the old runner crashes before opening its log: the worker sits as running until a sweep marks it "wrapper pid is gone without recording an exit". Three workers (M5.4 twice, M10.7) died this way, and a branch that needs a merge to catch up cannot get an executor to do that merge.

## Approach

Add `-P` (safe path, Python 3.11+, already the project minimum) to the wrapper's `Popen` argv in `spawn`, right after `sys.executable`. It affects only that interpreter, so the harness and the executor's own `python -m pytest` runs keep importing the worktree's code as they should. Do not set `PYTHONSAFEPATH` in the environment, since the harness inherits it. Test through the public spawn path with a worktree that holds a deliberately broken `specy_road/worker_runner.py`, and assert the harness environment carries no safe-path setting. Verify with the worker test files and `specy-road file-limits`.
