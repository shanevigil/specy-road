## Intent

A field run with sibling repositories not set in `nested_repos` could not get an approval to count. `review delegate --worktree` ran the reviewer in the leaf, but the record stored the main checkout's sibling heads. `heads_problem` then needs an exact match with every sibling clean, so unrelated dirt in other repositories staled the record and the answer depended on where it was asked. Mechanism read here: `_review_record_signed_data` stamps from `root`, and the gate evaluates `sibling_repos(repo_root)`.

## Approach

Stamp sibling heads from the checkout the reviewer ran in. Limit `heads_problem` to siblings the leaf's touch zones name; a leaf that names none has nothing to go stale. Evaluate the same set from either checkout. This narrows a staleness check, so keep it strict for named siblings and say so in docs. Fix the `review list` wording and the block count at the same time.
