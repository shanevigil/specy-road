## Intent

Defect D5 (Medium) from the rc4 real-harness checks (pre-release evidence 2026-11-05, ToDo app). The app had `require_implementation_review_before_finish: false` in git-workflow.yaml and `policy.reviewers_required: 1` in orchestration.yaml. In that state, `finish-this-task` printed `[ok] status -> Complete` and `[ok] removed registry entry`, then validate's error ("orchestration.yaml requires 1 reviewer(s) … but git-workflow.yaml leaves require_implementation_review_before_finish off …"), then a Python `CalledProcessError` traceback, and exited 1. `roadmap/phases/M2.json` and `roadmap/registry.yaml` were left modified and uncommitted.

The configuration was invalid. The defect is that finish found out only after it had written bookkeeping, and that a failure there leaves a half-mutated tree behind a traceback.

Fix: finish runs validate before its first bookkeeping write. Any failure of validate, export or digest before the bookkeeping commit restores what bookkeeping wrote and ends in a clean error.

Out of scope: the gate-agreement rule itself (review_gate_agreement.py, unchanged); the merge-landing undo after the commit (M15.40, unchanged); finish's landing modules (M22.10).

Overlaps checked (2026-11-05): no M21.16 to M21.23 zone names finish_task.py. M22.5 and M22.14 (rc5) also list finish_task.py, and this leaf lands first in rc4.

## Approach

- In `_finish_locked`, before `_bookkeeping_commit_phase`, run the same `specy-road validate --repo-root` that `_validate_export_digest` runs, capturing its output. On a non-zero exit, print its output and `finish-this-task: nothing was changed`, then exit 1. Do this after the branch, override and context checks, and before the PR-body snapshot write.
- `_validate_export_digest` fails without an exception: on a non-zero exit, restore the files `_bookkeeping_commit_phase` changed so far (chunk, rolled-up ancestors, registry; `git restore --source=HEAD --staged --worktree --` on the tracked ones). Print the failing command and `nothing was committed; fix it and run finish-this-task again`, then exit 1. Any other exception between the first write and the commit takes the same path, using the existing helpers where they fit (finish_bookkeeping_undo.py).
