## Intent

Nearly every leaf adds a line to `CHANGELOG.md`'s [Unreleased] section and so names it as a touch zone. The overlap rule then puts every such leaf in its own batch: on 2026-11-05 three rc4 fixes waited behind two others for that reason alone (RE 15:46). `grind.shared_zones` exempts directories, but two leaves naming the same file under one still overlap. Add a file-level kind, append-only, that overlaps nothing, and let finish merge two sides' added lines in it.

**Out of scope:** sections or ordering inside the file (lines are kept, integration side first); generating changelog entries; any other merge strategy.

## Approach

- One rule in `shared_zones.py`, used by every overlap reader (grind plan, validate's registry overlap warning, the M18.20 scheduler), as `shared_zones` is today.
- One pure-additions classifier shared by the trial merge (review_gate_ready.py) and finish's resolver (finish_land_deterministic.py), so review status and `review run` (M18.24) do not refuse what finish can merge.
- The merge rule is git's union merge restricted to pure additions: refuse when either side changed or deleted a base line, so a real edit is never merged blindly.
- The toolkit's `sr/roadmap/git-workflow.yaml` and the project template list `CHANGELOG.md`, replacing the dispatcher's `NO_CONFLICT_ZONES` entry.
- Depends on M16.50 (`grind:` settings), M16.19 (grind plan's end state) and M16.9 (finish's folded modules).
