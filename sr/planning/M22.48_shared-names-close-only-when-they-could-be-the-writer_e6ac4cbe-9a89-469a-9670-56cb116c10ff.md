## Intent

M22.19 made any name that two roster entries share close the gate, so that an executor cannot approve its own leaf under another name. Model profiles list every effort variant as an alias, and one Cursor model can sit in both an executor row and a reviewer row, so every reviewer name this repo uses now matches several entries. Since 2026-11-07 17:00, no leaf with two real approvals can land (M22.47 shows "2/2 approvals, 0 block(s): not met"). An adopter with one model in two rows would hit the same thing after upgrading.

The protection M22.19 added is about writers. Keep it for writers, and stop it closing the gate when none of the entries a name could be wrote anything on the leaf.

## Approach

In `review_eligible.reviews_to_judge`, a record with an ambiguous name that does not intersect the writers is judged, not refused. Close the gate only when its candidate entries have different families. A READY author's ambiguity already excludes every candidate; drop its closing problem.
