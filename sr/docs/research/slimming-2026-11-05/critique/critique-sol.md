1. **High — M16.0–M16.2; all mutating leaves: make the baseline an actual gate.** The phase says all three gate everything, but M16.3–M16.5 lack M16.1, M16.23 lacks both harnesses, and docs start independently. No dependency pins the baseline after rc4 fixes. Add a common prerequisite for implementation/test-rewrite leaves: rc4 fixes integrated, both harnesses green, metrics captured at the same recorded commit. Independent docs/triage may remain outside it. Baseline the delivered rc4 behavior; retain the rc3 fixture as an additional migration case.

2. **High — M16.0, M16.1, M16.11–M16.19: parity does not cover the moved functionality.** Help goldens, one successful leaf loop and review verdicts cannot prove worker runtime, cleanup or config parity. Before each area's move, freeze a finite behavior table from its existing tests: worker delegate/sync/message/handoff/reclaim/terminate, leases/slots/outbox/crash recovery and harness hooks; cleanup dry-run/apply with live/merged/dirty worktrees; grind resume/limits/events; roster refusals; guard verdicts; record read/write round trips. Bind each table to its consuming leaf. Retain real subprocess/race tests where process behavior is the contract. Do not require an exhaustive new integration suite.

3. **High — M16.1, M16.14, M16.17, M16.21: policy-key coverage is weaker than decision coverage.** One exercised row per schema key misses stale versus current commits, executor/coordinator/fresh-session exclusions, missing or invalid signatures, reviewer count/family rules, disagreement, carried approvals and policy interactions. Specify rows for the gate's existing reason codes, defaults and named pairwise interactions; assert both refusal and approval where applicable through the public gate. Freeze serialized historical records too: constructing every fixture with today's writer can hide reader compatibility regressions. If stable reason codes are unavailable, explicitly allow a preceding public-result seam rather than inventing prose keys.

4. **High — M16.14: `verify_cmd` is not an execution-stage check.** Its current contract supplies a bounded test command to executor/reviewer prompts, with selected test paths appended. Mapping it to baseline/ready/land can run different commands or silently remove prompt guidance. Add a migration table for all three keys and the review switch: absent, blank, CLI override/disable, old-only, new-only and mixed forms. Preserve prompt-time selection separately; specify command arguments, cwd/env, failure evidence and precedence. Test upgrade apply, repeat apply and dry-run no-write behavior. For zone checks, name how leaf zones select checks and how stale results stop counting.

5. **High — M16.15: the proposed orphan rule misclassifies normal work.** A claim with no worker and no review is also an ordinary manual executor's fresh claim. `worker list`, doctor and future GUI must not treat it as abandoned or free its slot. Replace the rule with a fixed state table distinguishing manual claims, live sessions/worktrees, delegated workers, terminal workers and genuinely abandoned claims, reusing the delivered M15.26 rules. Assert existing CLI outputs and cleanup eligibility remain unchanged.

6. **High — M16.15–M16.19; 0.3.2 GUI: freeze the interface before consumers develop against it.** A schema integer and four broad collections do not define correlation or lifecycle semantics. Specify leaf keys, worker/session identifiers, worktree path/branch, status vocabulary, review freshness, manual/chore records, missing sources and unknown state; include leafless workers and multiple worktrees. Snapshot must remain read-only. Put a fixture-based consumer contract behind `worker list`, plan, doctor and the existing GUI worker routes; sequence 0.3.2 GUI work after that contract, with an explicit dependency in its plan. M16.9's GUI folds must finish before GUI implementation edits those files.

7. **High — M16.6, M16.7, M16.9, M16.10, M16.16–M16.19, M16.21: split by changed lines, not net savings.** A -200-line budget can conceal thousands of moved lines. M16.6 moves at least 29 library modules and breaks two large SCCs; M16.7 changes all parsers, dispatch and error handling; M16.16 moves 5.3k runtime lines; M16.9 and M16.10 each span several subsystems. Split these into named families of approximately ≤800 added/deleted/modified lines per executor plus two reviews, accounting for import/test updates; separate pure moves from rule consolidation. Give M16.17 eligibility and roster-schema work separate leaves, and M16.19 runtime, record adapters and config migration separate leaves. Each split needs its own bounded parity table.

8. **High — M16.23–M16.28: these are programmes disguised as leaves.** M16.23 migrates 98 importers and 53 helper groups; M16.24 reorganizes most of 353 files; M16.25 promises -12k lines; M16.26 combines seams, six property-test domains and timing; M16.27 spans milestones, graph editing, archive and update. Create support primitives first, then migrate/reorganize/dedupe per subsystem in bounded batches. Split milestone coverage from graph editing and maintenance commands. Convert subprocess tests per family after that family's in-process seam exists. Do not consolidate independent tests merely because their files have five tests.

9. **High — graph/touch zones: enforce the serialization the prose promises.** No cycles exist in the current 35-leaf graph, but M16.11 and M16.12 can both edit `cli.py`, docs, templates and prompts. 10. **High — M16.3, M16.12, M16.34: triage is consulted without being a prerequisite.** M16.3 may delete `behaviour_changes.py` before the maintainer decides M13.14, and M16.12 conditionally absorbs M13.11 features before that decision. 11. **High — M16.22: porting the dispatcher does not implement the stated complexity rule.** Its ruff scan reports only scores above the configured threshold, so growth from 3 to 8 is invisible. File/function moves can conversely look like newly complex functions and block a behavior-preserving move. Define comparison identity across renames/moves and whether the rule covers all score increases or only increases above the limit; implement the maintainer's literal rule or obtain an explicit amendment. Add bounded cases for below-limit growth, unchanged moved functions and newly introduced functions. In block mode, missing ruff must block with an actionable diagnostic; a reported skip cannot allow approval. Include sr config and dispatcher replacement in the touch zones.

13. **High — M16.20, M16.21, M16.33: evidence cannot justify automatic capability deletion.** Replaying historical reviews against current code/config is not necessarily replaying the original gate; reason-code mentions are observations, not counterfactual outcomes. 19. **Medium — M16.4, M16.5, M16.8, M16.18, M16.23: replace structural absolutes with bounded contracts.** “One now,” “≤5 index builds,” “no handwritten manifest,” and “every guard case becomes one table” prescribe syntax rather than behavior. 24. **Medium — M16 dependency graph: state the real critical path and stopping rule.** The current unweighted longest paths contain nine leaves; one is {M16.0 or M16.2} → M16.3 → M16.6 → M16.7 → M16.11 → M16.13 → M16.21 → M16.22 → M16.33. Another equal-length route runs through M16.5 → M16.15 → M16.16 → M16.17 before M16.21. Actual duration will be dominated by the oversized move/test leaves, human policy decisions and release wait, so count-based parallelism is misleading. Recompute after splitting/adding edges. Put the recommended two-same-class-block rescope rule and approximately four-round cap into the working rules, with reviewers restricted to the enumerated behavior matrix and changed boundaries; additional input classes go to intake.

Overall verdict: sound consolidation direction, but not executor-ready. Workers/orchestration remain core as required, and the snapshot boundary supports the planned GUI. First repair the baseline and migration contracts, split the multi-thousand-line leaves, serialize shared files and separate post-release removals. Keep the numerical targets provisional until their budgets and measurements reconcile; otherwise the plan recreates the open-ended review loop it is meant to stop.
